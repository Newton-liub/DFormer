# 01：MUSeg 开发划分协议与生成工具计划

> 任务类型：协议设计 + 确定性数据清单工具。
>
> 模型要求：**Sol 必须先冻结第 2–4 节的协议；Terra 只能按冻结协议实现；最终由 Sol 复核。**
>
> 本文件只写计划，当前未生成任何新 split。

## 1. 目标与非目标

### 目标

- 从官方 `train.txt` 的 1595 张图中按 location group 构建固定 train-dev/val-dev。
- 官方 `test.txt=1576` 原样封存，不参与开发期 checkpoint 或超参数选择。
- 生成可重建、可审计、能验证无泄漏的 manifest、统计和 SHA-256。

### 非目标

- 不改动官方 `train.txt`、`test.txt` 或任何 RGB/Depth/Depth16/Label 文件。
- 不按单图随机切分，不将同一 location group 拆开。
- 不在本阶段修改训练循环或运行 GPU。

## 2. 冻结的分组语义

1. 对每行路径取文件 stem，以 `-` 分割。
2. location group key 为前四段：`MM-RR-DD-GGGG`。
3. 同一 key 的所有图必须落在同一个 split。
4. 先验证官方 train/test 的 group key 交集为 0；非 0 时立即停止。
5. 生成的 train-dev 与 val-dev 只能来自官方 train；二者并集必须精确等于官方 train，交集必须为 0。
6. 官方 test 与 train-dev/val-dev 的样本和 group 交集都必须为 0。

## 3. 推荐划分目标

- 目标 validation 图片比例：官方 train 的 20%，允许因整组约束产生小偏差。
- 目标约为 train-dev 1276、val-dev 319；最终数量由完整组分配决定。
- 六个矿区必须在两边都有代表；不得整矿留出，除非另立跨矿泛化实验。
- 优化优先级：
  1. 所有位置组不可拆；
  2. 六矿图片比例接近官方 train；
  3. 15 类的“含该类图片数”和前景像素占比接近；
  4. 全背景图比例接近；
  5. 深度有效比例、RGB 亮度和单图类别数分布接近；
  6. 图片总数接近 80/20。
- 固定 split seed。seed 具体值由 Sol 在实现前写入协议常量和文档，不允许 Terra自行选择或多次尝试后挑最好结果。

## 4. 防止隐性挑选

- 划分算法、目标权重、seed 和 tie-break 必须在查看模型 validation 性能前固定。
- 只允许基于数据统计优化，不能训练多个划分并选择成绩最高者。
- 如果稀有类无法同时满足比例，只报告偏差并由 Sol 决定是否接受；Terra 不得手工移动样本。
- 划分一经用于开发训练即冻结。后续修正必须版本化并使旧实验失效。

## 5. Terra 实现任务

建议新增：

- `tools/splits/create_museg_dev_split.py`
- `tools/splits/audit_museg_splits.py`
- `tests/test_museg_dev_split.py`

工具要求：

1. 输入参数至少包含 dataset root、official train、official test、output root、seed 和目标 val ratio。
2. 读取 Label、Depth16、RGB 统计；统计过程确定性，文件遍历排序固定。
3. 先按 group 聚合，再进行分层组分配；禁止先分图再修组。
4. 输出到新目录，不覆盖已有结果；重复同参数运行应产生字节一致的清单与 manifest。
5. 输出列表沿用当前 loader 可接受的 `RGB/...jpg` 相对路径格式。
6. manifest 至少记录：schema、算法版本、seed、输入列表 SHA-256、输出列表 SHA-256、样本/组数量、六矿分布、15 类统计、全背景数、深度有效率和亮度分布摘要。
7. audit 工具只读检查，不修复；任何重复、缺失、交叉或无法解析文件名都以非零退出。

## 6. 必须覆盖的测试

- 正确解析示例 `06-01-01-0215-230920140531-06-99` 的 group key。
- 同组 1/2/多图绝不跨 split。
- 输入顺序打乱不改变输出。
- 相同 seed 字节级复现；不同 seed 能改变至少一组且仍满足约束。
- train-dev∪val-dev=official train，且无重复。
- train-dev、val-dev、test 样本和 group 两两零交集。
- 六矿在 train-dev/val-dev 中均有样本和位置组。
- 缺 Label/Depth16、重复行、错误命名、官方 train/test 组交叉时快速失败。
- manifest 记录的哈希与独立重算一致。

## 7. 执行与人工门禁

1. Terra 只实现工具和测试，不擅自生成最终冻结 split。
2. 静态测试通过后，由 Terra 在本地生成一个候选版本及审计报告。
3. Sol 审核算法、统计差异、稀有类覆盖和防泄漏证明。
4. 向用户报告候选精确数量、组数、六矿分布、15 类偏差、全背景分布和所有哈希。
5. 用户明确确认后，将该 manifest 标为 frozen；否则调整算法版本并重新生成，保留旧候选记录但不得用于训练。

## 8. 产物与 Git 边界

- 应提交：工具、测试、冻结后的轻量列表和 manifest；若项目决定列表不提交，则必须提交算法版本和期望 SHA-256。
- 不提交：数据图像、逐像素大统计缓存或临时候选目录。
- 推荐单独提交标题：`建立 MUSeg group-aware 开发划分`。
- 提交后要求工作区除用户既有计划外无本任务改动。

## 9. 完成标准

- 冻结 train-dev、val-dev、official-test 三份角色清晰的清单。
- 所有样本和 group 闭合、零交叉，统计和 SHA-256 可独立重算。
- Sol 和用户完成门禁 A 确认。
- 后续训练代码只能读取冻结路径，不再动态切分。

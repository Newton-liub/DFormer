# 项目操作指南

本目录保存可重复使用的项目操作说明，不承担实验当前状态、研究结论或历史证据职责。

- 项目架构、数据/模型/训练/评估链和接手导航放在 `doc/guides/project/README.md`。
- 全部 Git 跟踪文件的分类与逐路径说明放在 `doc/guides/project/file-catalog.md`。
- 云端平台、文件管理和数据取回指南放在 `doc/guides/cloud/`。
- MUSeg 当前状态与恢复点只看 `doc/main/MUSeg-current-status.md`。
- 日期化审计、实验和交接材料放在 `doc/reports/`。
- 阶段门禁与历史执行设计放在 `doc/plans/`。
- 外部服务、版本和界面可能变化；执行指南前必须核对文首的验证日期、适用版本和官方文档。

## 文档状态头规范

新增或实质更新 `doc/plans/`、`doc/reports/` 和 `doc/audits/` 下的项目自有文档时，标题后必须用简短引用块明确以下信息：

1. **文档角色**：条件式计划、历史执行记录、日期化报告、审计或稳定指南；只有 `doc/main/MUSeg-current-status.md` 可声明自己是实时状态入口。
2. **形成或核验时点**：至少写日期；运行中快照应写到可区分该次核验的时间。
3. **实时入口**：统一指向 `doc/main/MUSeg-current-status.md`；涉及研究选择时再指向 `doc/main/MUSeg-open-decisions.md`。
4. **后继关系**：已有更新报告或状态时，说明正文中的“当前”“正在”“下一步”只按形成时点解释，并给出后继文档。

推荐模板：

```markdown
> **文档角色：** 条件式计划 / 历史快照 / 日期化报告 / 审计。
> **形成或核验时点：** YYYY-MM-DD 或 YYYY-MM-DD HH:MM UTC。
> **实时入口：** `doc/main/MUSeg-current-status.md`。
> **后继关系：** 正文状态按形成时点理解；更新事实见 `<后继路径>`。
```

历史报告的指标、哈希和形成时点事实不为匹配新口径而改写；发现过时时，只补状态头、后继指针或明确勘误。计划中的“当前”和“下一步”必须带形成时点限定，且不得单独构成运行授权。

## 1. 给上级的结论

**建议接受“方案 A 优先、方案 B 备用”的投入顺序，但只先批准一个有明确边界的准备阶段。**A 用三组训练检验真实空洞形态是否比等量规则删除更有任务价值；B 先贡献统一单视图评价入口，暂不启动其完整三策略、跨方法研究。

## 2. 概念与证据等级

- **MMFR**：本项目关于多种模态失效与鲁棒性的研究。这里的模态主要指 RGB 图像和深度图。
- **C0**：E1 Batch 1A 的既有训练对照；本次讨论的初始化是其 fixed-final，即第 2560 次成功更新后的固定权重，不是其更早的 A2 初始化权重。
- **checkpoint**：模型参数及可能的优化器状态快照。身份记录、配置路径与实际可读的权重文件是三种不同证据。
- **support / validity**：分别指不含 padding 的图像区域，以及该区域内是否有深度观测。原始二值无观测位置与线性缩放后数值为零的位置不一定相同。
- **S1 / S2 / S10**：新计划拟议的 1 / 2 / 10 个推理视图。S1 统一 padding 后是新口径，不是旧 Quick-Val。
- **HAM / NMF**：现有解码头及其非负矩阵分解计算；其评价前向仍有随机初始化，`eval()` 不等于确定性。
- **BN / AMP / FP32 / TF32**：批归一化及其状态 / 自动混合精度 / 32位浮点 / GPU矩阵计算的一种精度格式。它们影响训练或数值行为，不能从旧合同无声继承；TF32-off指关闭该格式。
- **A2 / E1 / A-v1**：项目既有训练、候选筛选及动作效用残差实验的阶段/身份名称，均区别于本次自然空洞增强“方案A”。
- **mIoU / pp**：平均交并比 / 百分点。投入门槛不等于统计显著性，也不等于论文发表标准。

本报告把事实分为：本轮直接源码/文档/Git 核验；既有统计产物与历史正式报告；上级方案提出但尚未执行的安排；本地建议但仍待批准的取舍。历史数值沿用原报告，不声称本轮重算分数、重 hash 权重或重做统计。

## 4. 两份新计划的审计意见

### 4.1 方案 A：值得先验证，但首轮只承担有限主张

赞同它的四项收缩：不加推理模块；用等预算自然输入续训对照；用有效删除量匹配的网格对照；不根据亮度弱相关发明场景匹配机制。自然洞本来就存在，A 的主张应是“新增形态覆盖是否有价值”，而非“首次让模型见到真实缺失”。

建议保留首轮三组 `A-Natural / A-Grid / A-Replay` 和未续训 C0 锚点，保持每组 2560 次成功更新、fixed-final、不用 val 选 epoch。三组总计 **7680 次正式成功更新**；这是预算草案，不是获批合同或耗时保证。

建议优先审计并一次性冻结以下细节：

1. **辅助头与损失。**新三组是否仅使用语义分割损失、是否关闭继承的可靠性辅助头；详见 §5.1。推荐首轮只保留分割目标，不为了复用旧 helper 而引入另一训练机制。
2. **学习率的实际数值。**C0 的 E1 起始 base LR 是 `1e-5`；更早 A2 是 `6e-5`。若“历史 C0 起始学习率的 0.1”按 E1 理解，则为 `1e-6`，不是 `6e-6`。建议上级明确接受哪个实际值，并同时冻结 warmup、scheduler、BN、AMP 与 NMF 训练精度；本地不擅自升 LR 或恢复终点 optimizer。
3. **公平匹配如何离线执行。**A-Grid 应由同一 sample / update / slot 的确定性配对计划获得目标删除量，而不依赖 A-Replay 训练先跑完或读取其模型输出。形态候选、有限尝试和共同跳过决策可以作为纯输入函数重算，不需要跨 run 共享可变状态或建大型掩码数据库。
4. **空间变换与掩码失败语义。**padding 单独排除；目标有效点以正式插入点定义；源组排除目标组；候选不满足 10%–50% 新增有效删除、匹配误差或尝试上限时，两增强组共同跳过同一槽位。匹配失败率是可执行性证据，不能事后靠复杂优化器补救。
5. **评价子集与压力条件。**高缺失主集只有 64 图，必须记录采集组和类别支持，不能将它当 64 个独立场景或自动当显著性证据。矩形压力条件的目标删除率可能因原有效支持而不可达，需预先冻结有限尝试、不可达处置与实际删除量记录，所有候选复用同一观测。
6. **初始化主张。**C0 已经过历史人工故障训练，从它微调只支持“在已有鲁棒训练底座上新增覆盖”的结论，不是从零训练或首次与人工增强对比。首轮不因此增加从零训练；最终论文若扩大主张，再补相应强对照。

方案 A 的高缺失 +1.0 pp、全体/低缺失 −0.3 pp、矩形 +0.5 pp、entire-missing −0.5 pp 等线，均为上级提出的投入门槛。建议运行前接受或一次性修订，结果后保持不变。工程错误记 BLOCKED；有效实验不过线记 STOP；微小正差不触发加模块或延长预算。

### 4.2 方案 B：保留，但只先借用其必要公共部分

赞同它不把旧反转归因于多尺度，也不把统一损坏输入包装为新思想。完整 B 的独立论文准入仍需要外部方法对、第二数据集和预算内选择的证据。

推荐当前只做 A 需要的 **S1**：原尺度、统一右下 pad 至 32 倍数、batch 1、FP32 / TF32-off、裁 pad 后回原标签网格、数据集 confusion 累计。提前明确公共 view 的随机身份，但不为了“未来可能做 B”立即实现全部策略、延迟平台或通用插件。

B1a 的拟议规模为 `2 checkpoints × 318 images × 4 conditions × (1+2+10 views)`，共 **33,072 次模型—样本 view 前向**；不是零成本诊断。没有实际就绪权重和同环境少量测时，不能承诺笔记本耗时或云费用。A 首轮的 `4 checkpoints × 318 images × 3 conditions × 1 view` 是 **3816 次 view 前向**，也需单独授权；不能与 A-v1 历史 3816 个 confusion 单元混为一回事。

公共入口支持 A 不等于 B 已立项。若日后 B1a 获批，S2 / S10 是对同一入口的明确扩展；B1a 不支持预定义翻转即停止独立研究，不继续扫尺度和随机策略寻找案例。

## 5. 已直接核验的工程接入风险

### 5.1 旧 C0 继承的辅助可靠性训练不是新三组的空白底座

C0 文件调用 Common；Common 实际从 `DFormerv2_S_MMFR_A2_DepthCorrupt_v3` 导入共享 `C`，后者启用可靠性头和混合故障。这里存在共享配置对象的就地修改，不宜同进程批量导入旧候选后假定互相独立。

```8:12:local_configs/MUSeg/DFormerv2_S_MMFR_E1_Batch1A_Common.py
from .DFormerv2_S_MMFR_A2_DepthCorrupt_v3 import C
```

`models/builder.py::EncoderDecoder.forward` 在可靠性头存在且传 label 时，要求完整可靠性监督 batch，之后把辅助 loss 加入训练目标。它不是仅在配置里留下了无害注释。

```536:542:models/builder.py

            if missing_reliability:
```

**推荐取舍：**新三组建立独立配置对象，只保留原骨干/解码器和分割损失，关闭旧辅助可靠性训练、F-lite、R-OE、A-v1。C0 源文件不改写；如果新实例不含可靠性头，加载时只允许明确的旧辅助头键不被使用，全部分割路径键必须完整匹配，禁止全局 `strict=False` 掩盖错误。未续训 C0 锚点也按同一分割路径和新 S1 评价，不能引用旧分数冒充。

这会改变完整 state-dict 的键集合，但不应改变原分割函数；其等价性尚未通过实际前向验证。若上级选择保留可靠性辅助训练，则应把相同 loss/target 合同写进全部三组，明确这不再是纯分割训练首轮，不能默默继承。

### 5.3 实际训练 helper 路径与空间元信息缺口

**本轮确认的实际调用是 `utils/dataloader/mmfr_training_v3.py::build_mmfr_training_batch_v3`。**`utils/train.py`直接导入它；同目录 `mmfr_training.py`提供sample ID、种子与uint8/normalized转换原语。两份新方案及旧调查写的 `utils/mmfr_training.py` 不是当前实际文件位置，应在下一执行单中纠正；本轮只在此记录指正，保持原稿与历史报告不改写。

直接复核 `TrainPre.__call__`：镜像、scale、crop/pad均已执行，但返回只有RGB/Label/Depth三数组，不返回镜像标志、scale、crop坐标或support。`RGBXDataset.__getitem__` 返回 `data / label / modal_x / fn / n`，其中`fn`为RGB路径，可进一步规范化恢复sample/group身份；`n`是数据集文件数，不是sample ID。当前没有传递Depth16原始mask或空间变换记录。

v3 helper确实已有几何support和有效深度处理，但support是从RGB与Depth的normalized零值共同推断，不是loader显式提供的变换mask；这两种证据不能混为“loader已经传了mask”。它反归一化为uint8，在support内构造`depth_valid_pre`，施加固定六种故障课程，并输出辅助target/validity/telemetry。因此可复用其转换与种子原语，不能把整个旧batch builder直接当作只做Replay的新函数。

raw 0 归一化约为 −1.7142857，而 normalized 0 是 padding 使用的数值，两者必须区分。源 mask 用最近邻传播，Depth 保留原数值插值，新增删除在合法 uint8 空间完成并同步 validity；不能在归一化张量上直接写 0。

新 A 需要目标 sample / group 身份、明确的非 padding support 和可重放的空间变换信息。应使用可选元信息返回或独立适配层，使旧 loader 调用默认行为不变；源掩码选择不能读取标签/val/test。完整 mask 流转和新匹配函数尚未实现或验收。

### 5.4 评价复用应按公共原语，不按旧实验结果门禁

本轮直接确认旧E1 Quick-Val导入checkpoint evaluator、10-condition evaluator和 `tools/evaluate_museg_checkpoint_fast.py`；R-OE/A-v1有各自特殊调用边界。现有runner已经部分复用，并不是完全互不相干的重复实现；剩余问题是实验专属循环/行为和若干私有函数依赖。无需先把这些旧runner全部重写。

新入口应复用 `build_msflip_views`、`build_rgb_view_cache`、`assemble_views`、`unit_seed_words`、`corrupt_depth` 与已核验的RNG/计分原语，单独表达 S1 的 padding、view 身份和输出变换。若公共能力仅通过旧脚本私有函数暴露，只抽出新入口确实需要的那小部分，不建立全模型插件体系。

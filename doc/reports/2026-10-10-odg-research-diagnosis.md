# ODG 首轮 30 epoch 科研诊断（供上级模型审核）

日期：2026-10-10；代码基线：`5c082ba`。ODG 指“局部观测分布几何先验”；Original 指作者单值深度差路径。以下区分**已核验事实**与**方法解释/建议**，没有新增分割评价结果。

## 一、结论与裁决

**停止当前 ODG 版本的直接续训；先用现有 checkpoint 做两次 25% 孔洞评价，再决定是否给予一次“最小修改后重新验证”的机会。** 当前证据不支持直接继续到 100/300 epoch，也不支持更换数据集来挽救分数。

核心发现是：**Original 与 ODG 的 29 个 `Geo.weight` 参数张量均未进入优化器，30 epoch 后与官方预训练逐元素完全相同。** ODG 更换了关系函数，却没有实现原计划要求的几何权重适配。因此当前结果准确说明“固定预训练几何权重的首版 ODG 在 SUN 开发集 clean 上更差”，不能视为充分验证了可适配 ODG；这一缺陷也不保证修正后有收益。

缺失鲁棒性问题仍值得研究；**局部分布替换几何 bias 是否值得继续，必须靠扰动条件的实际收益决定，而不是已有投入。** 若最小孔洞对照连鲁棒性改善信号都没有，默认淘汰当前 ODG，不自动安排修正重训。若有明确正向信号，才建议上级批准一次对两组共同修正的短实验。

## 二、原假设与当前实验到底验证了什么

[原始方案](../plans/2026-10-10-odg-no-gpu-instructions.md)的核心问题是：物体边缘、细结构及遮挡混合区域，把局部深度压成一个数可能丢失多峰结构。ODG 在输入观测上生成 16 区间软分布、按 stage 面积聚合，然后用归一化核相似度的 log 替代单值深度差。候选创新在于**空间局部分布直接构造 token-pair 几何 bias**，不是“首次使用深度分布”，也不是深度补全。

- **clean 已验证的内容：** 同训练条件下的正常输入代价与早期优化趋势。两组合同仅 `geometry_mode` 不同；dev 528 图、同 encoder 预训练、同 300 epoch 日程的 30 epoch 暂停点、同 4×4 累积及 AMP。mIoU 在 epoch 10/20/30 分别为 Original 26.01/36.82/39.39、ODG 24.92/34.83/36.97；差值 −1.09/−1.99/−2.42 个百分点。epoch 30 loss 为 0.3488/0.3625，mAcc 为 49.23/45.39。原始 CSV 与逐类 JSON 已直接核对。
- **尚未验证的内容：** 人工缺失鲁棒性、边界/混合区域优势、分布相对同支持域均值的独立贡献。没有孔洞评价、`mean` 训练对照或边界统计。少数类别提升不能替代这些证据：例如 fridge +13.91、person +10.26，但 tv −26.61、mirror −11.27、toilet −9.89。
- **解释边界：** 单 seed、三个早期验证点不足以证明最终收敛排序，更不足以数学上证伪分布假设；但持续扩大差距、loss 同向偏高，已经足以否决“先继续训练再说”。所谓 clean 是“未人工损坏”，并不意味着输入天然没有零值或无效观测。

## 三、为什么落后：按证据强弱排序

### 1. 已确认：几何关系改变，但用于校准它的权重没有更新

训练入口 `research/train_odg.py` 使用作者 `group_weight` 创建 AdamW。该函数按模块类型收集 Linear/Conv/Norm 的参数，下面的 Parameter 分支不能捕获模块上直接注册的参数，因为 `module.modules()` 返回模块而不是 Parameter：

```30:34:utils/init_func.py
    for m in module.modules():
        if isinstance(m, nn.Linear):
            group_decay.append(m.weight)
            if m.bias is not None:
                group_no_decay.append(m.bias)
```

```52:53:utils/init_func.py
        elif isinstance(m, nn.Parameter):
            group_decay.append(m)
```

**本次 CPU 定点取证：** 按实际模型和同一分组函数重建参数集合，714 个可训练参数张量中，优化器仅有 273+412=685 个；遗漏的 29 个恰好全部是 `backbone.layers.*.blocks.*.Geo.weight`，同时包含每 block 的空间与深度系数。两组 `last.pth` 保存的优化器组也均为 273/412、状态数均为 685；两组全部 29 个几何权重与预训练完全一致，最大差值为 0。`requires_grad=True`、有限梯度或总参数数相同，均不能证明参数被优化器更新。

stage0–3 的深度权重均值为 **3.8586/0.8059/1.4805/−0.0085**；stage0 最大 10.0534，stage2 有 2 个负值、stage3 有 3 个负值。最后 stage 的深度作用很弱，不应把 full attention 的“分布表达能力”当作主要有效机制。负权重会反转 bias 的奖惩方向，不能一概解释为距离惩罚。

**方法解释：** 两边共同遗漏参数不等于比较毫无价值，但继承的系数来自原有关系，候选替换关系后失去重新校准的自由。这是当前最明确、可最小修正的混杂因素；不能把所有差距确定归因于它。以往准备/状态材料中的“几何权重有更新、所有可训练层更新”应按本次实际 checkpoint 证据更正。

### 2. 已有抽样证据：ODG 改变了偏置量级，也可能削弱边界区分

归一化核使用 $s=p_i^\mathsf{T}Kp_j/\sqrt{(p_i^\mathsf{T}Kp_i)(p_j^\mathsf{T}Kp_j)}$；这不是原绝对差关系的简单无损推广：

```43:47:research/geometry.py
            similarity = pk[:, :, query:stop] @ p[:, None].transpose(-1, -2)
            similarity = similarity * inverse_norm[:, :, query:stop, None] * inverse_norm[:, :, None, :]
            log_similarity = similarity.clamp(EPS, 1.0).log()
            pair_valid = active[:, None, query:stop, None] & active[:, None, None, :]
            rows.append(torch.where(pair_valid, log_similarity, torch.zeros_like(log_similarity)))
```

**三图定点量级测量：** 使用已有 dev 样本 `train_31/33/35`，按实际验证归一化、531×730 padding 与 stage 网格，每图每 stage 固定 seed 抽 512 个关系对（前三 stage 限行/列，末级任意对；剔除自关系和空支持），比较实际 $|w_d\log s|$ 与 $|w_d\ell_h\Delta d|$，对全部 block/head/采样对取均值。ODG/Original 比值在 stage0–3 分别为 **0.687–0.769 / 0.640–0.717 / 0.580–0.691 / 0.575–0.632**。例如 `train_31` 的 stage0 均值从 0.2435 变为 0.1805、95 分位从 1.2785 变为 0.9576；stage3 的 ODG 均值仅 0.00116。这里是 bias 的 logit 单位，不是 mIoU。

这说明至少在这些样本上，替换导致深度偏置减弱，而空间系数没有共同适配。**尚未测 QK logits 或实际 attention 分配，不能据此声称深度项全局失效或已证明因果。** 三图也不代表完整数据分布。

**方法风险：** 相同混合分布的归一化相似度为 1，即使两处属于不同物体；空间直方图丢失单元内部布局。含前景/背景的多峰 token 又可能同时接近两个纯深度 token，使边界连接变宽。它可能改善混合观测，也可能引入跨物体连接，不能预设“更多分布信息必然更好”。Original 实际是双线性插值单值，ODG 是面积聚合；二者还混合了采样方式、支持域处理、分箱与核归一化差异，收益或损失不能全归于“保留分布”。

### 3. 输入表示与观测置信度不匹配

- **已确认表示：** loader 将 uint16 PNG 读为高 8 位灰度，使用 $d=(D_8/255-0.48)/0.28$；16 个等距中心对应约每 17 个灰度等级一个区间。单位、天然无效值约定仍未知，不能把这些分箱称作米制距离分布，也不能直接改成 uint16/255。
- **本次同三图取证：** 原 uint16 零值占比分别为 **35.02%/35.89%/60.88%**，与高 8 位灰度零占比相同；三图均没有“原生非零被高位读取变成零”的像素。当前支持域仍把这些零当有效观测。若其中零代表无效深度，ODG 会把大量缺失编码当作最低深度峰并面积聚合；但这只是待核实风险，不能凭零值直接定义天然 missing mask。现有输入公平兼容作者，不等于适合当前几何假设。
- **已确认置信度丢失：** `ObservationGeometry.distribution` 在 `mass>0` 时归一化为完整分布，不保留剩余观测数量的置信度；只有全空 token 才中性化深度项。少量残存观测与完整观测具有相同形式的 bias，局部缺失不一定获得保护。因此 ODG 的鲁棒性主要可能来自“排除删除值/全空中性化”，并不自动来自分布表达。
- **次要混杂：** ODG/mean 会把几何 bias 转成 attention logits dtype，Original 保留原数值路径（`Decomposed_GSA.forward`）。AMP 数值路径并非完全相同；目前没有证据把它列为主要原因，不为此扩展工程检查。

## 四、现有 checkpoint 的最低成本 25% 孔洞裁决

**下一步只需两次新推理，不训练。** 固定两组本地 `last.pth`（均 epoch30），复用已有 clean 分数；沿用同 dev 528 图、单尺度无 flip、同 AMP/padding、`hole_ratio=0.25`、`hole_seed=12345`、同图像顺序。现有 `research/evaluate_odg.py` 支持全部参数，无需新增代码。本次禁止 GPU，**此处仅提出后续获批评价方案，未执行，也不转成长 CPU 推理**。

孔洞生成器在图像支持域内生成一个连通矩形加可选末行，按像素计数精确取整；同时把共同深度输入填为 raw-zero 对应归一化值 $-0.48/0.28$，把支持 mask 置零，保持 RGB/GT/padding 不变。不是只改 ODG mask；也不是全深度模态掉线实验。25% 是图像支持面积，不保证删除了 25% 的非零深度，尤其上述零值较多，须限制结论。

令 $C_O=39.39,C_D=36.97$ 为 clean mIoU，$H_O,H_D$ 为孔洞 mIoU，至少比较：

1. **孔洞绝对性能：** $A=H_D-H_O$；这是受损输入上能否真正赢过基线的主指标。
2. **各自退化量：** $L_O=C_O-H_O,L_D=C_D-H_D$；退化改善 $B=L_O-L_D=A+2.42$。仅 $B>0$ 不等于孔洞分数更好；**只有 $B>2.42$ 才能补偿现有 clean 差距**。保留率 $H/C$ 可辅助报告，不能独立决定去留，因为较弱模型有较低起点。
3. 同口径逐类 IoU/退化、mAcc/mF1，以及实际删除比例和计数。现成入口已输出这些指标。若需机制定位，可另看孔洞内部与外部的局部退化；入口当前不输出区域指标，本轮不增加此实现，也不把它列为筛选前置。

**暂定筛选规则（科研决策阈值，不是显著性）：** 若 $A\ge1$ 个百分点，有值得修正重验的信号；若 $A\le0$ 且 $B\le0$，优先淘汰；若只改善退化但绝对性能仍低，记为 clean–robustness 取舍，只有缺失条件具有明确应用价值才考虑一次修正重验。临界正结果最多补一个预先固定孔洞 seed 的两次推理，避免挑孔洞；单 seed 阴性不证明所有故障均无效。

**归因限制：** ODG 使用准确的人工删除 mask，Original 没有利用该 mask 的几何中性化；虽然深度张量相同，正结果可能只是有效性处理，而不是分布优势。正结果后最关键的现成对照是训练 `mean`：同面积/同支持域/同核/同空域规则，仅丢弃分布。它不完全等于“Original 加 mask”，但能检验分布的增量贡献。把某个 checkpoint 在推理时强行切成 `mean` 只能做关系敏感性诊断，不能替代匹配训练消融。

## 五、DeLiVER：适合扩展故障验证，不适合现在替换 SUN

**官方事实：** DeLiVER 是合成驾驶场景多模态数据，具有五类天气（其中四类恶劣条件）及五类故障：motion blur、over/under-exposure、LiDAR jitter、event low-resolution。前三类针对相机质量，后两类针对 LiDAR/Event；**官方五类故障不是标量深度局部孔洞清单**。用 RGB+Depth 两模态时，后两类不能直接充当深度故障证据。我们的 25% 删除须独立标为人工深度孔洞，天气/官方故障与深度缺失分开评价。

官方 `depth` loader 实际读取 `hha/`，HHA 是水平视差、离地高度、法向角的三通道几何编码；DFormerv2 只取辅助输入第一通道构造几何关系。直接输入 HHA、任取通道或灰度化都不能当作同口径标量距离。已有交接记录确认本地原始 `depth/` 为单通道 uint8，但其生成公式/单位/无效值尚未闭环，当前接口也未适配完整路径与 25 类标签。已有本地 train/val/test 3983/2005/1897 的历史清点记录，本次未重复清点。

- **替换主数据集：** 优点是故障分组和正式 val/test 可用，适合驾驶场景模态互补研究；缺点是需要新 baseline、输入协议与 loader，且同时改变真实/合成、室内/室外、类别和距离分布，仍没有现成的深度孔洞主实验。更换后得分变好也不能解释 SUN 为什么失败。当前不值得承担这笔成本。
- **第二验证集：** 若 SUN 上出现可信的 clean/孔洞收益，DeLiVER 可检验跨场景、天气和相机故障下的适用边界；先固定标量深度协议、两边共同输入和官方 split，再独立注入相同孔洞。代价是另训两组，原 SUN checkpoint 不能直接用于 25 类结论。若研究仍聚焦真实室内 RGB-D，NYUv2 更贴近第二验证目标；若转向驾驶环境的复合传感器故障，DeLiVER 的优先级才更高。

本次仅定点核对[官方 README](https://github.com/InSAI-Lab/DELIVER)和[官方 loader](https://github.com/InSAI-Lab/DELIVER/blob/main/semseg/datasets/deliver.py)，未开展文献调查；深度编码未知项沿用[已有交接证据](../../临时/RESEARCH_HANDOFF.md)。

## 六、三个选择的最少实验与最终建议

- **继续当前 ODG：不推荐。** 最少先完成上述两次孔洞评价；即使孔洞胜出，也先解释冻结系数与 mask 收益，不能直接把当前 checkpoint 续到100来验证原合同。当前正常输入已损失2.42点，没有无条件继续的依据。
- **最小修改后重新验证：有条件推荐，且只给一次机会。** 若孔洞信号支持继续，上级批准后仅修正研究训练入口的参数分组，让29个已有几何权重真正进入优化器，两组共同修正；不新增模块、不改变权重符号/数据/增强/核。两组从同一官方预训练重启至30epoch，复用300epoch日程，各比较clean与25%孔洞。不能只修ODG，也不以直接续训来宣称公平的30epoch对照。只有clean差距显著收窄且孔洞有实际优势才申请延长；有正结果后补一组同预算`mean`，若mean达到相同收益，撤回“分布独立贡献”主张。
- **淘汰并调整方向：阴性时的默认选择。** 最少只需两次孔洞评价；若无退化改善且绝对性能更差，不再为当前版本追加训练。将问题重新聚焦为“无效/稀疏深度如何影响几何关系、有效性处理是否足够”，而不是继续叠加分布模块。新方向先有匹配的有效性处理对照和明确输入编码，不因DeLiVER名称含故障就立即迁移。

**供上级审批的建议顺序：两次旧checkpoint孔洞评价 → 按绝对性能与退化量裁决 → 有明确收益才批准一次共同修正重验；否则结束当前ODG。** 当前最大确定性问题是优化器遗漏，最主要方法风险是关系量级/边界连接改变与输入零值语义不清。修正是有根据的有限尝试，不是保留ODG的承诺。

# ODG 第二轮（R2）SUN RGB-D 30 epoch 结果（2026-10-10）

本报告记录用户批准的 R2 实验：用修复后的训练入口（周期验证 eval 模式、714 个可训练参数张量全部入优化器）从同一官方预训练权重重跑 `original` 与 `odg` 各 30 epoch，并在本地用对齐后的独立评价入口完成 clean 与 25% 人工孔洞评价。依据见[重训计划](../plans/2026-10-10-odg-retrain-30epoch-r2.md)，协议见[ODG 入口](../guides/odg.md)，实时状态见[项目状态](../state/current.md)，上一轮（R1）见[30epoch报告](2026-10-10-odg-sunrgbd-30epoch.md)与[评价对齐复测](2026-10-10-odg-bn-align-reevaluation.md)。

**结论摘要：** R2 两项修复均已生效并直接核对；两组都训练正常完成（各 8940 次 optimizer 尝试，无失败）。**本地对齐评价下 R2 未复现 R1 的 ODG 正向优势**：clean ODG −0.31、25% 孔洞 ODG −0.25、退化量差异仅 +0.06，均落在本地/云端同协议复现差（约 0.3 点）的量级内。同时两组绝对值相对 R1 大幅提升（original clean +4.02、孔洞 +4.92；ODG clean +2.26、孔洞 +1.71），说明 R1 的结论与 R2 的差异主要来自 R2 改变了训练语义，而不是评价口径。**本轮不据此判定 ODG 有效或无效；是否继续由上级裁决。**

## 1. 修复生效证据（与 R1 的差别）

- **优化器**：训练启动即打印并校验 `trainable_tensors=714, optimizer_tensors=714, unique=714, duplicates=0, missing=[], group_sizes=[302, 412]`；R1 只有 685 个张量入组（29 个 `GeoPriorGen.weight` 缺失）。
- **验证模式**：两组 `validation.csv` 与 `val_per_class/epoch-0X0.json` 均记录 `model_mode=eval`，并带 BatchNorm running 统计量指纹。两个 run 的 epoch-10 指纹中 `batches` 完全相同（2908980），说明验证过程没有增加任何 BN 计数；编码器部分计数相同也说明两组加载的是同一份官方预训练权重。
- **训练合同**：两组均为 `validation_mode=eval`、`optimizer_param_scope=all_trainable`，除 `geometry_mode` 外字段一致；train/eval 清单指纹相同（`feb16f0785bf` / `5312aeebab92`），批次 `4×4`（有效 16）、300 epoch 日程、lr $8\times10^{-5}$、seed 12345、同一预训练权重。
- 未改模型结构、未改作者代码、未新增模块；R1 的 checkpoint 与结果原样保留为历史探索结果。

## 6. 必须保留的归因边界

1. **R2 相对 R1 同时改变了两件事**：29 个几何权重（`GeoPriorGen.weight`）从"冻结在预训练值"变为参与训练；周期验证不再用 train 模式前向、因此不再用 dev 批次更新 BN running 统计量。当前数据**无法分离**这两者对 +4.0/+2.3 提升的贡献，也不能把提升归因于"eval 模式评价"（那只是记录与选择口径）。
2. **±0.3 点在本轮噪声量级内**：同一协议下本地与云端对同一 checkpoint 的复现差为 original +0.32、ODG −0.01；评价时作者 HAM 每个前向重新抽取随机基（`rand_init=True`），且两侧 torch/CUDA 版本不同（本地 2.7.0+cu128、云端 2.1.2+cu118）。因此 R2 的 −0.31/−0.25 不足以判定 ODG 更差，同样地 R1 的 +2.96 也没有在 R2 中复现。
3. 单 seed、单 dev 划分、单一孔洞 seed、30 epoch 暂停点；孔洞对照中"分布机制"与"显式删除 mask 的有效处理"仍未分离。

## 8. 下一步建议（供上级裁决）

1. **不自动续训 100 epoch**：R2 在 30 epoch 未显示 ODG 的正向信号，先解决归因问题更划算。
2. 若继续投入，优先级建议：**(a)** 设计最小对照分离"几何权重参与训练"与"验证不再污染 BN 统计量"两项贡献（例如以 R2 代码冻结 29 个几何权重重跑一组 30 epoch）；**(b)** 用 `mean`/无 mask 消融判断分布机制本身是否有作用；**(c)** 只有在 (a)(b) 显示明确机制收益后，才考虑 100 epoch 或正式 test。
3. 在任何后续实验前，建议先确认"评价噪声量级"能否通过固定 HAM 随机基或多次重复评价缩小，否则 ±0.5 点以内的差异都不可判读。

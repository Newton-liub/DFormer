# ODG epoch30：25% 深度孔洞对照结果

日期：2026-10-10；本地 RTX 5060 Laptop（8GB）。本轮使用现有 Original/ODG epoch30 `last.pth`，没有重新训练、修改模型/优化器或启动付费云GPU。科研诊断已审核通过，本报告记录获批的孔洞对照与必要的同入口 clean 基准。

## 1. 结果与建议

**现有独立评价入口下，ODG 的孔洞 mIoU 高于 Original 2.97 个百分点，有正向筛选信号；但发现评价入口未恢复训练时解码器的 BatchNorm 数值配置，暂不能将结果作为原训练模型的最终鲁棒性结论。建议保留候选待核验，暂停追加训练，交上级审核。**

同一本地入口、同配置的配对结果（mIoU 单位为%，下降幅度为百分点）：

- **Original：clean 41.31 → 25% 孔洞 39.77，下降 1.54。** mAcc 58.53→56.83，mF1 55.24→53.65。
- **ODG：clean 42.76 → 25% 孔洞 42.74，下降 0.02。** mAcc 57.58→57.70，mF1 56.76→56.81。
- ODG−Original：clean **+1.45**，孔洞 **+2.97**；ODG 的下降幅度少 **1.52**。本地 ODG 的 clean 起点反而更高，因此这里不只是“较低起点导致小降幅”；同时存在孔洞条件的绝对性能优势。但仅凭一次孔洞 seed 和这套评价数值配置，仍不能宣称方法成功。

历史训练内 clean 为 Original **39.39**、ODG **36.97**，本次本地 clean 分别高出1.92/5.79点，且排序反转。**历史 clean 与本地孔洞不能直接相减。** 初次两组孔洞分数均高于历史 clean，故仅补做了两组同入口本地 clean，以隔离评价口径差异；没有添加第二孔洞 seed、其他故障或消融。

## 2. 共同协议与执行事实

- 固定528张dev、37类；dev清单SHA1为`5312aeebab92a8b2af1836cce85f825a0732b0ef`，与两组训练合同一致。
- 入口`research.evaluate_odg`，配置`local_configs.research.ODG_SUNRGBD`；单尺度1.0、无flip、AMP开启、batch1、workers2、SUN padding开启，device=`cuda:0`。四次推理均为独立进程，随机种子12345；两组孔洞seed均12345。clean与孔洞仅改变`hole_ratio=0/0.25`。
- 人工连通孔洞同时填共同深度输入为$-0.48/0.28$、将对应支持mask置零；RGB、GT与padding保持。两组实际支持像素165,061,806、删除41,265,537，实际比例**25.000052%**（逐图取整所致）。孔洞结果的清单、seed、比例、填充值、像素计数与评价字段已直接核对一致。

## 4. 两项必须保留的归因边界

**分布与显式mask尚未分离。** 两组深度张量与人工孔洞相同，但ODG利用精确删除mask排除被删观测、全空token中性化深度bias，Original没有同样的支持域中性化。优势可能来自mask有效性处理、关系强度改变或分布本身，当前对照不能分离这些贡献。未运行`mean`、无mask或其他消融；不宣称分布机制已得到独立验证。25%指图像支持面积，不保证删除25%的非零/有效物理深度，也不代表整模态掉线。

**发现独立入口的BatchNorm配置与训练内评价不一致。** 原训练配置`bn_eps=0.001`，训练模型有criterion，会调用初始化函数设置解码器BatchNorm的eps；独立评价构建模型时`criterion=None`，跳过该函数，加载state_dict也不会恢复非张量属性eps：

```226:228:models/builder.py
        self.criterion = criterion
        if self.criterion:
            self.init_weights(cfg, pretrained=cfg.pretrained_model)
```

```11:13:utils/init_func.py
        elif isinstance(m, norm_layer):
            m.eps = bn_eps
            m.momentum = bn_momentum
```

为解释异常只做了一次CPU构建取证，无前向、无属性修改：现有独立入口解码器的`squeeze.bn`、`hamburger.ham_out.bn`、`align.bn`实际eps均为**0.00001**，不是训练时的0.001。这是已确认的模型数值配置差异，不能把clean大幅变化或排序反转简单归为硬件波动；但本轮没有通过修改eps的对照来证明它解释了全部差异。另有torch/CUDA版本和HAM随机基不同运行位置等差异，未扩大调查。

本轮严格保留了原评价入口，没有修正eps、模型代码或优化器。四组本地结果内部采用相同入口，但相对于原训练模型有上述偏离，**仅作为条件性筛选证据**。此前29个几何权重遗漏于优化器的事实不变。

## 5. 去留建议与恢复点

**暂保留ODG为待核验候选，不淘汰，也不据此启动训练。** 理由是当前入口下同时出现孔洞绝对优势与退化改善，已不是仅依赖“小降幅”的弱信号；阻塞是评价数值配置不一致，而非缺少训练。

上级若批准下一步，优先范围应限于**让评价恢复训练时保存的BatchNorm配置，并重做相同clean/25%孔洞配对**；这一步涉及评价模型数值属性恢复，当前“不修改模型”授权下未执行。无需先修优化器、重训或适配新数据集。若对齐后仍有明确优势，再决定是否值得进一步验证分布贡献；若优势消失，撤回本次正向判断。不把新的评价口径反转当作已推翻原30epoch结果。

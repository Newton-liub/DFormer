# MUSeg + DFormerv2 快速 Baseline：总方向规划

> **文档角色：当前计划总方向与阶段边界。**
> **形成时点：2026-08-29。**
> **实时入口：** `doc/main/MUSeg-current-status.md`；研究选择见 `doc/main/MUSeg-open-decisions.md`。
> **计划状态：** 方向规划已建立；具体训练、评估、云资源和 official-test 运行尚未授权。
> **前置关系：** 继承 `doc/plans/archive/2026-08-MUSeg阶段二长程Baseline与MVE/` 中可复用的代码、数据、证据和审计结论，但不继承其中尚未冻结的旧执行口径。

## 1. 目标

本计划的目标是快速建立一个可靠的 **DFormerv2-S on MUSeg baseline**：

1. 使用 DFormerv2 模型和官方预训练资产在 MUSeg 上完成可复现训练；
2. 尽量采用 DFormerv2 官方论文公开的训练与测试口径，而不是把当前 seed 1 的简化验证配置当作正式基线；
3. 让最终预测结果与 MUSeg 原始 Label 网格对齐，明确区分模型输入尺寸、预测输出尺寸和指标计分网格；
4. 形成一个输入契约、训练协议、评估器和证据身份完整的基础模型，供后续模块配对比较；
5. 保持 official test 封存，先在冻结的 development split 上快速完成基线和模块方向判断。

本计划复现的是“DFormerv2 官方论文口径在 MUSeg 上的公开适配”，不是声称复现 MUSeg 作者未公开的内部测试代码。MUSeg 论文只公开给出了部分输入尺寸信息，未给出完整 DFormerv2 适配命令，因此所有已知事实、适配假设和未确认项必须分开记录。

## 2. 总体原则

- **模型不混淆：** 使用 DFormerv2-S，不把 DFormer v1 模型结构或 v1 checkpoint 当作本计划模型。
- **数据不混淆：** 训练和 development 验证使用冻结的 `train-dev`/`val-dev`；official test 在正式协议冻结前保持 `sealed_unread`。
- **训练测试分开：** 训练裁剪尺寸不等于测试时必须固定 resize 的尺寸。
- **官方口径优先：** 训练优先采用 DFormerv2 的随机尺度增强和 480×640 crop；测试优先实现论文公开的五尺度水平翻转推理。滑动窗口作为独立备选，不与主基线静默混用。
- **原始标签计分：** 每个尺度的预测恢复到 MUSeg 原始 Label 网格后计分；保存的可视化尺寸与正式 metric geometry 必须分别记录。
- **协议显式化：** 颜色顺序、归一化、Depth policy、缩放/插值、padding、翻转、滑窗、checkpoint 选择、seed 和 evaluator 版本都写入协议和结果身份。
- **不跨协议拼接：** 当前 seed 1 只保留历史 development reference；不能把其单尺度结果与新多尺度协议混入同一个 baseline 统计。

## 3. 阶段路线

### 阶段 A：目标与来源冻结

明确 DFormerv2 源码 commit、官方预训练权重、MUSeg 数据转换版本、development split、标签映射、Depth policy、颜色/归一化契约和目标 evaluator。此阶段只做协议和证据准备，不读取 official test。

### 阶段 B：DFormerv2 论文口径评估器

在当前可审计的 MUSeg evaluator 上增加明确的 DFormerv2-style multi-scale flip 模式：多个公开尺度分别推理，RGB/Depth 同步变换，必要时按模型下采样约束补齐输入，翻转预测恢复方向，所有预测恢复到原始 Label 网格后融合和计分。单尺度、固定 resize、滑动窗口保留为有明确名称的对照模式。

### 阶段 C：快速 B0 基线

完成最小静态/CPU 前置检查和短运行确认后，使用冻结 development split 训练 DFormerv2-S 基础模型。训练增强、预算、seed、checkpoint 规则和资源上限在本阶段详细计划中另行冻结。该阶段只产出 development baseline，不解封 official test。

### 阶段 D：基线收口与可比性报告

核验 checkpoint、协议、split、预训练权重和预测输出身份；报告整体 mIoU、per-class 指标、输入/输出尺寸、计分网格、推理模式、显存和运行限制，并明确哪些结果是公开 DFormerv2 口径、哪些是 MUSeg 适配选择。

### 阶段 E：后续模块对照

在 B0 协议冻结后，对候选模块实施同 seed、同数据顺序、同训练预算、同 evaluator 的 paired comparison。只有在 B0 和模块的协议身份完整一致时，才解释为模块带来的差异。最终正式矩阵和三 seed 统计另立后续计划。

## 4. A1/B1 的纳入结论

### A1：已证明风险，但不是可直接放入模型的模块

A1 已证明 MUSeg 全背景样本或有效监督像素为空时，普通 masked loss 可能出现空集合归约风险。A1 是问题证据和验收条件，不是网络模块，也不产生需要单独开关的模型结构。

### B1：可以直接纳入新 baseline，但只能作为必要稳定性修复

B1 的 `safe_masked_mean` 已通过张量级检查和真实模型 CUDA 场景回归，能够在无有效前景像素时保持有限 loss、有限梯度并产生精确零连接。当前状态已确认它进入历史 seed 1 基础训练链。

因此新计划规定：

- 新 baseline 默认包含 B1；
- 不再安排“去掉 B1”的性能消融；
- B1 的作用表述为训练稳定性和数值正确性修复，不宣称它已经带来 mIoU 提升；
- B1 不等于解决 Depth=0 或 depth-validity 问题，后者仍属于独立的 A2/B2 研究问题。

证据入口：`doc/reports/2026-08-21-museg-mve-a1-b1-a2-git-alignment.md`、`doc/reports/2026-08-21-museg-mve-cleanup-and-disposition.md` 和 `doc/main/MUSeg-current-status.md`。

## 5. 暂不在本总规划中冻结的事项

以下内容只在后续详细计划中确定，当前不能根据本文件直接启动运行：

- 最终颜色谱系和 normalization identity；
- multi-scale 是否作为 development 默认验证，及其与资源上限的关系；
- 训练 epoch、batch、seed、学习率和 checkpoint 选择规则；
- evaluator 的具体命令、输出 schema 和逐项契约测试；
- B2 是否进入本轮模块筛选；
- formal 三 seed 和 official-test 解封条件；
- 云实例型号、最长运行时间、自动停止和证据同步流程。

## 6. 交付顺序

1. 本总方向规划获得确认；
2. 建立输入/训练/测试协议详细计划；
3. 建立或修正 DFormerv2-style multi-scale flip evaluator；
4. 完成 baseline preflight 和短运行；
5. 训练并收口 development B0；
6. 冻结 B0 后再规划模块筛选和正式三 seed。

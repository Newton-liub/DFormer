# 路径 B 到路径 A：校准迁移检查

> **实验状态：** 可选后续实验，未执行。
> **实验类型：** 单一冻结温度的 clean→Depth 退化迁移检查。
> **前置条件：** 路径 A 与路径 B 的共享身份门禁已通过；路径 B 的 clean 温度已在 `C` 上拟合并冻结；路径 A 的退化条件已在运行前注册。
> **上级计划：** [`../00-总方向规划.md`](../00-总方向规划.md)。
> **实时状态：** [`../../../../../main/MUSeg-current-status.md`](../../../../../main/MUSeg-current-status.md)。

## 1. 要回答的问题

在 clean calibration 集 `C` 上得到的同一个全局正温度 `T`，应用到路径 A 的一个预注册 Depth 退化条件后，是否仍能改善概率可靠性？

这个检查用于识别校准的迁移边界：它可以区分“clean/同域校准有效”和“校准能够迁移到退化输入”这两个不同结论。迁移失败不等于全局温度在 clean `E` 上失败，也不能通过退化数据重新拟合温度来修复。[PR004]。`RE136` 和 `RE226` 只能作为后验校准/风险门控的邻近背景，不能替代 calibration under distribution shift 或 corruption calibration 的直接来源。

## 2. 固定身份与前置条件

- 使用路径 A 和路径 B已经冻结的同一 checkpoint、输入契约、evaluator、标签、有效像素掩码和 logits manifest；固定模型为 CVPR 2025 的 `DFormerv2-S`。[RE006][PR001]
- `T` 只能来自路径 B 的 clean `C`；不得使用退化条件的标签或 `E` 重新调参。
- 退化条件必须来自路径 A运行前冻结的 mask、fill、seed、目标/实际覆盖率和 condition ID。
- clean 与退化样本必须一一对应，official test 继续保持 `sealed_unread`。[PR001][PR003][PR004]

## 3. 实验步骤

1. 锁定路径 B 在 clean `C` 上得到的 `T`、拟合目标、参数约束、protocol 身份和产物哈希。
2. 读取路径 A中一个预注册退化条件的同源 float32 logits；不得重新生成未登记的退化强度或 mask。
3. 在同一退化 `E` 上比较 `softmax(z)` 与 `softmax(z/T)`，复用同一标签和有效像素掩码。
4. 报告 NLL、ECE、Brier、HCE、风险—覆盖/AURC，以及 argmax、mIoU、逐类 IoU 和改变像素比例。
5. 按图像或 location group 做 paired 汇总，并与 clean `E` 的路径 B结果并列报告。
6. 检查 checkpoint、condition、mask、样本、logits、标签、有限性和 official-test allowlist；任一失败时标记 `protocol-blocked`。

## 4. 判读边界

- **迁移支持：** 冻结的 clean `T` 在预注册退化 `E` 上至少一个主概率指标达到预注册改善，同时保持 argmax 和分割预测不变。
- **同域有效、迁移失败：** clean `E` 改善成立，但退化 `E` 无稳定改善或明显恶化。结论只能写为校准存在退化迁移边界。
- **结果不确定：** 概率指标与风险排序方向冲突，或区间不足以支持明确判断。
- **协议阻塞：** 身份、paired 对齐、mask、logits 或 official-test 边界失败；不得解释科学指标。

## 5. 资源与限制

该检查只需读取已有 logits 并进行 CPU 离线计算，不需要训练或更新模型。若退化 logits 尚未导出，导出操作必须另行授权；本文件本身不授权 GPU、完整数据评价、云资源或 official test。

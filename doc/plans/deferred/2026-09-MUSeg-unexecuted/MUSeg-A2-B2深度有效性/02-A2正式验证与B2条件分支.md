> **文档角色：** 延期且未执行的 A2/B2 候选方案；它保留原拟议顺序、证据和停手边界，不是当前执行方案，也不自动授权 GPU、训练、云资源或 official test。
> **计划状态：** 2026-09-05 起移入未执行区；当前没有任务或恢复点。
> **形成或核验时点：** 2026-08-31。
> **上级方向：** [`00-总方向规划.md`](./00-总方向规划.md)。

> **原拟议首项任务：** 任务 1“A2 协议与本地准备”；该任务及完整 A2、B2 实现和任何 GPU/训练操作均未执行。
> **执行组织：** 共 3 个顺序任务，不继续拆碎；B2 短训、完整独立训练和 paired screening 另立后续计划。

## 1. 目标与交付

本方案只交付以下闭环：

1. 在当前 epoch 420 RGB Quick-B0 上冻结可审计的 A2 协议；
2. 获单独授权后，在完整 `val-dev` 上运行 A2 并输出 `A2-pass/stop/inconclusive`；
3. 仅在 `A2-pass + 用户明确批准` 后，冻结并实现 B2 depth-validity gating，完成金标准、兼容性、真实 forward/backward 和 `B2-zero-train` 裁决；
4. 将训练性 B2 验证移交给新的后续计划。

本阶段不改变 Quick-B0 身份，不移除 B1，不读取 official test，也不把冻结 checkpoint 上的人工 corruption 或零训练行为写成训练后鲁棒性结论。

## 2. 原拟议任务组织与重新启用起点

### 任务 1：A2 协议与本地准备（未执行）

- 冻结 A2 条件矩阵、mask 生成、manifest、自然分层和裁决规则；
- 在现有 checkpoint evaluator 上增加明确隔离的 A2 模式，禁止更新权重；
- 完成最小 CPU 定点检查和静态诊断；
- 产出可供用户确认的 protocol/config 草案，但不运行完整 `val-dev` A2。

**未来重新启用起点：** 从稳定基准建立独立分支后，先定点核对 evaluator、Depth 读取/量化和 B0 主评估身份，再重新提交第 4–6 节中标为“待确认”的协议项。未取得新确认前，不执行任务 2。

### 任务 2：正式 A2 与裁决（待单独授权）

- 先运行 `q=0` 等价和 protocol/preflight 完整性门禁；
- 再按冻结矩阵运行完整 318 条 `val-dev`；
- 输出条件级指标、样本级 paired delta、自然无效深度分层、manifest 和结构化裁决；
- 裁决只能是 `A2-pass`、`A2-stop` 或 `A2-inconclusive`。

`A2-stop` 结束本轮 B2；`A2-inconclusive` 保持阻塞。最多允许一次经用户批准、使用新 protocol identity 的针对性补充验证，不得看到结果后不断追加条件。

### 任务 3：条件式 B2 与零训练验证（仅 A2-pass + 用户批准）

- 冻结 validity 来源、各 stage 下采样、full/decomposed GSA shape 和 pair-valid 数学语义；
- 先写/冻结金标准，再依次实现数据 validity、端到端可选参数、full GSA、decomposed GSA 和 strict compatibility；
- 完成 all-valid 等价、all-invalid/mixed 金标准、legacy 回归、参数/state-dict、真实 forward/backward；
- 使用冻结 checkpoint、不更新权重运行 `B2-zero-train`，输出 pass/stop/inconclusive。

任务 3 不包含 B2-short 或完整独立训练。任何训练性验证必须另立计划，重新冻结 paired B0/B2 的初始化、seed、数据顺序、预算和 evaluator，并取得 GPU/云资源授权。

## 3. 固定身份与不可变边界

- 模型：DFormerv2-S RGB Quick-B0，HAM decoder，保留 B1 `safe_masked_mean`。
- checkpoint：epoch 420 `selector-epoch-420.pth`，SHA-256 `f246a3afc50334c81302b7bfebdadf7cf37d00326bf1c3aa54f6a151754e3a1c`。
- `val-dev`：318 条，SHA-256 `1d0719d8f64f016d48995c25ab66d4004d76b7155d9efeef7cbb7454c0dd0e83`。
- RGB：`rgb-imagenet-rgb-order-v1`；Depth：当前全局量化 8-bit、单通道复制 3 通道、mean `0.48`、std `0.28`。
- evaluator：所有正式指标恢复到原始 Label 网格；前向精度、尺度和融合方式必须绑定当前主评估身份或显式建立新的 A2 evaluator identity。
- official test：`sealed_unread`；A2 的 split allowlist 只允许 `val-dev`。

历史 16 张 official-test pilot、epoch-10 checkpoint 和旧 BGR development reference 只用于解释问题来源，不进入新 A2 的样本、统计或裁决。

## 4. A2 人工 corruption 协议

### 4.1 必须在运行前冻结的矩阵

- corruption 比例 `q`：`0、0.1、0.3、0.5`；
- mask 类型：至少 `block` 与 `random`；
- fill 类型：`zero` 与同图有效 Depth 中位数 `median`；
- mask seed：至少 2 个固定 seed，具体值待任务 1 提交确认；
- checkpoint：默认只使用第 3 节的唯一 B0 checkpoint；增加第二 checkpoint 必须预注册且重新评估成本；
- 样本：完整 318 条 `val-dev`；小样本只可做无指标技术检查，不能替代正式矩阵。

注入候选只能来自量化前原始 `Depth16 > 0` 的像素。对同一 sample、q、mask type 和 seed，zero/median 必须复用完全相同的 mask。`q` 的实际注入像素数、可注入像素数和实际比例都要记录，不能只记录目标比例。

### 4.2 确定性与结构化身份

每个 condition 必须绑定：

- schema 与 condition ID；
- Git commit、protocol SHA、tool/config identity；
- checkpoint/model、split 和输入契约 SHA；
- sample ID、q、mask type、fill type、mask seed；
- 原始有效像素数、实际注入数、mask SHA 或可复算身份；
- evaluator/metric geometry、precision 和 official-test 拒绝状态；
- 命令、环境、退出码和失败/恢复史。

随机性从冻结 mask seed 与稳定 sample identity 派生，不能依赖遍历顺序或 Python 进程随机 hash。

### 4.3 `q=0` 等价门禁

运行任何非零 corruption 前，必须证明：

- `q=0` 不改变输入 Depth、预测标签和样本顺序；
- 指标与同 checkpoint、同 evaluator 的冻结 B0 参考在预注册容差内等价；
- zero/median、block/random 和所有 mask seed 的 `q=0` 结果一致；
- official-test allowlist 拒绝和 checkpoint strict load 生效。

任一项失败都记为协议/实现失败并停止，不得继续生成 A2 研究结论。

## 5. 自然无效深度分层

每个样本按量化前 `Depth16 == 0` 的自然无效比例分层，同时报告：

- 每层样本数和自然无效比例分布；
- clean 指标与每个 corruption condition 的 paired delta；
- 人工 mask 的实际可注入区域和样本覆盖；
- 分层内方向一致性及置信区间或预注册的稳健摘要。

**待确认：** 分层 cut-off、最小层样本数和稀疏层合并规则必须在任务 1 中根据 `val-dev` 的只读分布摘要提出并由用户确认，不能从已归档计划静默继承，也不能看过性能结果后再切层。

自然分层没有足够样本或方向不稳定时，不单独阻止人工 A2 达到工程 `A2-pass`，但裁决必须写明“只支持人工 corruption 条件”，禁止扩展为真实缺失机制、现实鲁棒性或部署收益。

## 6. A2 聚合与裁决

### 6.1 必须预注册的统计单位

- 主聚合单位是样本级 paired delta，而不是只比较两个独立总体均值；
- 主要指标、foreground 类定义、无有效标签样本处置、同一 condition 多 seed 聚合顺序必须冻结；
- 同时报告总体 mIoU/mAcc/mF1、per-class、每样本方向一致比例和剂量趋势；
- zero 与 median 的比较必须使用同一 mask，避免把 mask 差异误判为 fill 效应。

### 6.2 待用户确认的候选门槛

以下仅是已归档设计提供的候选，不在本文件形成时点自动生效：

- `q=0.3` block-zero 相对 clean 的 foreground mIoU 下降至少 `2.0` 个百分点；
- 至少 `75%` 样本的 paired delta 为负；
- `q=0.1 → 0.3 → 0.5` 总体不升，相邻反弹不超过 `0.2` 个百分点；
- 所有预注册 mask seed 方向一致；
- `q=0.5` 平均下降不足 `0.5` 个百分点可作为 stop 候选；
- zero 相对 median 的额外退化阈值、自然分层辅助条件和统计不确定性规则仍待任务 1 提案。

任务 1 必须把最终阈值写入新 protocol identity 并获得用户确认。阈值确认前不得执行任务 2，也不得把历史门槛写成当前裁决事实。

### 6.3 合法输出

- `A2-pass`：完整性和 `q=0` 门禁通过，预注册主条件、方向一致和剂量趋势达到冻结阈值；自然证据强度单独标注。
- `A2-stop`：效应明确不足、剂量趋势失败、只在单个 seed/条件成立，或完整性/等价性失败且不能在同一协议内修复。
- `A2-inconclusive`：门槛附近、条件缺失、样本层不足或不同 mask/fill 证据冲突，不能等同于通过。

只有 `A2-pass` 写入实时状态且用户再次明确批准，任务 3 才解锁。

## 7. B2 数学、shape 与实现边界

B2 的目标语义为：

- 两个 depth patch 都有效时，保留原有 depth decay；
- 任一 patch 无效时，仅移除该 pair 的 depth decay，保留 positional decay；
- `validity=None` 和 all-valid 在冻结容差内等价 B0；
- 默认不增加可训练参数，不新增 state-dict key。

候选 pair 语义为 `pair_valid = valid_i & valid_j`。任务 3 开始前还必须冻结：

- validity 来自量化前 `Depth16 > 0`，padding 为 invalid；
- RGB、Depth、Label 与 validity 的 scale/crop/flip 同步；validity resize 使用 nearest；
- 每个 stage 的 validity 下采样和 patch 聚合规则；
- full GSA 与 decomposed GSA 的 batch/head/H/W 展开、transpose、pair mask 广播；
- dtype、device、AMP、数值容差和 invalid pair 的精确公式。

实现顺序固定为：失败金标准 → 数据 validity → 端到端可选参数 → full GSA → decomposed GSA → strict compatibility → 真实 forward/backward。

## 8. B2 金标准与零训练门禁

### 8.1 最小金标准

- full GSA：`2×2` 空间；
- decomposed GSA：非方形 `2×3`；
- batch `2`、多 head；
- all-valid、all-invalid 和 mixed validity；
- `validity=None`/all-valid 与 legacy B0 的 logits/中间量等价；
- strict load 当前 B0 checkpoint；
- 参数量和 state-dict key 不变；
- forward/backward、有限梯度、dtype/device/AMP 行为；
- 现有 NYU/SUNRGBD 与 B1 路径不被静默改变。

### 8.2 `B2-zero-train`

- 使用任务 2 的冻结 checkpoint、split、A2 corruption masks 和 evaluator；
- 不更新权重，不允许把 B2 checkpoint 另存为“训练后模型”；
- 同时比较 clean、主要人工 corruption 条件和自然分层；
- 裁决阈值必须在运行前单独冻结，不能直接从旧计划继承；
- 合法输出为 `B2-zero-train-pass/stop/inconclusive`。

zero-train 只判断机制是否按设计工作、是否在冻结权重上呈现足够的即时恢复且 clean 退化受控。它不能证明 B2 经训练后有效，也不授权短训或完整训练。

## 9. 失败、停手与证据规则

- checkpoint、split、commit、protocol、输入契约或 evaluator identity 不匹配：停止并保留现场；
- 非有限值、strict load 失败、mask 越界、随机性不可复算、official-test 意外访问：立即停止；
- A2 实现问题只重复受影响的最小检查，不扩大到完整测试套件；
- A2 修复改变数值语义时，受影响条件全部作废，不能只重跑不利一侧；
- B2 改动影响 legacy 语义或 state-dict 时，不进入 zero-train，先由用户决定是否接受新模型身份；
- 不自动增加 q、mask、fill、seed、checkpoint、训练预算或补充实验。

每项结构化结果必须记录完整身份、退出码、失败/恢复史、指标是否计算、official test 是否参与和证据 SHA-256。大型预测、mask、数据和 checkpoint 不进入 Git。

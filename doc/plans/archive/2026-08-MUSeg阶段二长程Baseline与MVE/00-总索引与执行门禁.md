## 1. 目标与边界

本阶段建立可审计的 DFormerv2-S MUSeg 研究链：先校准颜色与 validation 几何，再用 development evidence 验证 MVE（最小验证实验）问题、筛选模块，最后对冻结架构执行 B0/最终 variant 的 paired 三 seed，并在独立授权后一次性读取 official test。

固定边界：

- official test 不参与颜色、几何、epoch、checkpoint、模块、A2/B2 或 seed 选择；
- 单 seed、单 checkpoint、短训和 screening 只能形成 development 证据；
- 历史训练结果和原始证据不因新协议而改写；
- GPU、训练、后评估、云资源和 official-test workload 均需实时状态允许并由用户单独授权；
- 代码、协议、数据、预训练、seed、evaluator 或预算变化均产生新身份，不跨协议拼接统计。

### 活动主线

5. `05-协议校准与Development-B0收口.md`：修复预处理/后评估契约，关闭颜色 provenance 与 validation geometry 的不确定性，收口 `development-reference-B0`。

## 3. 统一实验身份

### B0 身份

- `development-reference-B0`：已完成的长程 development seed 1 及其协议内后评估；只作历史开发参考。
- `color-geometry-screening-B0`：颜色/几何校准中，从同一 pretrained、同一独立 calibration protocol 训练的 B0；不得复用 `52.84` 直接比较不同颜色谱系。
- `module-screening-B0`：每个 screening protocol 内与 variant 同 seed、同预算实际训练的 B0。
- `formal-B0`：Gate E 后，在最终代码基线上关闭最终模块、用完整 official train 和正式三 seed从同一 pretrained 训练的对照。

这些身份不能跨 protocol 复用 checkpoint，也不能混入同一 mean±std。

### B1 与 B2

- B1 是 `safe_masked_mean` 数值稳定性修复，已经进入基础训练链；它是必须保留的回归，不再安排“去掉 B1”的性能长训。
- B2 是尚未实现的 depth-validity gating；它必须依次通过 A2 证据、用户授权、数学/shape 金标准、legacy 等价、零训练与短训，再作为候选进入统一 screening。

## 4. 统一结果名与中间态

- A2：`A2-pass`、`A2-stop`、`A2-inconclusive`。
- B2 零训练：`B2-zero-train-pass`、`B2-zero-train-stop`、`B2-zero-train-inconclusive`。
- B2 短训：`B2-short-pass`、`B2-short-stop`、`B2-short-inconclusive`。
- B2 配对筛选：`B2-screening-pass`、`B2-screening-stop`、`B2-screening-inconclusive`。

每项判断必须记录聚合单位、方向一致定义、数值容差、缺失条件、失败 run 和证据强度。`inconclusive` 不等于通过；最多允许一次预注册补充实验，且必须使用新 protocol，不得不断追加条件。

## 5. 活动门禁

### Protocol Gate

进入条件：显式 `channel_order`/normalization 契约、原始像素计分 evaluator、CPU 契约测试和五项 val-dev 后评估证据闭合；颜色与 validation 几何由独立 calibration protocol 冻结。其职责是冻结后续 development 输入和 evaluator，不评价模块收益。

### MVE Evidence Gate

进入 B2 的必要条件：A2 按预注册判据得到 `A2-pass`，证据完整，并由用户明确批准继续。自然无效深度证据不足不单独否决工程开发，但限制结论只能覆盖人工 corruption。

### Gate E：架构与正式矩阵冻结

合法输出有两种：

1. `B0-only`：没有候选达到预注册标准；仍可进入正式 baseline；
2. `B0 + 最终模块/消融组合`：冻结每个 variant 的代码开关、训练预算、三 seed、checkpoint/evaluator、资源约束和停止条件。

Gate E 不要求强行保留模块，不把单 seed screening 写成正式改进。

### Gate F：official-test allowlist

只有全部 `formal-B0/variant × 3 seeds` 的 checkpoint、SHA-256、协议、退出码、失败/恢复史和 sealed-test 证据闭合后，用户才能批准一次性 official-test allowlist。Gate F 只控制 test 解封，不再修改架构或训练协议。

## 6. 通用证据与停止规则

- 每个结构化结果记录 schema、完整 commit、protocol、split/pretrained/checkpoint SHA、seed、variant、命令、退出码、输入契约和 metric geometry。
- 发现非有限值、OOM/Xid、数据/哈希/commit/seed 不一致、checkpoint strict load 失败、输出目录碰撞或 official-test 意外访问时立即停止并保留现场。
- 修复影响数值语义时，受影响的 paired 两臂全部作废；不能只重跑不利一侧。
- 大型预测、mask、数据、checkpoint、运行日志和凭据不进入 Git。
- 任何提交或推送前核对实时状态与工作区；未经用户确认不推送远端。

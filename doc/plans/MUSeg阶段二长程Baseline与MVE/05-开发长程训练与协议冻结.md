# 05：开发长程训练、曲线分析与正式协议冻结计划

> 任务类型：长程 development 实验与研究决策。
>
> 模型要求：Terra 只能按冻结命令运行和收集证据；**训练是否继续、是否收敛、选哪个协议必须由 Sol 分析并由用户确认。**
>
> 数据：只用 train-dev 训练、val-dev 验证；official test 全程封存。

## 1. 目标

- 观察 DFormerv2-S 在 MUSeg 上的长程学习、平台和过拟合趋势。
- 判断论文的 500-epoch预算对当前 DFormerv2-S/单卡配置是否合理。
- 冻结正式训练所需的 total epochs、LR schedule、验证/保存间隔、checkpoint 规则和 3 seeds。
- 形成成熟 development baseline，供后续 A2 使用。

## 2. 开发协议起始值

起始方案以论文协议为上限而非结论：

- 最大 500 epochs；
- 输入 640×480；
- 04 确认的 batch；
- optimizer、LR、warmup、增强先使用已冻结候选；
- 每 5 或 10 epochs 验证，固定周期保存；
- 至少三个预注册 seeds，单卡顺序运行；
- 主选择指标为 val 前景 mIoU，辅助 mAcc、mF1、per-class IoU、train loss、吞吐和显存。

Sol 在首次运行前写入 protocol ID、seed 列表和所有值；Terra 不补默认值。

## 3. 分步执行策略

### 3.1 Development seed 1

- 先完整运行 seed 1，允许按预定里程碑报告但不因短期波动调参。
- 建议里程碑：epoch 1、10、20、50、100、200、300、400、500。
- 每次报告 train loss、val mIoU/mAcc/mF1、best epoch、LR、AMP、吞吐、显存和异常。
- 只有预注册停止条件触发才提前停止；不能因为“看起来够了”临时终止。

### 3.2 Seed 1 曲线审查

Sol 检查：

- train loss 是否继续下降；
- val mIoU 是否持续上升、平台或持续下降；
- best 是否只是单点噪声；
- 稀有类和全背景样本是否异常；
- LR 与 warmup 是否符合设计；
- 是否出现过拟合、欠拟合或优化不稳定。

若发现代码/协议错误，seed 1 作废，修复后从头重跑；不能把修复前后拼成一个 run。

### 3.3 Development seeds 2/3

seed 1 无协议错误后，按完全相同配置顺序运行 seeds 2/3。禁止依据 seed 1 改配置后直接把三者汇总；若确需改配置，则新建 protocol version 并重跑全部 seeds。

## 4. checkpoint 选择原则

- 不从 official test 选择。
- 每 seed 使用同一规则得到 `best-val-miou.pth`；tie 规则预先固定。
- 不选择三 seed 中最好的一个作为代表；报告三者和 mean±std。
- A2 正式筛查优先在三个 development best checkpoint 上配对运行；低成本预审可用中位表现 seed，但不得替代正式三 seed。
- 曲线分析可以提出固定 epoch `E*`，但必须注意 poly LR 总长度：改变 total epochs 会改变整个 LR 轨迹。

## 5. 训练周期冻结决策

### 情况 A：500 epoch 前后仍稳定提升

- 500 可能仍不足；Sol 提出扩展上限的新协议，用户确认后全部 development seeds 从相同初始化重跑。

### 情况 B：500 附近平台且无明显退化

- 可冻结论文对齐的 500-epoch正式协议，正式阶段使用 epoch-500 checkpoint。

### 情况 C：明显早期平台或过拟合

- 不直接把 500-schedule 的某个早期 epoch 当作新短 schedule 的结果。
- Sol 选择：
  1. 保持 500 总 schedule，冻结固定早期 checkpoint `E*`；或
  2. 重新设计总 epochs=`E*` 的 LR schedule，并从头重跑 development 三 seeds。
- 只有新协议自身通过三 seed 验证后才能用于 official 训练。

### 情况 D：三 seeds 趋势冲突

- 不挑最好 seed；检查方差、数据顺序、checkpoint 和指标实现。
- 必要时增加预注册 seed 或延长观察，但由 Sol 单独提出，用户批准。

## 6. 预注册停止条件

- 非有限 loss/metric、持续 AMP scale 崩落；
- OOM、Xid、数据加载失败、SwanLab 中断；
- split/hash、commit、配置或 seed 与 protocol 不一致；
- 吞吐长期异常且排除正常验证开销；
- checkpoint 无法读取或 resume 状态不一致。

停止后保留现场，不自动重启；按 02 的受控恢复规则处理。

## 7. 冻结协议产物

Sol 生成一个 machine-readable + Markdown protocol record，至少包含：

- protocol ID/version；
- model、pretrained SHA、完整 commit；
- train-dev/val-dev 数量和 SHA；
- total epochs、LR/warmup/poly、batch/workers、AMP、增强；
- eval/save interval；
- seed 列表；
- checkpoint 选择、tie 和 early-stop 规则；
- 三 seed曲线摘要、best epoch 和 mean±std；
- official 阶段固定使用 final epoch 还是固定 `E*`；
- A2 使用哪些 development checkpoints；
- 所有已知限制。

## 8. 人工门禁 E

向用户报告：

- 三 seed 的完整对比；
- 是否收敛/过拟合及证据；
- 推荐正式总 epochs 和 checkpoint 规则；
- 与论文 500 epochs 的一致/偏离；
- 正式三 seed 预计时间和成本。

用户明确确认后协议冻结。之后任何改变都必须升级 protocol version，旧正式 run 不可混用。

## 9. 完成标准

- development 三 seed 按同一协议完成或有受控、可解释的失败结论。
- official test 没有在任何训练、验证或决策命令中读取。
- Sol 和用户冻结正式协议及 A2 checkpoint 集合。
- 允许进入 06；历史 20-epoch/epoch-10 结果仍只标记为 qualification/pilot。

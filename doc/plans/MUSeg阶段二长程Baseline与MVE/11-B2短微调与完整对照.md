# 11：B2 五轮短微调与完整 B0/B2 对照计划

> 任务类型：分级成本的 B2 训练验证。
>
> 模型要求：Terra 可运行冻结命令和收集证据；**Sol 必须控制每个门禁、paired 实验公平性和最终结论。**
>
> 进入条件：10 的零训练 G0 已通过并经用户批准。

## 1. 总原则

- B0 与 B2 的初始化、数据、seed、batch、optimizer、LR、增强、样本顺序、验证和 checkpoint 规则必须成对一致。
- 不允许 B2 从 B0 已训练模型继续，而 B0 不做等量微调。
- 不允许只比较 B0 一个 seed和 B2 最好 seed。
- 开发门禁只用 train-dev/val-dev；official test 在完整协议冻结前保持封存。

## 2. 五轮短微调设计

### 数据

- 从 train-dev 中按 location group 生成固定 20% 训练子集；算法、seed、列表和 SHA 预先冻结。
- val-dev 全量作为验证和 A2 corruption 评估集。
- 该短训子集与 val-dev 位置组零交叉。

### 两臂

- B0：gating=false。
- B2：gating=true。
- 两臂从同一个冻结 baseline checkpoint 或 09/10 规定的相同初始化开始；必须对称。
- 固定同 seed、同 5 epochs、同 LR schedule 和数据顺序。
- 至少使用预注册 paired seeds；若最小方案先单 seed，只能作为 gate，不作为结论。

### 结果

- val-dev 干净 mIoU/mAcc/mF1；
- 自然无效深度高/低组；
- A2 corruption sweep；
- q=0 干净条件；
- 训练稳定性、显存和吞吐。

## 3. 五轮门槛 G1

至少满足一项收益且满足安全约束：

- 自然高无效率组前景 mIoU 提升至少 1.0 个百分点；或
- `q=0.3 block zero` 提升至少 2.0 个百分点；

同时：

- val-dev 全量干净 mIoU 下降不超过 0.5 个百分点；
- paired seeds 方向不冲突；
- 无新增数值、checkpoint、显存或吞吐不可接受问题。

未通过时停止完整 B2，不修改门槛追结果。

## 4. 完整 development B0/B2 对照

G1 通过后，按 05 冻结的完整 development 协议：

- B0/B2 都从同一 pretrained 初始化独立训练；
- 3 个 paired seeds；
- 同 train-dev/val-dev、total epochs、LR、batch、增强和选择规则；
- 每个 pair 使用相同 seed；
- 报告每 seed 的 paired Δ、mean±std 和曲线；
- 只用 val-dev 选择 checkpoint 和判断是否值得 formal test。

### Development G2

Sol 在运行前冻结正式门槛，至少要求：

- 干净 val 不显著退化；
- 自然无效高组或 corruption 的收益跨 paired seeds 稳定；
- 效应不能只来自一个 seed/类别/人工 mask；
- 性能成本可接受。

不通过则 B2 停止，不解封 official test。

## 5. 正式 full-train B0/B2 对照

Development G2 通过且用户批准后：

1. 冻结 B2 formal protocol；
2. B0 和 B2 都用完整 official train=1595，从同一 pretrained 初始化训练；
3. 使用与 06 等价的 3 paired seeds 和总 schedule；
4. 训练期禁止 official test；
5. 每个 arm/seed 具备退出码、manifest、SwanLab、checkpoint SHA；
6. 所有六个 run 验收完成后，由用户批准一次性 test 解封；
7. 对预定 checkpoint 评估 official test，禁止根据 test 换 checkpoint。

若 06 的 B0 正式 run 与当前 B2 protocol 在 commit、数据、训练配置和 evaluator 上完全兼容，Sol 可论证复用；任何关键差异都必须重跑 B0。Terra无权自行判定可复用。

## 6. 最终统计和声明

报告：

- B0/B2 每个 paired seed 的 test 指标和 Δ；
- mean±std、per-class、自然无效率分层、corruption sweep；
- 参数量、训练/推理吞吐、显存；
- 恢复/失败历史和所有 SHA；
- B2 在干净、自然缺失、人工缺失中的不同效应。

声明边界：

- 只在人工 corruption 提升：只声明鲁棒性收益。
- 自然高无效率和 full test 也稳定提升：才能讨论 MUSeg 自然 Depth=0 改进。
- 3 seeds 不稳定或 full test 退化：不得写成模型改进成功。

## 7. 停止和回退

- 任一 gate 未过，停止后续高成本实验，保留 B0。
- 发现代码 bug，受影响 arm/seed 作废；修复独立提交后成对重跑。
- test 解封后不得继续调 B2；若产生新版本，视为新研究并重新建立 development 协议。
- 不删除失败 run，它们是审计证据。

## 8. Git 和产物

- 训练/预测/checkpoint/SwanLab 数据不进 Git。
- 可提交最终报告、机器可读摘要 schema 和 evidence index。
- 除非发现代码缺陷，本阶段不修改生产代码。
- 最终报告由 Sol 撰写或逐段复核，Terra 不独立做因果结论。

## 9. 完成标准

- 五轮 G1、完整 development G2 和 formal test 三层门禁均有明确通过/停止记录。
- 所有 B0/B2 对照是 paired、同协议、三 seed，test 未参与开发。
- 结论与证据强度匹配；未通过时明确保留 B0、终止 B2。
- 项目形成可复现的 baseline→A2→B2 完整证据链。

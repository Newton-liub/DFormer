# 09：B2 validity gating 几何规格与张量金标准计划

> 任务类型：模型机制设计，不是机械编码任务。
>
> 模型要求：**仅 Sol 执行并签署。不得把本文件独立交给 Terra 设计 B2。**
>
> 进入条件：08 已判定 A2-G，且用户明确批准继续 B2。

## 1. 目标

在不增加可学习参数、不伪造深度、不丢弃 RGB/Label 监督的前提下，定义 B2：

- 两个深度 patch 都有效时，geometry prior 保留原 depth decay；
- 任一 patch 无效时，移除该 pair 的 depth decay，仅保留原 positional decay；
- 全部有效时 B2 与 B0 数值等价；
- 不传 validity 时保持 legacy B0 行为。

本阶段只输出规格、伪代码、shape 表和金标准测试，不实现生产代码。

## 2. 必须先审计的实际链路

Sol 逐级追踪并记录：

- 原始 `Depth16`、转换后 8-bit `Depth` 和无效 0 的语义；
- `RGBXDataset`、训练/验证预处理、镜像、缩放、裁剪和 padding；
- dataloader batch 字典；
- `utils/train.py`、`utils/val_mm.py`、`utils/eval.py`、`utils/infer.py`；
- `models/builder.py::EncoderDecoder`；
- `models/encoders/DFormerv2.py` 的 backbone、stage、`BasicLayer`、`RGBD_Block`、`GeoPriorGen`；
- `GeoPriorGen` 的 decomposed GSA 与 full GSA depth/position decay shape。

不得根据名称猜 shape，所有 shape 以真实 forward 和最小张量验证为准。

## 3. validity 来源与增强规格

必须明确并冻结：

1. validity 来自量化前 `Depth16 > 0`，不能从归一化后的 depth 数值判断。
2. RGB、Depth、Label、validity 使用同一几何随机参数。
3. validity resize 只用 nearest；镜像/裁剪与其他模态严格同步；padding 区为 invalid。
4. 人工 A2 注入时使用 `valid = original_valid & ~injected_mask`。
5. 数据增强后每个 stage 如何得到 patch validity：nearest、all-valid、any-valid 或比例阈值必须由 Sol 给出机制理由和金标准。
6. depth 仍按 B0 的 bilinear 路径进入 geometry prior；validity 的对齐顺序与输出尺寸必须明确。

## 4. full GSA 规格

Sol 输出：

- stage 输入 validity shape；
- resize 后 `valid_i`、`valid_j` 和 `pair_valid` 的精确 shape/广播；
- `mask = weight_pos * pos_decay + weight_depth * depth_decay * pair_valid` 的等效伪代码；
- batch/head 维度是否共享；
- bool 到浮点的 dtype/device/AMP 规则；
- 全 valid、全 invalid、mixed 的手算小矩阵。

禁止把 positional decay 一并 mask；禁止改变原 `self.weight`、decay 参数或 state dict。

## 5. decomposed GSA 规格

这是高风险部分，Sol 必须分别定义：

- width attention 的每行/列 validity pair 构造；
- height attention 的 validity transpose/reshape；
- 与 `generate_1d_depth_decay` 输出的精确 shape 对齐；
- `mask_d_h`、`mask_d_w` 只被对应 pair mask，`mask_h`、`mask_w` positional 项保持；
- batch/head/空间维的广播和 transpose 顺序；
- 非方形 H×W、batch>1、多 head 的金标准。

Terra 不得用“让测试过”的任意 reshape 代替该规格。

## 6. backward compatibility

规格必须保证：

- `validity=None` 完全执行 B0；
- `validity=all_true` logits 在浮点容差内等于 B0；
- 参数量和 state-dict keys 不变；
- 旧 pretrained/baseline checkpoint 可严格加载；
- decoder、safe loss、Label ignore 不变；
- 不启用 B2 的 NYU/SUNRGBD 等配置行为不变。

## 7. 张量金标准测试设计

至少定义以下测试的输入、期望值和容差：

1. full GSA 2×2 depth + all valid：B2 decay=B0。
2. full GSA all invalid：depth decay 全被移除，position 保留。
3. full GSA mixed：只有 both-valid pair 保留 depth decay。
4. decomposed 非方形 2×3 的 width/height mixed validity 手算结果。
5. batch=2 的不同 validity 不串样本。
6. AMP/float32 dtype 与 device 正确，无隐式 CPU tensor。
7. 全 valid B0/B2 logits 等价。
8. 参数量/state-dict key 完全相同，旧 checkpoint strict load。
9. forward/backward finite，invalid 区不会切断无关 RGB/Label 梯度。
10. 几何增强后 validity 与 Depth16 已知图案对齐。

## 8. 规格产物

Sol 应生成并提交：

- B2 数学定义；
- 全链路接口表；
- 每个 stage/GSA 的 shape 表；
- 伪代码但不实现；
- 金标准测试向量和预期结果；
- 允许修改文件与禁止修改文件；
- 性能/显存预期和 fallback；
- 已知歧义及最终选择理由。

## 9. 人工门禁

向用户解释：

- B2 具体改变哪一项 geometry prior；
- 为什么 invalid pair 只保留 positional decay；
- full/decomposed 两条路径如何处理；
- validity 下采样语义；
- 对 B0 checkpoint 和参数量是否兼容。

用户确认、Sol 签署规格后，才允许 Terra 执行 10。

## 10. 完成标准

- 无未决 shape、广播、下采样或 legacy 语义。
- 每条核心数学行为都有手算金标准。
- 规格足够机械化，使 Terra 无需自行做模型研究判断。
- 未修改生产模型代码。

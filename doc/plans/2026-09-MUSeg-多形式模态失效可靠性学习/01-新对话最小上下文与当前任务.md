## 2. 计划内当前状态

- `DVG-B1-oracle-gsa-v1` 已以 `oracle-not-supported` 关闭，不能修改其 A/B/C 后继续追加实验。
- 新方向为 MMFR（Multi-Modal Failure Robustness，多模态失效鲁棒性），研究对象扩展为 RGB/Depth 的完全缺失、局部缺失、噪声、模糊、量化、错位和混合失效。
- MUSeg 适合受控合成失效的矿井域开发研究，但没有自然失效真值，不能单独支持真实故障率或现实部署可靠性结论。
- A1 已完成两个 standalone 模块：`utils/dataloader/multimodal_failure.py` 与 `models/modal_reliability.py`。主代理复跑静态编译、CPU 定点 probe 和静态诊断均通过；现有训练、模型、配置、checkpoint 与 evaluator 路径未改变。
- A2 设计已冻结于 [`03-MMFR-A2训练接入与公平对照协议.md`](03-MMFR-A2训练接入与公平对照协议.md)：corruption 在最终 crop 后、GPU 前由主训练进程执行；每个样本使用训练位置、global rank、sample slot 和 sample-id hash 构造独立 NumPy RNG；当前只采样 Depth 失效，使用单前向、$\lambda_{rel}=0.1$、$\lambda_{cons}=0$，reliability head 在 A2 仅承担辅助监督，不接入 geometry prior。
- A2 的限定代码接入、主代理 CPU qualification 与本地 GPU 单步 preflight 已完成。GPU preflight 使用真实 `train-dev`、官方 pretrained、Ham decoder、SyncBN 和 AMP，修复 reliability 分支 FP16 下溢与 probe selector finalize 两个运行阻塞后，最终尝试 6 个 batch、跳过 5 次初始 GradScaler update 并完成 1 次 AdamW update；全部 loss 有限，未保存 checkpoint。
- 正式训练职责已固定为云端单 GPU，本机仅承担推理、想法初步验证和小规模 preflight。默认选择 RTX 4090 24GB；RTX 5090 32GB 只在 4090 缺货、24GB 容量不足，或相同配置短 probe 证明其单位样本成本更低时使用。科学超参数不随换卡改变。
- 当前没有已授权执行任务。正式训练、完整 epoch、云端 batch size 10 容量/吞吐 probe、checkpoint save/load、DDP、完整评价、云资源与 official test 均需用户另行批准。

## 3. 固定边界

- `train-dev=1277`、`val-dev=318` 的当前职责不因代码脚手架改变。
- official test 保持 `sealed_unread`。
- 新模型后续必须从同一官方 pretrained 独立训练，不从 Quick-B0 最终 checkpoint 续训。
- DFormerv2 当前是 RGB-centric：Depth 主要进入 geometry prior。`MMFR-B1` 只能解决 Depth 可靠性适配，不能宣称覆盖 RGB 完全失效。
- 不修改 `doc/main/MUSeg-current-status.md`、`doc/main/MUSeg-open-decisions.md` 或 DVG-B1 结论的子代理权限；这些由主代理复核后更新。

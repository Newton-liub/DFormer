## 2. 计划内当前状态

- `DVG-B1-oracle-gsa-v1` 已以 `oracle-not-supported` 关闭，不能修改其 A/B/C 后继续追加实验。
- 新方向为 MMFR（Multi-Modal Failure Robustness，多模态失效鲁棒性），研究对象扩展为 RGB/Depth 的完全缺失、局部缺失、噪声、模糊、量化、错位和混合失效。
- MUSeg 适合受控合成失效的矿井域开发研究，但没有自然失效真值，不能单独支持真实故障率或现实部署可靠性结论。
- A1 已完成两个 standalone 模块：`utils/dataloader/multimodal_failure.py`（v1，`MMFR-A1-train-corruption-basis-v1`）与 `models/modal_reliability.py`。主代理复跑静态编译、CPU 定点 probe 和静态诊断均通过；现有训练、模型、配置、checkpoint 与 evaluator 路径未改变。A1 已修订为 `MMFR-A1-corruption-basis-v2`（模块 `utils/dataloader/multimodal_failure_v2.py`，supersede v1；A1 v1 模块保持冻结，A1 v2 模块不导入也不改写它），修订原因是 v1 的 severity 被编码两次、且 `blur`/`misalignment` 的 severity 是绝对像素量。
- A2 设计已冻结于 [`03-MMFR-A2训练接入与公平对照协议.md`](03-MMFR-A2训练接入与公平对照协议.md)：corruption 在最终 crop 后、GPU 前由主训练进程执行；每个样本使用训练位置、global rank、sample slot 和 sample-id hash 构造独立 NumPy RNG；当前只采样 Depth 失效，使用单前向、$\lambda_{rel}=0.1$、$\lambda_{cons}=0$，reliability head 在 A2 仅承担辅助监督，不接入 geometry prior。v2 的 corruption 输入/表示层定性为 model-input/representation-level synthetic corruptions，不是 Kinect 真实物理噪声模型。
- A2 的限定代码接入、主代理 CPU qualification 与本地 GPU 单步 preflight 已完成。GPU preflight 使用真实 `train-dev`、官方 pretrained、Ham decoder、SyncBN 和 AMP，修复 reliability 分支 FP16 下溢与 probe selector finalize 两个运行阻塞后，最终尝试 6 个 batch、跳过 5 次初始 GradScaler update 并完成 1 次 AdamW update；全部 loss 有限，未保存 checkpoint。该 preflight 绑定 v1 协议身份，历史事实与哈希原样保留。
- A2 已修订为 `MMFR-A2-train-integration-v2`（supersede `MMFR-A2-train-integration-v1`，原因是“正式 500 epoch 尚未执行，所以在结果产生前进行协议修订”）；两个分析身份为 `MMFR-A2-clean-control-v2` 与 `MMFR-A2-depth-corruption-train-v2`，对应 run id 为 `museg-dformerv2-s-mmfr-a2-clean-control-v2` 与 `museg-dformerv2-s-mmfr-a2-depth-corruption-v2`。v2 代码身份为 `utils/dataloader/multimodal_failure_v2.py`（A1 v2）、`utils/dataloader/mmfr_training_v2.py`（A2 v2 batch helper）与 `local_configs/MUSeg/DFormerv2_S_MMFR_A2_Common_v2.py`、`DFormerv2_S_MMFR_A2_Clean_v2.py`、`DFormerv2_S_MMFR_A2_DepthCorrupt_v2.py`；`models/builder.py` 与 `utils/train.py` 增加 v1/v2 双协议守卫，v1 模块与 config 保持冻结。
- A2 v2 的科学语义修订：severity 只编码一次；`blur`/`misalignment` 改为相对尺度；Depth 监督目标为 $R_D^{sup}(p)=depth\_valid\_pre(p)\cdot R_D^{syn}(p)$；只监督 Depth 通道，RGB 为 all-ones scaffold；`natural_invalid_pixels`、`synthetic_missing_pixels`、`post_corruption_invalid_pixels`（另有 `implicit_quality_pixels`）分开记录。冻结项不变：`p_clean=0.25`/`p_corrupt=0.75`、三阶段 curriculum、`max_specs=2`、`lambda_rel=0.1`、500 epoch、optimizer、LR、batch size、clean-only selector、六单失效主 score、clean drop 门槛、paired location-group bootstrap 与云端单卡/4090/5090 规则。
- v2 阶段科学含义：A1 = “synthetic failure generation + corruption-derived reliability surrogate”；A2 = “Depth corruption robustness training + parallel reliability estimation”；A2 的 predicted reliability 不影响 segmentation backbone/decoder/geometry prior，因此 A2 的 segmentation gain 不能归因于 reliability head。B1 才是第一个真正的 reliability-aware segmentation 阶段。DFormerv2 统一描述为 RGB-primary semantic path + Depth geometry-prior path 的非对称架构。
- 正式训练职责已固定为云端单 GPU，本机仅承担推理、想法初步验证和小规模 preflight。默认选择 RTX 4090 24GB；RTX 5090 32GB 只在 4090 缺货、24GB 容量不足，或相同配置短 probe 证明其单位样本成本更低时使用。科学超参数不随换卡改变。
- 本次门禁执行已获用户授权并完成。`tools/mmfr/gradient_path_isolation.py` 已于 2026-09-15 01:32（本地时间）在本地 RTX 5060 Laptop GPU 上实际执行，退出码 `0`、墙钟 `15.3` 秒、结论 `gradient-path-isolation: PASS`（`failures` 与 `warnings` 均为空列表）；它检查 `lambda_rel=0` 与 `lambda_rel=0.1` 两次 backward 的共享参数梯度一致、reliability head 只在后者有有效梯度、head 开/关时 segmentation logits 一致，三项均实测成立。该门禁因此不再阻塞，“通过之前禁止启动正式 A2 v2 训练”的前置条件已经满足。除本次门禁外当前没有其他已授权执行任务；正式训练、完整 epoch、云端 batch size 10 容量/吞吐 probe、checkpoint save/load、DDP、完整评价、云资源与 official test 均需用户另行批准。证据、哈希与证据边界见第 6 节与 [`03-MMFR-A2训练接入与公平对照协议.md`](03-MMFR-A2训练接入与公平对照协议.md)。

## 3. 固定边界

- `train-dev=1277`、`val-dev=318` 的当前职责不因代码脚手架改变。
- official test 保持 `sealed_unread`。
- 新模型后续必须从同一官方 pretrained 独立训练，不从 Quick-B0 最终 checkpoint 续训。
- DFormerv2 当前是 **RGB-primary semantic path + Depth geometry-prior path 的非对称架构**：Depth 作为 geometry prior 进入 GSA，而不是与 RGB 对称的显式语义编码分支。`MMFR-B1` 只能解决 Depth 可靠性适配，不能宣称覆盖 RGB 完全失效。
- v2 冻结项不得在冻结身份内更改：`p_clean=0.25`/`p_corrupt=0.75`、三阶段 curriculum、`max_specs=2`、`lambda_rel=0.1`、500 epoch、optimizer、LR、batch size、clean-only selector、六单失效主 score、clean drop ≤ `0.50` 个百分点。不因新论文采用 50% missing 等设置而照抄；KSTrack 的 50% modal-incomplete 属 tracking 场景，不能推出 MUSeg 最优 corruption ratio；若未来发现 exposure 不合适只能新开 protocol。
- 不修改 `doc/main/MUSeg-current-status.md`、`doc/main/MUSeg-open-decisions.md` 或 DVG-B1 结论的子代理权限；这些由主代理复核后更新。

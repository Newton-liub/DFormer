## 1. 一句话目标

以冻结的 MUSeg DFormerv2-S RGB Quick-B0 为稳定起点，规划一个先验证“深度边界证据受损是否构成可复现问题”、再验证“最低复杂度的几何可信门控是否有增益”的快速最小可行实验（MVE）；当前不主张真实粉尘、真实传感器故障、三维绝对几何或部署安全收益。

大白话说，先用最便宜、变量最少的实验判断问题和最小方案是否值得继续，不直接实现完整低照度—粉尘—深度恢复系统。

## 3. 已核验的固定身份与不可变边界

- **模型起点：** DFormerv2-S RGB Quick-B0；当前最终 checkpoint 为 epoch 420 的 `selector-epoch-420.pth`，SHA-256 为 `f246a3afc50334c81302b7bfebdadf7cf37d00326bf1c3aa54f6a151754e3a1c`。
- **既有开发 split：** `val-dev` 共 318 条，SHA-256 为 `1d0719d8f64f016d48995c25ab66d4004d76b7155d9efeef7cbb7454c0dd0e83`；它已参与 checkpoint 选择，不能被静默改称独立评价集。
- **输入契约：** RGB 使用 `rgb-imagenet-rgb-order-v1`；后续计划必须另外核对 Depth 原始编码、无效值、量化链和可控退化注入位置。
- **主 evaluator：** `msflip-whole-original-grid-v1`；任何快速 MVE 若改用单尺度、缓存 logits 或局部边界指标，必须建立独立 evaluator/protocol identity，不能冒充 Quick-B0 主评估。
- **基线结论边界：** Quick-B0 是 single-seed development 基线，不提供训练随机方差。
- **official test：** 保持 `sealed_unread`（封存未读），不得参与抽样、校准、阈值选择、方向筛选或恢复流程。
- **授权边界：** 当前只授权计划文档创建。没有代码实现、数据读取、GPU、训练、完整评价、云资源或 official test 授权。

## 4. 关键概念与命名边界

- **MVE（Minimum Viable Experiment，最小可行实验）：** 用最低成本回答一个可证伪问题，不等于论文级完整实验。
- **DVC（Depth-validity Corruption Check，深度有效性破坏检查）：** 候选路径 A 的语义前缀，负责验证问题是否存在；后续完整名称拟使用 `DVC-A1-<数据职责>-v<protocol>`。
- **DVG（Depth-validity Gating，深度有效性门控）：** 候选路径 B 的语义前缀，负责验证最低复杂度干预是否有效；后续完整名称拟使用 `DVG-B1-<条件>-v<protocol>`。
- **A/B 图例：** `A = 问题或现象验证`，`B = 方案或干预验证`。阶段号只表示本实验族内部顺序，不使用裸 `A1` 或裸 `B1`。
- **B1 数值修复：** 项目已有 `safe_masked_mean` 修复。它与未来完整名称 `DVG-B1` 不是同一对象，任何文档都不得把后者简称为裸 `B1`。

上述名称尚未进入实验 protocol identity；数据职责与条件后缀必须在文献和项目事实闭合后才能冻结。

## 5. 后续计划结构（待资料闭合后编写）

1. **共享身份与协议门禁：** 核对数据职责、场景分组、Depth 编码、可比模型输出、evaluator、统计单位和 official-test 拒绝规则。
2. **`DVC-A1` 问题验证：** 只改变一种预注册的深度边界有效性变量，先做最小完整性/CPU 检查，再在获批范围内执行配对评价。
3. **`DVG-B1` 方案验证：** 仅在问题证据达到冻结门槛且用户再次批准后，先做 Oracle（已知坏区的理想门控）上限，再决定是否拟合低自由度门控。
4. **方向裁决：** 分别允许 `supported`、`not-supported`、`inconclusive` 和 `protocol-blocked`；任何一个结果都不自动解锁训练或完整联合恢复。

后续细节不在本轮提前写死。尤其是“60 对样本如何得到”“是否保留三维分支”“是否存在严格可比的 RGB-only 输出”“联合双边滤波是否作为唯一补全基线”都必须先过资料与项目事实门禁。

## 6. 证据与结论分层

- 纯文档和静态核对只能形成“计划准备证据”。
- 小样本完整性检查只能形成“工程检查”，不能形成模型效果结论。
- 人工深度退化只能支持受控 corruption 下的敏感性或相对改进。
- development MVE 不能改写为独立测试、自然退化、真实三维几何或部署结论。
- 任何正式结果必须绑定命令、环境、退出码、代码身份、checkpoint/split/protocol/evaluator identity、产物哈希、失败与恢复历史，并显式记录 `official_test_included=false`。

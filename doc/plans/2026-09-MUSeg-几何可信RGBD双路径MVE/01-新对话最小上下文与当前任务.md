## 3. 最少需要知道的固定身份

- 模型是 DFormerv2-S RGB Quick-B0，epoch 420 checkpoint SHA-256 为 `f246a3afc50334c81302b7bfebdadf7cf37d00326bf1c3aa54f6a151754e3a1c`。
- `val-dev` 有 318 条、196 个 location group，覆盖六个 mine，split SHA-256 为 `1d0719d8f64f016d48995c25ab66d4004d76b7155d9efeef7cbb7454c0dd0e83`；它已参与 checkpoint 选择，结果只能称为 development evidence。
- 原始 `Depth16` 是二维 `uint16`，`0` 为无效；现有模型输入使用固定映射 `round(Depth16 * 255 / 13932)` 形成 8-bit Depth。注入应发生在原始 Depth16 上，再统一走量化、归一化和 evaluator 链。
- 当前没有严格可比的 RGB-only checkpoint/logits；首轮不使用 RGB-only 回退。
- 主 evaluator 是 `msflip-whole-original-grid-v1`；新 MVE 必须另建 identity，但保持相同五尺度翻转和原始 Label 网格。
- official test 继续为 `sealed_unread`，本计划不得读取。

## 4. 当前任务卡

- **当前唯一交付物：** `DVG-B1-oracle-gsa-v1` 的基础方案设计已完成。后续参考文献补充、GSA 代码定位、新 protocol 细化和执行授权尚未完成。
- **后续最终目标：** 在参考文献和 GSA 代码定位完成后，冻结 B 的 protocol；通过 clean/q=0 等价、mask 传播和 1–2 样本 preflight 后，再由用户单独批准完整的 paired development evaluation。
- **输入：** v3 protocol、冻结 v1 派生 allowlist、构造性摘要、已通过的 v3 preflight、固定 checkpoint、原始 `Depth16`、RGB/Label 和冻结 evaluator。【文献依据：参考资料清单 P0-1、P0-5】
- **输出：** B 基础设计、后续需要补齐的 GSA/mask 细节、拟比较的 baseline/Oracle、指标和合法终点；后续完整评价才会生成 B 的 per-image/per-group 结果、产物哈希和裁决。
- **前置门禁：** B 必须复用 v3 已核验的标签契约、218 张图/138 个组范围和 `official_test_included=false`；必须证明只改变 GSA depth contribution，并在完整评价前另行明确批准。
- **停止条件：** 任一身份或哈希不符、condition 覆盖不完整、mask hash 漂移、对照面积不匹配、非有限值、输出网格错误或用户尚未批准完整评价时立即停止。

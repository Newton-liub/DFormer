## 2. 计划内当前状态

- `DVC-A1-valdev-boundary-zero-v1` 与 v2 保持各自 `protocol-blocked` 历史终态；不得覆盖或重解释。
- 独立 v3 已完成 218 张图、138 个 location group 的完整开发评价，主裁决为 `not-supported`；该结论不阻止单独验证 Oracle 门控方案，但 B 的结果不能回写成 A 的支持证据。
- 11 篇全文和常见官方代码核验已完成。它们能支撑连续 confidence、可靠性乘 affinity、Full attention 等机制边界，却没有唯一给出 DFormerv2 所需的四级 reliability 和 Full/H/W gate。
- 用户已选择 A：原始 `m=1` 表示受损、`r=1-m` 表示可信；先按 evaluator 用 `INTER_LINEAR` 从原图映射到五尺度 view，再 flip、右/下 padding `r=1`，最后对四个 stage 用 `INTER_AREA` 聚合为连续有效面积比例。
- 用户已选择 B：Full/H/W 均使用 query/key 两端 reliability 的连续对称乘积，只乘 `self.weight[1] * mask_d*`；spatial contribution、Q/K/V、rotary encoding、Depth 输入、decoder 和 logits 不变。
- `None`、clean、q=0、全可信 mask 必须进入原始 forward 旁路；逐 stage 输出和最终 pre-softmax logits 以 `torch.equal` 验收，不使用 `allclose` 放宽。
- C 已部分关闭：clean 容忍度严格为 0，指标只保留 Boundary IoU 主指标与 mIoU 辅助指标。仍需用户冻结 `oracle-supported` 最小 Boundary IoU 实际效应量、95% 区间联合规则和 mIoU 的裁决职责。
- 当前没有 `DVG-B1-oracle-gsa-v1` protocol，没有 DVG-B1 模型代码，也没有模型 forward、preflight、GPU 或科学结果。

## 3. 最少需要知道的固定身份

- **模型：** DFormerv2-S RGB Quick-B0，epoch 420 checkpoint SHA-256 为 `f246a3afc50334c81302b7bfebdadf7cf37d00326bf1c3aa54f6a151754e3a1c`。
- **数据：** B1 复用 v3 的 218 张图、138 个 location group；`val-dev` 已参与 checkpoint 选择，因此结果只能称为 paired development evidence，不能称为独立测试。
- **输入：** corruption 在原始二维 `uint16 Depth16` 上生成并置零，之后走现有量化、归一化和 evaluator；Oracle mask 必须与同一 condition 的 corruption mask 和哈希一致。
- **evaluator：** `msflip-whole-original-grid-v1`，五尺度 × 原图/水平翻转，共 10 view；只在右/下 padding，逆 flip 后恢复原始 Label 网格，FP32 平均 pre-softmax logits。
- **指标与统计：** Boundary IoU 主指标、mIoU 辅助指标；以 138 个 location group 为 bootstrap 单位，seed `20260908`，10,000 次 percentile bootstrap。
- **official test：** 继续 `sealed_unread`，所有 protocol/产物必须记录 `official_test_included=false`。

## 4. 新对话的唯一任务卡

### 4.1 P0 第一交付物：关闭 C 并物化 protocol

- **输入：** 本文件、`00`、`04`、开放决策第 12 节，以及用户明确给出的 C 数值。
- **需要用户冻结：** Boundary IoU 最小实际净增益、95% 区间规则、mIoU 是仅报告/否决项/联合门槛。
- **输出：** `04` 第 10.3 节、开放决策第 12 节和 `DVG-B1-oracle-gsa-v1` protocol 模板使用完全一致的规则，并注明“项目预注册选择，非文献标准”。
- **通过条件：** protocol 确定性物化，绑定 checkpoint、split、allowlist、v3 mask manifest、代码/evaluator identity、输出位置和 SHA-256。
- **停止条件：** 用户未给 C 数值或任一 identity 无法复核时，保持 `reference-blocked`/`protocol-blocked`，不修改模型代码。

### 4.2 后续顺序：不得跳级

1. **P1 CPU qualification：** 实现 A/B 最小算子和参数链，只检查五尺度、flip、padding、四级 shape、partial/empty/all-1、product 对称性与广播；不加载 checkpoint、不跑模型 forward。
2. **P2 no-op：** `None`、clean、q=0、全可信 mask 的逐 stage 输出和最终 logits 全部 `torch.equal`。
3. **P3 1–2 样本 preflight：** 覆盖 clean、非空 `boundary-q75`、`nonboundary-q50` 的 10 view，检查 gate 生效、spatial 不变、finite、hash 和原图网格。
4. **P4 完整评价：** 只有 P3 通过后，另行说明设备、时长和范围并取得用户明确授权；未授权不得运行 218 张图完整 GPU paired development evaluation。

任何阶段若必须改变 A/B/C 数值语义，建立新 protocol identity 并从 P0 重来；不得查看结果后换成 nearest、min、query-only、hard threshold、stage 子集或追加 condition。

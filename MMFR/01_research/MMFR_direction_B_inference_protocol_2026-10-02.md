# 方案 B：固定传感器观测与显式推理预算下的 RGB-D 鲁棒性审计

> 版本：v1.0｜日期：2026-10-02  
> 定位：备选、高风险的评测与实证研究；目前不建议与方案 A 同时大规模立项。  
> 状态：已形成可证伪研究方案；尚无统一入口的新结果，也没有已就绪的外部 MUSeg 对照权重。  
> 配套方案：`MMFR_direction_A_natural_missing_2026-10-02.md`。  
> 核心原则：先证明这是跨方法、影响实际选择的问题，再决定是否值得写成论文；只有 F-lite 的一次翻转，不够支撑独立论文。

## 0. 一页决策摘要

**本方案的起点是真实存在的历史现象，但历史证据比“多尺度导致翻转”复杂得多。**F-lite 在 Quick-Val 与 Main-Val 之间同时改变了视图、padding、随机数消耗、view batching 和执行环境。因此，下一步不能直接跑一遍多尺度，再把所有差异解释为 TTA。[E0 §6]

本版明确修订上一轮设想：

1. **“固定推理预算”改为“显式记录预算，并在相同预算约束下选方案”。**1、2、10 个 view 不等成本；同样 view 数也不意味着不同模型的耗时相同。
2. **首先统一 padding、逐 view 随机策略、batch grouping 与环境，再比较视图集合。**旧 Quick 与旧 Main 只作为历史动机，不充当新对照的两个实验臂。
3. **不再假设这个方向几乎零成本。**E0 的限定盘点没有找到可立即使用的本地 MUSeg checkpoint，更没有现成的非 MMFR 成对权重。[E0 §8]
4. **进一步收紧创新判断。**2020 年的 SCrIBE 相关论文已经明确让模型面对同一损坏输入，并比较单尺度和多尺度。因此，“固定损坏 + 有/无多尺度”不是新的研究思想。[W-SCRIBE §4]

拟用工作题目：**《RGB-D 失效鲁棒性结论是否依赖推理协议？固定观测、随机配对与预算约束下的研究》**。

| 必答问题 | 本方案的回答 |
| --- | --- |
| 实际问题 | 用一种推理配置挑出的“更鲁棒”模型，换到部署允许的配置后，是否仍值得选择？ |
| 已有工作 | 传感器失效 benchmark、统一损坏比较、多尺度鲁棒性评价和 TTA 分析均有先例。 |
| 失败启示 | F-lite 的收益跨协议未复现，且多种变量同时变化；A-v1 的近零收益不是第二个翻转案例。 |
| 潜在新增 | RGB-D 缺失观测下可重复、跨方法的排序变化；其与预处理/随机推理的关系；对预算内模型选择的实质影响。 |
| 最小验证 | 第一轮先用恢复的 C0/F-lite 做三个统一策略，再用一组预先指定的外部方法验证；通过后第二轮跨数据集确认。 |
| 停止原则 | 统一后现象消失、只有 F-lite 成立、只发现本地 bug 或缺少独立方法证据，停止独立论文投入。 |
| 最终数据与对照 | MUSeg + NYUv2；DFormerv2-S、CMX-B2、GeminiFusion-B2，至少一个外部缺失鲁棒方法及其对应底座。 |

**优先级：低于方案 A。**统一评价中的必要部分可以服务 A；只有下面的科学准入条件通过，才把 B 升格为独立论文。最终保留两份方案，不意味着一定能产生两篇论文。

- **[E-F]** 旧 `2026-09-22-mmfr-e1-batch1a-c0-flite-mainval.md` 及结果 JSON；当前数值与状态引用 E0 的复核摘要。
- **论文依据**：已提供 PDF、先前 GeomPrompt 全文及既有索引；外部补充限于与本问题直接有关的 TTA/输入损坏鲁棒性先例和 NYUv2 官方说明。
- 文中三种新策略、随机配对规则、阈值和实验预算均是**本方案设计**，不是现成代码已经实现的事实。

### 1.2 已有四共同条件

| 条件 | Quick C0 | Quick F-lite | Δ pp | Main C0 | Main F-lite | Δ pp |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| clean | 53.46 | 54.15 | +0.69 | 56.69 | 56.02 | −0.67 |
| spatial_dropout@.75 | 51.40 | 52.39 | +0.99 | 53.92 | 54.32 | +0.40 |
| misalignment@.75 | 52.15 | 52.63 | +0.48 | 55.57 | 55.24 | −0.33 |

来源：[E0 §6.2]；数值沿用历史显示精度，不从舍入数值重新制定旧 gate。

这里能确认的是：**同一对 checkpoint 的相对收益，在不同评价协议下出现了符号变化。**不能确认的是：多尺度、翻转、padding、NMF 随机性或环境中的哪一个造成了变化。

历史 Quick 主量是三个困难条件的 M3，Main 主量是六种单故障的 M6。M3 的 +0.96 pp 和 M6 的 −0.3966 pp 不能直接相减来估计“多尺度效应”。

### 1.3 不能省略的协议差异

| 因素 | 旧 Quick-Val | 旧 Main-Val | 新研究如何处理 |
| --- | --- | --- | --- |
| 权重 | C0/F-lite 各自 fixed-final 2560 | 同一对权重 | 恢复精确权重，禁止挑别的 epoch |
| 数据 | val-dev 318，四条件 | val-dev 318，十条件 | 首轮固定同一四条件 |
| raw corruption | 原图损坏一次 | 原图损坏一次后生成 views | 在统一入口中真正复用同一份观测 |
| 图像尺度/翻转 | 原尺度无 flip | 五尺度，各原图+水平 flip | 三种预定义 view 集合 |
| padding | 不 pad | 右下 pad 到 32 倍数，normalized 0 | 全部策略统一 pad |
| 插值/输出 | 原图输入，必要时插值 logits | 多次输入缩放，裁 pad、反 flip、回原网格 | 使用同一套变换/反变换实现 |
| NMF | reset-per-unit 后一次 forward | reset 后依次多次 forward | 对相同 canonical view 使用相同随机起点 |
| view batching | batch 1 | 最小尺度原图+flip 合 batch 2，其余 batch 1 | 首轮全部按 view 顺序、batch 1 |
| 融合 | 单次 logits | FP32 平均 pre-softmax logits | 新策略统一采用后者的 logit 语义 |
| 精度 | FP32、TF32 off | FP32、TF32 off | 保持一致，但不宣称跨设备逐位一致 |
| 环境 | 云 4090，torch 2.1.2/cu118 | 本地 5060 Laptop，torch 2.7.0/cu128 | 一轮全部在同一环境完成 |

来源：[E0 §§6.1、7]。

同一 seed 数字不自动等于同一损坏数组；相同原始损坏也不等于各 view tensor 相同；相同 `eval()` 状态更不保证 NMF 不随机。E0 已明确这些层次，研究不能把它们简化成一个“固定 seed”开关。

### 1.4 其他失败不能拿来凑样本数

A-v1 的 hard learned−off 约 −0.001873 pp，门控值仅在约 0.541–0.543 间；其正式结论为 STOP。这不是有意义的协议翻转。R-OE 的约 +0.01 pp 又存在底座变化和缺少同权重 bypass 的归因限制。二者不作为本论文的“独立方法证据”。[E0 §11]

C0 与 F-lite 在训练时有样本顺序和 clean slot 的既有差异，不能据此做“只增加一个模块的严格因果”结论。但固定这两个训练产物后研究其输出对新推理协议的依赖，仍是可以明确界定的对象。[E0 §6.1]

## 2. 文献已占据的范围与本方向创新风险

### 2.1 最接近的先例

**MMSS Sensor-Failure Benchmark**已经定义整模态缺失、随机部分缺失与噪声评价，并使用多种模型。E0 的本地源码阅读发现其随机损坏脚本没有现成的 sample-keyed 观测复用；但这只描述所读源码，不证明所有论文实验均使用了不公平输入，也不能作为“本文首次统一损坏”的依据。[MMSS；E0 §10]

**SCrIBE 相关研究（2020）**在 §4 明确说明，让多个模型同时面对同一损坏输入以消除运行时生成差异，并比较 Multi-Scale Classification。论文表 2 还分别报告了有/无多尺度的正常及受损输入结果。因此，“相同损坏再比较单/多尺度”已有直接先例。[W-SCRIBE]

**Understanding Test-Time Augmentation**研究 TTA 的理论行为。它支持把推理增强当作需要明确说明的算法组成，但不为我们的具体 RGB-D 设置提供已经证明的收益或排序结论。[W-TTA]

**GeomPrompt**在 §4.3 使用 DFormer-B 的五尺度+翻转，以及 GeminiFusion MiT-B3 的单尺度 480×480 无翻转；同一个模型家族内的对照保持一致。这是论文明确披露的设置，不应批评为其家族内对照不公平。它提示跨架构比较时需要同时记录推理策略，不能从其两列数字单独分离架构效应。[AI023]

**局部损坏空间鲁棒性研究**已经讨论受损区域和未受损区域，不允许把“加区域指标”当成填补空白的唯一贡献。[W-SPATIAL]

### 2.2 其他已提供论文的作用

ConD、RobustSeg、SimMLM 和 SGMA 提供已有的缺失训练、蒸馏、排序与融合机制；它们是外部对照或解释边界，不是要在本方案里叠加的新模块。When Fusion Fails 的医学分辨率差异机制不能直接解释我们的 depth resize。OmniSegmentor 与 DFormer++ 的预训练/表示贡献也不等于失效鲁棒性结论。[AI024；PR090；AI026；PR089；AI025；OmniSegmentor；DFormer++]

### 2.3 什么才可能值得形成论文

必须同时具有：

- **超出孤例的发现：**跨独立方法、跨数据集的实质排序变化，而非一张表中 +0.01/−0.01 的交换。
- **RGB-D 特有的实证内容：**原始缺失观测、深度零值/插值、几何条件或随机解码如何参与这种依赖；不能只有泛泛的“TTA 会影响结果”。
- **决策价值：**预算内的模型/策略选择确实受影响，并能在独立评价中验证；不是把昂贵模型换成便宜模型这个常识。

**统一输入、固定随机数、记录 latency、画 Pareto 图都是研究工具，不自动是算法创新。**尚未发现上述三条都成立的本地证据，所以本方向目前只能保留为高风险候选。

## 3. 可证伪的论文主张

### 3.1 主问题

> 面对同一份已发生深度失效的传感器观测，改变合法的推理 view 集合后，一个鲁棒方法相对于其底座的优势是否会实质改变；这种改变是否足以影响预算内的模型选择？

“同一份观测”指损坏后的原始 RGB-D 数据，不是要求所有 view 像素数组完全相同。

### 3.2 研究假设

**H1：协议依赖仍然存在。**统一 padding、环境、输入与随机调用规则后，C0/F-lite 的收益翻转仍达到实用量级。

**H2：不是 MMFR 孤例。**一组预先选定的已发表外部方法及其对应底座，也出现同类有意义的结论变化。

**H3：不是单次随机抽样或单一数据集偶然。**固定方法后，新的评价随机流和 NYUv2 能支持相同类型的观察。

**H4：有部署意义。**这种变化影响相同延迟上限内的可行选择，并有明确的独立结果支持。

第一轮主要判断 H1/H2；第二轮判断 H3/H4。不得在 H1 失败后无限搜索新的策略组合来寻找反转。

### 3.3 允许的失败结果

统一后翻转消失，是有价值的内部工程结论，但不自动构成这篇论文。若只能确认历史存在混杂、无法锁定一个因素，则应如实记录“联合统一后未复现”，不能反推单一因素负责。

## 4. 三种统一策略：只保留必要控制

### 4.1 一次生成的观测

对每个样本 $x$ 和条件 $c$，只生成一次受损深度：

$$
\widetilde D_{x,c}=C(D_x;c,\eta_{x,c}).
$$

$C$ 复用现有故障实现，$\eta$ 是按样本和规范条件确定的随机流。所有模型、所有推理策略复用这份 $\widetilde D$，不能在 view 内再次生成损坏。

沿用 `clean`、`spatial_dropout@.75`、`misalignment@.75`、`entire_missing@1` 四个条件的规范身份，不能由于局部列表重排而偷偷改变 condition index。无需为此建立新哈希库；在单次运行中共享对象/缓存，并保留清晰的配置记录即可。

### 4.2 三种策略

| 策略 | view 集合 | 所有策略共同规定 |
| --- | --- | --- |
| S1 | scale 1.0，original | 统一原始输入与归一化；右下 pad 至 32 倍数；whole；batch 1 |
| S2 | scale 1.0，original + horizontal flip | 同一变换代码、原标签网格、FP32/TF32-off |
| S10 | scales .5/.75/1/1.25/1.5，各 original + horizontal flip | 裁 pad、反 flip、回原网格，FP32 等权平均 pre-softmax logits |

这是新研究协议，**S1 不是旧 Quick-Val**。旧 Main-Val 不修改，旧分数不替换。用少量清晰参数记录新协议即可，不创建多层 profile/manifest 体系。

S1→S2 回答固定尺度下增加翻转视图的总效果；S2→S10 回答在已有翻转策略上增加尺度的总效果。两者都增加计算，不能描述为免费增益或严格等成本实验。

### 4.3 随机性如何配对

对每个 canonical view，用稳定的“样本—条件—尺度—翻转标识”确定推理随机起点；S1 的原尺度 original 与 S2/S10 中同一 view 使用相同起点。首轮不将某两个 view 临时合 batch。

C0/F-lite 共享的 HAM/NMF 调用应配对到对应随机入口；不能只在整套 S10 开始时恢复一次状态，再声称其第五个 forward 与 S1 是同样抽样。不要修改 NMF 算法、强行关闭其随机性或更换解码头来追求通过。[E0 §7]

外部模型按其实际随机模块处理；不要求不同架构使用形状不相容的同一随机张量。若外部方法的路径差异导致额外随机消耗，须明确配对到了哪一层，不能用全局 seed 相同代替说明。

**重要边界：**相同 view 的配对并不消除“更多 view 带来更多随机预测平均”的影响。第一轮研究的是完整推理策略效应；要声称尺度几何而非随机集成导致变化，需要第二轮的专门对照。

### 4.4 可复用入口

E0 已定位：`build_original_full_input`、`build_msflip_views`、`build_rgb_view_cache`、`assemble_views`，以及 `unit_seed_words`、`corrupt_depth`、FAST RNG capture/restore 和 `NMF2D._build_bases`。[E0 §7]

最小实现是一个薄入口：共享 raw corruption → 构造规范 views → 配对前向 → 共用输出变换与计分。不是重写训练框架，也不是迁移整个 MMSS 工程。

MMSS 当前根目录许可未确认，且依赖 DELIVER 的 `semseg.*`。其代码可供阅读，不自动授权复制到本项目；本方案以现有自有 runner 为主。[E0 §10]

## 5. 指标与预算：避免制造新的混杂

### 5.1 先在同一条件集合内比较差值

设 $J_{m,p,c}$ 为方法 $m$、策略 $p$、条件 $c$ 下的数据集级 mIoU。每个条件先累计 confusion matrix 再计分。

$$
M_{3,m,p}=\frac{J_{m,p,\mathrm{SD}}+J_{m,p,\mathrm{Mis}}+J_{m,p,\mathrm{EM}}}{3},
\qquad
\Delta_{m,p}=M_{3,m,p}-M_{3,b(m),p}.
$$

$b(m)$ 是该方法预先指定的对应底座。协议对相对收益的变化量为：

$$
I_m=\Delta_{m,\mathrm{S10}}-\Delta_{m,\mathrm{S1}}.
$$

这些只是常规差值定义，不命名为新的鲁棒性指标。$I_m$ 反映固定模型对新策略的响应差，不证明训练机制的因果贡献。

clean 单独报告，三个困难条件也逐项报告；不能让其中一项大涨掩盖另一项严重下降。第二轮扩到六类单故障时另报 M6，不用它替换第一轮 M3 进行前后比较。

### 5.2 一张图的“缺失率”可能有两种含义

原始 acquisition support（真实有无观测的位置）经过尺度变换，与线性插值后数值仍为零的位置并不必然一致。[E0 §§5–7]

可以在已有 view 构造时顺手记录两者的差异，作为解释线索：原始二值无观测 mask 用最近邻变换；Depth 仍沿正式数值插值路径。**只测量，不改变模型输入，不抑制几何先验。**插值得到非零值不意味着传感器重新观测到了那个位置，也不能把这类比例变化直接当成排名变化的原因。

这一描述量不单独启动额外大实验；若没有清楚机制证据，论文只报告总协议依赖。

### 5.3 latency 的定义

在同一硬件、同一软件栈、单图请求条件下测时，包含 view 变换、模型前向、反变换和融合；人工故障生成与磁盘读盘单独列出、不混入主推理延迟。GPU 测时需要正确同步，先有少量预热。

功能比较阶段固定 view batch 1。原生实现的批处理加速可以另列，但不能一边改 batch、一边仍称只比较尺度。报告中位数及一个尾部量，例如 P90，不进行复杂服务性能审计。

**同 view 数不是等延迟，同一策略也不是不同模型的等成本。**参数量和 FLOPs 只能辅助解释，不能替代本机实测。额外分支的全部计算要计入，不能给 ConD 等方法漏算辅助编码器。

### 5.4 预算内选择

给定延迟上限 $\tau$，候选是“模型 + 策略”的组合：

$$
\mathcal F(\tau)=\{(m,p):t_{m,p}\le\tau\}.
$$

在开发集上从可行集合选择鲁棒分数更高的组合，再在独立评价上验证。可画质量—延迟 Pareto 边界，即没有另一组合同时更快且更准确的选择集合。

没有实际部署时限时，可以在看精度结果前，约定以 C0-S1 延迟为单位的固定预算档位，例如 1×、2×、4×、12×。这些是分析用档位，不是已知矿下机器人需求；报告全部档位，无可行方案就明确写无可行方案，不能事后只展示最有利的预算。

## 6. 第一轮：先确认现象，再付出外部方法成本

### 6.1 准备条件

先从已记录远端/归档中恢复 **C0 与 F-lite 的精确 fixed-final 权重**。E0 的结论是限定目录未找到本地文件，不是权重永久丢失。不能重训两份新模型然后声称复现旧翻转。[E0 §8]

准备统一入口只需必要输入/输出检查：相同 raw 观测确实共享，S1 在三个策略中的对应 view 路径一致，计分使用相同标签网格。代码阅读足以确认的事项不再造 unit test；最多用极少数已允许的 dev 样本核对前向和输出形状，不运行全项目测试。

本文件不授权连接付费云资源、开训练或读 official test；执行预算须在启动前明确。

### 6.2 第一轮 B1a：C0/F-lite 的统一比较

固定 **2 个 checkpoint × 318 图 × 4 条件 × S1/S2/S10**。按 view 计为 33,072 次模型—样本 view 前向；各尺度开销不同，这个计数不是耗时估计。

这已经不是一两张图的 smoke check。优先在同一台机器完成；用首批少量实际样本给出总时长估计，不使用“十个 view 等于十倍延迟”的假设。

只输出一张策略—条件表、clean/M3 差值、逐组计分所需的混淆计数与实测延迟。无需默认保存全部 logits、逐层激活或高清预测图。

**B1a 若不支持明确翻转，立刻停止独立方向探索。**不扩展到二十种尺度、各种融合权重、不同 padding 取值或多套精度，以便找到某个能翻转的配置。

### 6.3 第一轮 B1b：一个预先指定的外部方法对

只有 B1a 过线才安排。优先候选是 **ConD 与其官方支持的 DFormer 底座**，理由仅是 E0 已记录 `RGBD-MMCD` 外部代码，而不是已证明它会出现翻转。

必须满足同一 MUSeg 开发划分、清楚的训练来源、正确模型行为和可用权重。ConD 不能被“简化的 dropout”替代。移植到 DFormerv2 需明确标为移植；为减少新结构工作，优先使用原实现支持的底座。

**目前没有现成外部 MUSeg 成对权重。**若需要训练底座和 ConD，其成本必须单独估计并获批；不能把已有仓库或公开 NYUv2 权重写成“可直接在 MUSeg 验证”。

若 ConD 在工程上无法用，允许在看其分数之前明确改选另一个已发表方法及对应底座；不能因为 ConD 没翻转，就连续换方法直到找到有利案例。无法在允许预算内取得独立对照，则 B 保持资源阻塞/不立项，不继续修 F-lite。

### 6.4 第一轮准入与淘汰

以下门槛是快速分配资源的设计，不是领域标准。对两个预先指定方法对分别要求：

- S1 与 S10 的 **M3 相对收益符号相反**，两端绝对值均至少 0.25 pp，即收益变化至少 0.5 pp。
- 至少一个 Depth 失效条件也出现达到实用量级的变化；只有 clean 翻转不够支撑“模态失效鲁棒性”的主张。
- 不是由输入/类别口径错误造成，也不能仅靠某一个重复采集组撑起现象。使用已保存混淆计数做一次按采集组的敏感性检查即可，不把每个像素当独立样本。

**第一轮 GO 要求两组成立，且至少一组来自非 MMFR 的已发表方法。**B1a 通过仅表示值得考虑 B1b，不等于论文方向通过。

以下情况直接 STOP：统一后无翻转；仅有极小差值；只有 F-lite 成立；独立方法不支持；只有本地实现 bug；或者所有现象只是已知“更多计算通常更好”，没有实际选择改变。

若只有资产缺失，标记 BLOCKED，而不是宣称假设被证伪；但从快速论文的投入角度，不自动批准漫长基线建设。

## 7. 第二轮：验证稳定性、外部性与实际选择价值

第一轮通过后，第二轮不改候选方法，不重新搜索 view 配置。

### 7.1 三件必要的事

**第一，换一个事先固定的评价随机流复验。**所有方法保持配对，只改变 HAM/NMF 等评价随机抽样。若翻转消失或只剩约零差，应降低为一次随机实现现象，不宣称稳定结论。该重复不等于多训练种子。

**第二，在 NYUv2 复现固定协议。**选择明确来源的 rawDepths 作为主观察输入，建立相应训练/评价版本；方法与底座使用同版本。不能把本来基于 filled 输入训练的模型突然改喂 raw 后的掉点全部解释为方法不鲁棒。NYUv2 需要的数据和训练成本必须计入。[W-NYU；E0 §9]

**第三，验证预算内选择。**在开发集上固定模型—策略选择规则和预算档位，然后在独立评价中比较这些已固定选择。不能用最终测试分数反选模型，再报告“最优选择获得提升”。

### 7.2 一个有针对性的随机集成对照

如果论文准备把变化解释为“尺度/几何观测的作用”，需要把它与“多做几次随机预测取平均”区分。

第二轮仅增加一个对照：**原尺度 original 重复前向 10 次，每次独立但成对的 NMF 抽样，再平均 logits。**它与 S10 的前向次数相同，但不同分辨率的计算不同，不能称严格等算力；仍要实测延迟。

若重复原图已产生相似结果，支持的是随机集成解释，而不是多尺度带来新的传感器信息。没有必要同时扫所有随机种子或替换解码头。原模型没有相关随机模块时，这个对照可能无意义，应说明并省略。

### 7.3 第二轮停止线

建议继续要求：首轮至少一个外部方法对在新随机流中保留明确的协议依赖，并在 NYUv2 得到同类型、非微小的选择影响；预先固定预算内的选择比较，在独立评价中至少出现一个约 0.5 pp 以上的实际差异，其他档位完整报告。

这仍是投入门槛，不能替代置信区间。最终按采集组/场景对成对差值做重采样，区分数据波动和训练/推理随机波动。

若只在 MUSeg 上成立、只在 HAM 上成立或只对 F-lite 成立，应据证据缩小结论；若不足以超过既有 TTA 研究的简单复现，就结束独立论文路线，保留为项目技术说明。**不通过新增门控、换主干、另找数据集继续救方向。**

## 8. 最终数据集与 baseline 矩阵

### 8.1 数据集固定为 MUSeg + NYUv2

MUSeg 负责真实矿下部分缺失场景；NYUv2 负责不同场景的 RGB-D 外部验证。本方案不扩到 DELIVER 的四模态接口，也不在首轮引入第三个数据集。

NYUv2 官方标注包已包含投影后未补洞的 `rawDepths` 和补洞后的 `depths`，单位为米，约 2.8 GB；不是必须下载完整录像。主表使用 raw 版本，filled 版只能是注明来源的补充，不能在看到结果后切版本。[W-NYU]

数据集内训练与评价分别进行，类别空间不混合；使用两数据集不等于零样本跨域。MUSeg 继续沿用开发集与采集组隔离；NYUv2 的内部开发划分来自官方训练部分，按 scene 分组。原先封存的 official test 只在协议、比较对象和选择规则固定后启用。

### 8.2 最终最低对照集合

| 组合 | 必要作用 | 注意事项 |
| --- | --- | --- |
| DFormerv2-S 的 C0 / F-lite | 问题发现案例，解释旧实验 | 不是外部独立方法；不由此恢复 F-lite 有效性结论 |
| ConD / 对应 DFormer 底座 | 第一组已发表缺失鲁棒方法对 | 使用原支持结构；复制编码器计入真实成本 |
| CMX-B2 | 不同融合结构的固定策略比较 | 尚需 MUSeg 适配/权重，不声称就绪 |
| GeminiFusion-B2 | 另一种融合结构，避免只研究同一解码器 | 推理随机性与输入表示按实际实现记录 |
| GeomPrompt-Recovery / 对应底座 | 有条件补充最近的输入修正路线 | 官方完整代码未确认，不能设为首轮阻塞项；论文重实现必须显式标注 |

E0 中的 `RMMSS`（RobustSeg）代码可作预先明确的替代或补充，但不因“已有 clone”就默认复制整套训练。DFormer++、OmniSegmentor 不作为必做项；所有版本名称保持区分。[E0 §§8、10]

至少覆盖一个不依赖当前 HAM/NMF 的模型实现，才能降低“只是这个随机解码器特性”的解释。如果外部实际实现仍共享相同模块，应如实记录，不按论文名字不同就当成机制独立。

### 8.3 两种表必须分开

**控制表：**同一底座/方法对、同一观测和统一 S1/S2/S10，研究相对收益如何变化。

**系统表：**不同模型的实际质量与延迟，研究预算内有哪些可选组合。相同策略不代表不同架构等资源；原生论文设置可单列，但不混进控制表。

RGB-only 可作退路参考，但没有必要为了凑排行榜新增大量单模态模型。若使用，必须正常训练，不能把双模态模型 Depth=0 直接命名为独立 RGB-only。

## 9. 论文可以怎样写，什么情况下不应写

### 9.1 可能成立的贡献组织

贡献一：在明确的深度失效观测下，展示多方法、双数据集的协议依赖，并区分原始观测、view 变换和随机前向。

贡献二：用有限的控制实验说明至少一个具体机制或关键混杂；如果只能确认总体依赖，就明确这是实证结论，不编造“几何被破坏”等因果解释。

贡献三：给出可复用的评价实践和预算内选择证据，而不是“提出新的融合网络”。代码产物可以是薄 evaluator 和规范的实验表，不需要开发评测平台。

### 9.2 最小图表

| 图表 | 要表达的内容 |
| --- | --- |
| 历史差异表 | 旧 Quick/Main 同时变了什么，为什么不能直接归因 |
| 策略—方法差值图 | 两个独立方法对在相同四条件中的 Δ，而不是混合绝对分数 |
| 控制结果 | padding/随机性统一后的结论；必要时原图重复预测对照 |
| 质量—延迟图 | 所有候选组合、预先指定预算和实际可行选择 |
| 第二数据集结果 | 同一研究问题在 NYUv2 是否成立，边界在哪里 |

不要求画复杂理论框架图，不为一篇实证研究强造模块缩写。

### 9.3 不能使用的表述

不能说“首次使用相同损坏输入评价”；不能说“首次发现 TTA 影响鲁棒性”；不能从 E0 的源码观察指控已有论文不公平；不能把一个 NMF 抽样的翻转称为普遍规律；不能为了挽救 F-lite 事后宣布单视图才是唯一正确口径。

若论文最终只是“统一了本项目的一些工程细节”，其价值是提高本项目可靠性，不足以自动支持独立论文。这个判断应当在第二轮结束时兑现，不通过继续扩矩阵拖延。

## 10. 资源与执行边界

### 10.1 最大资源风险

并不是新 evaluator 需要多少行代码，而是**缺少真实可用的独立 MUSeg 基线权重**。恢复 C0/F-lite 可以支持 B1a，但不能替代 B1b。[E0 §8]

因此建议的投入顺序是：先服务方案 A 的最小统一单视图入口；在权重恢复后，单独估价 B1a；B1a 通过才讨论外部成对基线成本。没有充分预算时，将 B 作为备用计划保存，而不是一边搭平台一边等待论文问题出现。

### 10.2 下一张执行单

**目标：**恢复精确 C0/F-lite，准备 S1/S2/S10 的统一入口和 B1a 预算。

**输入：**本方案、E0、旧结果与权重记录、现有 view builder/RNG/metric 代码。

**允许改动：**独立薄 runner、必要日志字段、少量输入/前向检查。机械性文件定位和代码工作可交给子模型。

**禁止改动：**旧 evaluator/原始结果、训练参数、NMF 算法、主干/解码器、official test；不自动新增外部方法训练或大规模硬件对照。

**最小验收：**同一原始损坏观测复用；三策略公共 view 的输入与随机政策一致；padding 和计分路径统一；两份正确权重能够加载。只做能消除明确歧义的检查，不重复全仓审计。

**输出：**权重恢复位置、三策略参数、预计耗时、B1a 是否可执行；运行获批后交策略—条件结果和明确 GO/STOP。初始 Git 仅保存一次必要改动，干净则不空提交；不增加 manifest、全文件哈希或重复状态审计。

外部仓库仍放 `D:\0Project\origin`，先检查已有目录/索引/remote，禁止为同一论文重复 clone。源码许可不清晰时只作阅读参考。

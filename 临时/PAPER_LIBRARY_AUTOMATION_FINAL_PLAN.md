## 3. 工具合同：一个薄封装、四个子命令

`paper_workflow.py` 使用普通工具环境 `D:/2Env/anaconda/python.exe`，复用现有依赖；提供 `intake-plan`、`intake-apply`、`supplement-plan`、`supplement-apply`。不调用模型 API，不自动阅读或生成科研判断。

- 共用 `--index` 参数，默认指向外部权威 JSON；资产根目录取已加载索引的 `library_root`。隔离验收允许显式 `--index` 与配套 `--root`，真实运行时根路径不一致即停止。派生 Markdown 路径由所选 index 推导，不能落回硬编码正式位置。
- plan 命令默认只读权威索引/原资产，仅写用户指定的一个审核 JSON 并输出简短可读摘要；同名审核文件已存在则拒绝覆盖。它是本次操作输入，不是第二份活动索引。
- apply 必须传入 `--plan` 和与已审核文件一致的 `--approved-plan-sha256`。此参数只绑定批准内容，不能替代用户或上级模型的实际授权；Skill 必须先取得明确批准。
- 审核 JSON 只含操作类型、实际 index/root、基线指纹、审批对象、必要资产清单或 supplement 白名单变更。没有常驻任务队列、独立 manifest 文件、历史日志库或自动恢复数据库。
- 所有正式保存都调用 `store.save_index(..., expected_fingerprint=审批基线)`；不改写 JSON，不调用带硬编码索引位置的 `_write_indexes`。保存后用 `SaveResult` 区分 JSON 已提交和派生视图重建失败。
- 无实际新增或无字段变化时不保存、不轮转备份、不增加 revision。冲突返回失败并列出准确阶段、已发生的复制/提交和恢复前置条件；不自动回滚或重试提交。

## 4. 工作流 A：paper-intake

### 输入与预检

输入为用户指定的 bundle 或一层 bundle 父目录；不接受模糊的全盘搜索，不接收压缩包自动解包。用户同时指定审核计划落点。默认仅批准全新论文接入。

1. Skill 读取项目状态、外部入口和共享 Rule；工具通过 store 加载真实索引，取得基线指纹 F0。索引缺失/结构非法、身份冲突或需要未获准的 schema 迁移即停止，禁止重新初始化或 bootstrap。
2. 逐个枚举指定来源，调用 `_analyse_bundle` / `_eligible_markdown` 检查正文；不能只用 `_scan_bundles`，否则没有 Markdown 的异常目录会被静默漏掉。缺正文、空正文、正文身份不确定、文件不可读或不支持的链接/junction 均进入异常类。
3. 递归清点每个来源的全部普通文件，记录相对路径、字节数和 SHA-256，包含 mapping、DOCX、XLSX、辅助 Markdown 与其他附件；不只统计四类资产。空文件、缺少正文引用的本地资产作为异常；没有某一类资源本身不等于异常，不强制每篇都有 Figure/Tables/Formula/Word。

### 去重、审核计划

4. 候选查找覆盖索引的 canonical（正式主记录）、alternate（已有另一抽取 bundle）及本批互比。使用正文 hash、正规化题名和现有身份关系规则；既有 DOI/arXiv 优先用 `bibliographic_value` 的最终有效值，而不是忽略人工 override。arXiv 版本差异只能提示版本关系；作者/主题相近不作重复裁定。
5. 对可能相同的实际 bundle 才计算其完整资产清单，不哈希全库全部附件。查找基于索引线索；候选实际路径缺失或正文 hash 与索引不符则停止该候选判断，不把过期索引当作可靠等同证据。
6. 分为五类并写出理由：
   - **全新**：无身份/版本候选、预检正常、目标无冲突，可进入待批准复制列表。
   - **全资产重复**：正文和全部文件路径映射/字节 hash 一致；保留来源，跳过复制和索引修改。
   - **正文相同、附件不同**：列出新增/缺失/改变的附件，留原处待人工判断；包含 UMIS-Mine 类情况。
   - **疑似版本**：同身份但正文不同、标识冲突/版本差异、相似题名或多个候选；留原处待裁决。
   - **异常 bundle**：列出结构/读取问题，不能进入 apply。
7. 全资产比较只允许将已识别的主正文文件名映射为统一正文角色；其余附件按原相对路径比较，不随意按 hash 忽略文件名或配对资产。比较不确定时不宣称完全重复。同批完全重复可建议只接入一个明确代表，仍由审核计划批准。
8. 审核 JSON 保存 F0、每项分类/来源/完整来源清单、匹配论文身份、候选比较摘要及其全清单摘要指纹、批准候选的目标与主正文重命名映射。目标名复用 `_safe_component`；只有复制后的主正文可按批准映射改文件名，字节不改，附件名不改。目标撞名不自动加后缀选版本。
9. 向用户/上级模型提交分类和精确操作清单并停止。不得自行把疑似版本变成新 LIB、alternate 或 duplicate-review。审批可只选择安全子集；其余继续保留。

### 获准后复制、dry-run、提交、验收

10. apply 核对批准计划 hash、index/root、F0、全批来源清单及参与判重的候选；目标必须仍不存在。全部预检查通过后才开始复制，拒绝 source/root 重叠、嵌套目标和链接。仅复制批准的全新项，来源不移动、不删除，不调用 bootstrap 或导入路径模式。
11. 复制及批准的正文改名后，按已批准路径映射比较目标全文件清单和 hash，并再次确认来源仍等于审核清单；任何差异立即停止，报告已复制目标。复制中断留下的目录不自动删除或当作完整入库。
12. 通过 `_refresh_plan(root, {})` 和 `_sync_index(...)` 做只读内存 dry-run：传原 store 文档和空 duplicate 输入，不附历史编号映射，不执行文件系统动作。复用现有 LIB 分配，不手工编号。将 `to_disk_document` 前后比较结果输出为索引提交摘要。
13. 提交许可仅限新增批准路径的一篇一条记录与相应 `next_lib_number` 更新；旧完整记录、LIB顺序、human、override、supplement、alternate、duplicate-review及其他根字段均须不变。出现身份警告、旧记录刷新变化、unexpected missing 或超出批准清单的新增即停止并重新送审，不扩大写入权限。
14. 若 dry-run 正好满足批准合同，重新确认磁盘指纹仍为 F0，再调用一次 `save_index(expected_fingerprint=F0)`；锁内并发核对由 store 完成。不能另起普通 CLI 刷新后用其新指纹绕过审批基线。
15. 重读已保存索引，验收路径→LIB、实际新增数量、原完整记录保护、人工编号为空、schema/备份、目标资产和来源保留；通过现有 `write_markdown_view` 重建管理视图。AI 阅读导出有需要才复用既有导出函数，不新增转换器。

**输出**：审核 JSON/摘要；成功后的来源→目标→实际 LIB 对照及提交指纹/验收结论。**停止**：审批缺失、计划或来源变化、并发修改、候选不明确、目标冲突、复制/资产校验失败、dry-run超范围、store拒绝或验收失败。JSON 已保存但 Markdown 失败单列为派生产物问题，不重做复制/保存。来源清理永远另行授权；本版工具不提供自动清理、版本合并或 rollback 命令。

## 5. 工作流 B：paper-supplement

**输入**：上级模型给定的 LIB 或已确认人工编号、研究问题/指定阅读范围、是否允许查官方实现、草稿/审核计划位置。默认阅读状态保持原值，默认追加而非替换已有笔记。

1. 按 LIB 精确定位；人工编号复用 `manual_id_key` / `manual_ids_of`，包括归属该 LIB 的既有 alternate 编号。未核验编号只作线索；零匹配、多归属或指定编号互相矛盾即停止。确认正式记录和正文路径，不把 pending 来源当 canonical。
2. 先用 `supplement-plan --id …` 的只读定位模式获取 F0和本篇上下文（无 `--draft` 时不生成审核文件），完整读取已有 `human.supplement`、阅读状态和本篇书目；保留旧正文、旧来源、旧限定语。此时记录正文及实际拟读本地证据的 hash，阅读期间变化需停止复核。缺正文或指定附件不可读即说明阻塞，不伪造阅读。
3. Skill/执行模型只读指定正文及必要图表、表格、公式，必要时读取获准的官方代码。数值优先结构表并核对正文；未实际打开的 XLSX、附录或图不算已读。官方实现事实须有 URL/本地路径、文件/函数/行范围及 commit（可取得时），不能用 README 发布承诺冒充已检查实现。
4. 草稿采用四个短区块：阅读范围与未读范围；论文作者事实及来源；官方实现事实及来源；模型判断/与当前研究的关系及不确定项。每条关键结论标正文路径+章节/图/表/公式，代码结论另标实现来源。分别使用“未阅读”“已读范围未报告”“尚未核实”，不把局部缺项扩大成全文未报告。
5. `supplement-plan --id … --draft … --expected-fingerprint F0 --plan …` 先拒绝阅读期间的索引/证据变化，再生成可审核的新 supplement 和差异摘要：默认在旧 `content_md` 后追加一个有范围标记的补充段，旧文本作为完整前缀保留；旧 `sources` 及其他 supplement 扩展键保留，新来源按现有兼容结构附加。修正/替换必须在审核计划明确列出旧段、新段及理由，不允许无说明全覆盖。
6. 审核计划绑定 F0、唯一 LIB、草稿 hash、正文/实际引用本地证据的 hash、拟保存 supplement、阅读状态是否变化；`source_note` 保留原说明并追加本次阅读范围，`updated_at` 在正式保存时写入。追加内容已存在或完全相同则 no-op，不重复追加。
7. 向用户/上级模型送审并停止。获准后 `supplement-apply` 校验计划 hash/F0/草稿及正文、已引用本地证据的 hash，禁止把审核后变化的证据当成原审核输入；只将批准对象补入从 F0 加载的文档。
8. 保存前用 `to_disk_document` 做白名单比较：只允许指定 LIB 的 `human.supplement`、被明确批准的 `human.reading_status` 改变；其他所有论文/字段和 `next_lib_number` 均须不变。通过 store 保存一次并重读验收，重建管理视图；需要 AI 导出时调用现有导出函数，存储正文不改标题格式。

阅读状态只使用 store 现有枚举。局部阅读默认 keep；若上级明确要求跟踪剩余全文工作，可批准 `needs_full_text`。`full_text_completed` 必须有明确全文范围完成记录及单独批准，笔记非空或读了方法/实验不满足条件。本版不新增 `partial_read` 状态。

**输出**：证据草稿、一个审核 JSON及限定字段差异；保存后的实际指纹/状态/验收摘要。**停止**：定位不唯一、证据不可取得、旧笔记冲突、审核缺失、正文/计划/索引变化、越权差异或保存失败。证据缺项可以明示后交审，不能虚补事实；科研判断与最终裁决仍由上级模型或用户负责。

## 6. 复用清单与最小新增功能

现有接口已直接核对，执行模型按以下边界复用，不另建写入器：

- `paper_library.py`：`Bundle.record`、`_eligible_markdown`、`_analyse_bundle`、`_normalise_title`、`_relation`、`_safe_component`、`_refresh_plan`、`_sync_index`。最后两个负责内存扫描/同步计划及稳定 LIB 分配，不直接保存。
- `paper_library_store.py`：`load_index` 返回内部文档与指纹；内部论文的 auto 字段是扁平的，不能误按磁盘嵌套结构编辑。`library_id_of`、`manual_id_key`、`manual_ids_of`、`bibliographic_value`、`validate_document`、`to_disk_document` 用于定位、最终值和差异验收。
- `save_index` 返回 `SaveResult`，已包含短锁、指纹复核、备份和原子替换；`file_fingerprint` 用于操作前后核对；`now_iso` 用于时间戳。不要再包一层长期锁或文件事务。
- `write_markdown_view`、`render_ai_markdown` / `write_ai_export` 已可重建派生文件；`_export_supplement_markdown` 已处理标题、围栏、公式和链接，原样复用，不修改存储笔记以迁就导出。
- `paper_library.cmd --dry-run` 仍是人工维护入口，但输出没有完整逐字段保护报告，且不能携带审批时的外部指纹；新工作流直接复用内存 API 并显式调用 store。不要使用 `_import_plan` 的弱 exact 判断或让 `_sync_index` 决定未批准版本归属。

必须新增且只放在 `paper_workflow.py`：

1. 指定来源枚举/异常显式报告、全文件路径+大小+hash清单、候选资产比较和复制前后映射核验。
2. 五类入库审核、审批 hash与基线指纹贯穿、只复制批准新项、内存 dry-run白名单验收；阻止弱 exact/alternate自动决策。
3. LIB/人工编号定位、保留旧笔记的 supplement计划、仅 supplement/阅读状态保存和no-op检测。
4. 参数化隔离 index/root、简短错误/部分成功输出，以及批准前后逐记录差异核对。

推荐修改范围：新增上述四文件；外部 `_index/README.md` 加四子命令/审批与中断说明，`DFormer/doc/guides/external-resources.md` 加两个 Skill 的调用入口。现有 scanner/store/UI及启动器保持不变；无新增依赖、测试框架、数据库或常驻服务。实施完成的事实与恢复点届时由主代理更新 `doc/state/current.md`，本轮不更新。

## 7. 分阶段执行与最小验收

### 阶段 1：Skill / Rule

按第 2 节新增三个入口，描述分别限定“处理后 bundle 接入”和“指定论文证据补充”；写清默认只出审核材料、审批后才apply、跨消息重新调用。先按第 3–5 节写命令合同，阶段 2 再与实际 `--help` 定点对齐；不在Skill复制函数说明和历史状态。

**最小验收**：frontmatter、路径、调用示例和审批边界内容复核；Customize及 `/` 能发现两个独立入口，调用一个不要求读取另一个Skill。未刷新时先重新加载窗口。只做文档内容复核，不运行项目测试，不执行真实操作。

### 阶段 2：最小工具

先实现共用加载/审批/差异比较与四子命令参数，再完成 intake清单/比较/复制和supplement追加/保存；直接调用第 6 节API。注重合法路径、no-op、锁内冲突和JSON已提交的状态输出，不扩展版本处理系统。

**最小验收**：`--help`、修改区域静态诊断和只读/纯内存定点检查，明确 plan无正式写入、apply无批准拒绝、没有直接JSON写入或bootstrap调用。禁止为无关warning重构源码。

### 阶段 3：隔离验收

本计划获准后，仅在系统临时目录创建少量合成bundle与隔离索引，所有命令显式指向隔离路径；LIB由现有 `_sync_index` 生成。用短内存断言及实际工具命令，不新建验证脚本/测试文件，不复制完整真实论文库或引入测试框架。

**最小验收用例**：

- intake覆盖全新、全资产重复、正文同/附件异、疑似版本、无正文异常；特别有“文件数相同但一个附件hash不同”的UMIS类样本。
- 目标占用、正文改名映射、源文件在审批后改变、同批互比；完全重复/无新增不保存，成功复制来源仍在。
- 内存dry-run和一次保存后，旧编号/human/override/supplement/alternate/duplicate-review不变；批准外的变化拒绝。
- supplement已有内容追加保留、编号规范化定位、无变化no-op；局部阅读不自动完成全文；白名单外字段变更拒绝。
- 审批后改变隔离索引、持有同一store锁导致超时、复制中断/校验失败均停止；JSON成功而Markdown失败时报告已提交，禁止二次保存。只做这些覆盖新增风险的定点用例。
- 验收前后正式索引指纹不变；工具参数与调用记录证明所有写入落在隔离目录。完整项目测试不运行，因为不能覆盖论文工作流的主要风险。

### 阶段 4：申请真实试用

给用户/上级模型提交文件差异、上述定点结果和一个最小试用申请：一篇用户确认全新的bundle + 一篇指定LIB的追加证据补充，分别审计划、分别授权。UMIS-Mine不作为自动合并试用对象。

**最小验收**：获准后真实intake严格走“预检→审核→复制→资产核验→内存dry-run→正式同步→验收”；supplement严格走“定位→旧补充→定点阅读→草稿→审核→保存→验收”。核对实际字段/资产及来源保留；主代理记录结果与恢复点，然后停止。没有授权即只提交申请，不自动试用、清理、Git提交或推送。

## 8. 需用户/上级模型裁决的少量事项

1. 是否批准本实施合同以及其中的最小隔离数据/定点验收范围；本文件尚不意味着授权实施或正式索引写入。
2. 真实试用选哪一篇确认新bundle、哪一篇LIB及具体阅读问题；UMIS-Mine历史来源路径当前不可读，若将来处理需先提供现位置并单独裁决资产差异，不阻塞工具建设。



1. **不要启动云实例、capacity probe 或正式训练。先把当前状态从“可进入 cloud probe”改为** `needs-local-qualification-before-cloud-probe`**。** 保留现有 gradient-path isolation 的 PASS，不撤销已有证据；但把文档中“因此 A2 分割性能变化的直接原因就是 corruption exposure”“不再需要任何进一步隔离”的措辞收窄为：**“FP32 数学梯度层面已证明 auxiliary reliability loss 不改变共享参数梯度；实际 AMP/GradScaler optimizer-update trajectory 尚未证明完全隔离。”** 原因是当前门禁只覆盖 batch size 1、FP32、单进程、单样本，而正式训练明确使用 AMP、batch size 10。 更关键的是，历史 v1 GPU preflight 的前 6 次尝试中有 5 次被 GradScaler 跳过，因此这里不是纯理论风险。
2. **新增一个正式阻塞门禁** `MMFR-A2-v2-amp-update-path-isolation`**。** 不要只比较 backward gradient，而是使用真实 v2 Depth-corruption 模型、真实训练 batch、正式 AMP + GradScaler 路径，对同一初始化、同一 batch 序列、同一 corruption/RNG 做两条严格配对轨迹：A 为 `lambda_rel=0`，B 为 `lambda_rel=0.1`。每一个 attempted step 都记录 `GradScaler.get_scale()`、是否发生 optimizer step、shared gradients finite 状态、shared optimizer state、shared model parameters。至少获得 **10 个真实 successful optimizer updates**；如果 50 个 attempted steps 内仍得不到 10 个 successful updates，则门禁失败并报告。通过标准是：两条轨迹的 step/skip 序列完全相同、scale trajectory 完全相同、每次 successful update 后所有非 `reliability_estimator.`* 参数逐位或在冻结容差内一致；允许 reliability head 自身参数不同。若不一致，立即阻塞，不得继续声称 A2 的 auxiliary head 对 segmentation training trajectory 完全隔离。此检查应成为可复跑工具，不能再使用运行后删除的一次性脚本。
3. **新增** `MMFR-A2-v2-initial-state-equivalence`**，在任何训练前比较 clean control 与 corruption model 的共享初始状态。** 这是当前文档遗漏的公平性门禁。clean control 不实例化 reliability head，而 corruption model 会额外实例化 4,386 个参数；同时官方 pretrained 明确缺少 `extra_norms.0/1/2.{weight,bias}` 六个张量，它们依赖仓库初始化。 因此不能只写“相同 seed + 相同 pretrained”就默认共享初始权重相同。要求从两个独立新进程开始，设置完全相同 seed，分别构建 `MMFR-A2-clean-control-v2` 与 `MMFR-A2-depth-corruption-train-v2`，加载同一 official pretrained，然后逐名称比较所有共有 parameter 和 buffer。必须报告：common keys 数、exact-equal 数、最大绝对差、`extra_norms` 六个张量各自 SHA-256，以及 shared optimizer param-group 超参数。**共有模型参数必须全部一致。** 再分别重复构建两次，验证 `extra_norms` 初始化在冻结 seed 下可复现。若失败，先修 construction/load 顺序，不得训练。你当前文档自己也把 `extra_norms` 确定性列为未核验事项。
4. **把当前一次性 A2 CPU 47 项检查固化成仓库内可复跑脚本。** 新建类似 `tools/mmfr/a2_v2_cpu_qualification.py`，不要改变测试内容，至少复刻现有 47 项：clean exact no-op、Depth target、pad neutral、RGB unchanged、pre/post validity、invalidity balance、确定性、clean/corrupt 分支可达等。当前证据明确承认原脚本已经删除，因此外部审计者无法原样复跑。 新脚本执行后生成结构化 JSON，记录脚本 hash、代码 hash、样本 identity、assertion 数量和 PASS/FAIL。旧的 47/0 结果保留为历史，不覆盖。
5. **正式训练前必须做一次完整** `train-dev=1277` **的 Depth validity distribution audit；不得再用那个 98.5% zero 的单样本推测全数据。** 当前唯一实测样本几乎全部 Depth=0，而你也已经明确说它不能外推。 新建只读 CPU 工具，扫描全部 `train-dev`，至少输出每样本 `depth_valid_pre` 比例的 mean/median/std、P1/P5/P10/P25/P50/P75/P90/P95/P99、min/max，以及有效率 `<1% / <5% / <10% / <25% / <50%` 的样本数量；再按 location group 汇总。随后用冻结 corruption RNG 对训练进度 early/mid/late 各抽一组确定性样本，统计 reliability supervision 中 `natural_invalid / synthetic_missing / newly_valid / implicit_quality / clean-valid` 各占多少监督像素，以及 `R_D^sup` 的直方图。**这一项只收集事实，不允许低级模型自动修改 loss。** 审计结果返回后再决定 BCE 是否会被 native-invalid 像素严重支配。原因是当前 `R_D^sup=V_D^pre·R_D^syn` 会让所有原生无效区域直接成为 target 0；如果 MUSeg 普遍很稀疏，reliability head 可能主要学成“zero/nonzero detector”，而不是 graded reliability estimator。当前 R1 虽然计划区分 explicit-invalid 与 implicit-quality，但那是评价阶段，不能替代训练分布审计。
6. **暂时不要让低级模型自行“修复”** `newly_valid_pixels`**，先增加一个 validity-transport 审计，并按 corruption 类型拆开统计。** 对 `gaussian_noise / blur / quantization / misalignment / spatial_dropout / entire_missing` 分别记录 `V_pre`、`V_post`、输入值变化、`R_syn`、`R_sup`。特别把 misalignment 单独审计：报告“源坐标有效、目标原坐标无效但平移后出现非零”的像素，以及相反方向的像素。当前文档只是用一个闭合平衡式证明记账没错，这不等于 target 语义已经正确。 输出完成后将问题拆成两个明确选择供高级模型决定：**A）native-invalid sentinel 始终保持缺失，intensity corruption 只作用于已有有效 Depth；B）允许 corruption 产生 spurious depth，但必须把这种现象明确命名为 spurious-measurement corruption，而不能继续暗含在普通 Gaussian noise 里。** 对 misalignment 则另行决定 validity 是否应随 Depth 一起 spatial transport。低级模型不得替你选择。
7. **删除 R1/S1 中没有文献或前置假设支持的“起草期自拟成功阈值”，不要让用户为了冻结而随便选一个数字。** 当前模板里的 Spearman `-0.10`、Brier/AURC `5%` 相对改进、S1 `0.25 pp` 单调容忍等，都被文档自己标为 provisional。 我的建议不是“请你确认这些数字”，而是：R1/S1作为 supplemental analysis **只预注册指标、分组、估计量和置信区间，不设置新的成功/失败 gate**。R1 固定报告 MAE、Brier、risk-coverage、AURC、reliability-risk rank relationship 及其 bootstrap 95% CI；S1 固定报告各 severity 曲线、宏平均 robustness-AUC、单调违反次数作为描述统计。它们都不得替代主 A2 success gate。`bootstrap=10000` 可以保留为计算精度设置；`alpha=0.05` 若只用于 95% CI 可以保留。**Holm-Bonferroni family=12 只有在明确列出 12 个 confirmatory hypotheses 后才能存在，否则删掉。** C1 的 10,000 bootstrap 也可以直接冻结为计算设置，不要把它包装成科学阈值。
8. **把“当前未提交 dirty worktree”升级为正式运行前的 immutable source identity 门禁。** 当前所有 v2 hash 都对应未提交工作区。 在进入付费云 probe 之前，必须二选一：优先方案是形成一个本地 Git commit/tag（不要求 push）作为 `MMFR-A2-v2-pretrain-freeze`；如果确实不能 commit，则生成完整 source bundle / patch + manifest，包含 HEAD、`git status --porcelain`、完整 `git diff --binary`、所有新文件、protocol/templates、工具和 SHA-256。之后任何科学代码变化都必须新 identity。不能让 500 epoch 正式实验继续挂在“某个 dirty worktree 的若干单文件 hash”上。
9. **完成上述 2–8 后再更新总规划的恢复点。** 届时只有当 `initial-state-equivalence=PASS`、可复跑 CPU qualification=PASS、dataset validity audit 已形成并由高级模型确认不需要改变监督语义、AMP update-path isolation=PASS、source identity 已冻结，才可以把状态改成 `eligible-for-cloud-capacity-probe-authorization`。当前文档虽然说 gradient isolation 已不再阻塞，并把本地 v2 GPU preflight写成“若用户希望降低风险可做”， **这句要改：v2 AMP/update-path qualification 不是可选项，应成为正式训练前硬门禁。**



### 对当前方案本身的评价

上一轮最关键的结构性错误基本已经修正：A2 与 B1 的因果边界清楚了、Depth-only supervision 清楚了、severity 二次编码和分辨率依赖问题都被处理了，而且你们没有把单点 qualification 写成模型效果。文档也明确保持了“没有训练、没有 checkpoint、没有 MMFR 指标、没有 official test”的边界。

现在最值得警惕的反而不是“再设计一个新模块”，而是**不要太早开始 500 epoch**。尤其是你们已经发现一个真实样本里 native-invalid Depth 占比极高，又已经观察到历史 AMP preflight 有大量 GradScaler skip。这两个事实意味着“辅助可靠性分支数学上不回传 segmentation”还不足以推出“实际训练轨迹只由 corruption exposure 决定”。把上面这轮本地资格证据补齐，成本远小于两次 500 epoch 训练，却能明显提升后续结果的可解释性。

**所以我给当前版本的正式审计结论是：**`需修订后进入`**，不是** `阻塞`**，也还不是** `可进入云端容量/吞吐 probe 授权`**。**

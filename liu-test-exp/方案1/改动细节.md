## 3. 逐文件改动细节

### 3.1 `utils/dataloader/multimodal_failure_v2.py`（新增，A1 v2）

- **身份：** `PROTOCOL_ID = "MMFR-A1-corruption-basis-v2"`，`SUPERSEDES = "MMFR-A1-corruption-basis-v1"`，`SEVERITY_ENCODING = "single"`；v1 模块保持冻结且不被本文件导入。
- **单次 severity 编码：** `gaussian_noise`、`blur`、`quantization` 的连续 burden 直接等于实测归一化损伤，不再额外乘 severity：

$$
b_{\text{graded}}(p)=\operatorname{clip}_{[0,1]}\left(\frac{\max_c|\Delta_c(p)|}{255\cdot \mathrm{DAMAGE\_REFERENCE}}\right),\qquad \mathrm{DAMAGE\_REFERENCE}=0.25 .
$$

- **相对尺度空间损坏：** `blur` 的 $\sigma=\text{severity}\cdot \mathrm{BLUR\_SIGMA\_FRACTION}\cdot\min(H,W)$（`1/80`，等价于 v1 在冻结 480 像素 crop 上的 6.0 px 上限）；`misalignment` 每轴最大位移为 $\text{severity}\cdot \mathrm{MISALIGN\_MAX\_SHIFT\_FRACTION}\cdot H$（或 `× W`，`1/30`），有效区 burden 为实际位移除以当前尺度允许的最大位移，越界像素取 `MISSING_BURDEN=1e4`。
- **保持不变：** 三阶段 curriculum（上限 `0.30`/`0.60`/`1.0`，spec 数 `1`/`1–2`/最多 `max_specs`，`entire_missing` 仅重度且固定 severity `1.0`，severity 下限 `0.05`）、乘法组合 $R_m^*(p)=\prod_k\exp(-b_{m,k}(p))$、输出契约（uint8 scope/dtype 不变、`float32 [2,H,W]` target、通道序 RGB→Depth）、fail-closed 校验。
- **metadata：** 每类记录 corruption 参数、realized damage 统计、burden 与 reliability 汇总；`entire_missing` 与 `spatial_dropout` 的 burden 取值集合只有 $\{0,\text{MISSING\_BURDEN}\}$。

### 3.2 `utils/dataloader/mmfr_training_v2.py`（新增，A2 v2 helper；本次含实质代码修复）

- **corruption 位置：** DataLoader 完成 mirror/scale/crop/pad 之后、batch 搬到 GPU 之前，由主训练进程逐样本执行；不修改 `TrainPre`/`RGBXDataset`。
- **RNG：** 每样本独立 `numpy.random.Generator(PCG64(SeedSequence(words)))`；words 顺序为 `train_seed, epoch_1_based, iteration_0_based, global_rank, sample_slot_0_based, sample_id_sha256_u32_be_0..3`（sample id 统一 `/` 后取 SHA-256 前 16 字节按大端拆 4 个 uint32）；训练进度用训练位置而非墙钟。
- **有效性拆分：** 新增 `depth_valid_pre = (raw_depth_pre > 0) & valid_mask` 与 `depth_valid_post = (raw_depth_post > 0) & valid_mask`；故意不再导出 v1 的单一 `depth_valid`（`V1_ONLY_KEYS` 记录该键，旧调用方会显式失败）。
- **监督目标：** $R_D^{sup}(p)=V_D^{pre}(p)\cdot R_D^{syn}(p)$；clean 样本中原生有效像素 target=1、原生 Depth=0 的像素 target=0；crop/pad 区保持中性 target=1 并恒为精确零输入。
- **本次实质修复（唯一一处）：** 原实现对无效像素记账断言 `post_corruption_invalid_pixels == natural_invalid_pixels + synthetic_missing_pixels`。该等式在 `gaussian_noise` 或 `misalignment` 把原生无效（`raw Depth == 0`）像素变成非零时不成立，导致 CPU 定点检查在**首个真实 corrupt 样本**上即以 `RuntimeError` 中止。现改为显式记录 `newly_valid_pixels` 并断言闭合平衡：

$$
\mathrm{post\_corruption\_invalid} + \mathrm{newly\_valid} = \mathrm{natural\_invalid} + \mathrm{synthetic\_missing},
$$

  仍保持 fail-closed（真正的记账不一致仍会中止运行）。同时在模块 docstring 中修正了“三者构成划分”的错误表述。v1 helper 没有这套记账，未受影响。
- **v1 复用关系：** 本文件从 v1 helper 复用 seed words 构造、uint8 round-trip 与 curriculum 位置等协议无关基础设施，并在 import 时断言一致性；A1 v2 失效核不导入 v1 核。

### 3.4 `models/builder.py`（修改）

- 新增 `_mmfr_supervised_channels(reliability_cfg)`：读取 `supervised_channels`，默认等价于 v1 的“两通道”；对空列表、未知通道名或重复通道名 fail-closed。
- `EncoderDecoder` 新增 `self.reliability_supervised_channels`，并在启用 head 时记录日志（含实际监督通道）。
- `reliability_auxiliary_loss`：构造 `channel_weight`（Depth 为 1、RGB 为 0），与 `valid_mask` 相乘得到 `supervision_mask`；若掩码内没有任何被监督像素则**抛错**而不是继续零损失；`depth_valid`（v2 传入的是 `depth_valid_post`）仅作为特征有效性输入。
- 对旧配置的影响：不启用 reliability head 时整段路径不进入；v1 配置不传 `supervised_channels` 时保持两通道语义，故 v1 身份语义未变。

### 3.5 `utils/train.py`（修改）

- 同时导入 v1 与 v2 batch helper，并新增协议守卫：只接受 `MMFR-A2-train-integration-v1` 或 `-v2`；v2 额外强制 `basis`、`severity_encoding="single"`、target 组合字符串、`supervised_channels=["depth"]`、`relative_scale_spatial_corruptions=true`，否则 `parser.error`。把 v2 config 交给 v1 helper（或反之）是硬错误。
- 新增守卫：reliability 不得声明 `feeds_backbone` / `feeds_geometry_prior` / `geometry_adapter_enabled`。
- v2 路径把 `depth_valid_post` 交给 head 作为特征有效性，`valid_mask` 作为 loss 掩码。
- 遥测新增 `newly_valid_pixels` 汇总与 `natural/synthetic/post/newly/implicit_quality` 五类计数日志（按有效像素归一化）；v1 路径保持原有日志。
- 配置未启用 A2 时，整段逻辑保持惰性，旧训练路径不变。

# MUSeg 后验校准研究：两条最短验证路径

## 0. 研究边界与共同前置条件

本文只设计早期最小可行实验，不代表任何新实验已经执行，也不把历史 pilot 结果写成阶段二正式结论；当前正式长程三种子 baseline 尚未完成，因此两条路径只能在阶段二门禁放行并取得至少一个验收合格的冻结 checkpoint 后启动，若 pilot 得到 G，再在三个正式 seed 上复核方向稳定性。[RE130]

共同研究对象固定为本项目 `DFormerv2-S + ham`、MUSeg 15 类 RGB-D 语义分割、480×640 输入和逐像素输出；MUSeg 提供对齐 RGB/Depth 与 15 类像素标注，这些项目事实用于界定实验对象而不是宣称复现论文数值。[RE429]

官方 `test=1576` 在开发期继续封存，不参与退化工作点、checkpoint、温度、指标阈值或 G/N-G 决策；本方案不改变已经冻结但尚未完成实施与门禁的 `MUSEG-DEV-SPLIT-PROTOCOL-1`，因为独立数据职责和未知评价条件是可信校准结论的必要前提。[RE136]

在阶段二开发划分通过门禁后、长程训练开始和 checkpoint 选择规则实际使用数据之前，应另立协议，在不改变 `MUSEG-DEV-SPLIT-PROTOCOL-1` 成员归属的前提下，将允许用于验证的 location groups 进一步冻结为互斥职责：`model-selection` 只用于 checkpoint 选择，`calibration-pilot` 只用于拟合全局温度，`evaluation-pilot` 只用于路径 A 的问题验证和路径 B 的独立评价；三者不得兼任，也不得接触官方 test。[RE136]

上述职责扩展必须先于正式长程训练冻结；如果现有 `val-dev` 已经整体参与过 checkpoint 选择，则不能事后从中抽取样本并宣称是独立 pilot，而应等待新的无泄漏协议或新的合格 checkpoint。[RE136]

两个 pilot 清单应在查看本研究指标前一次性冻结，记录样本与 group 清单、互斥审计、有效标签像素和主要类别覆盖；具体样本数以门禁后的开发数据审计为准，选择“满足基本覆盖且尽可能小”的清单，不为追求有利结果反复改划分。[RE447]

两条路径优先共用同一个合格 checkpoint、同一推理配置与同一批 float32 logits；路径 B 的未校准与校准分支必须逐元素读取同一份缓存 logits、标签及有效像素掩码，从而把差异限制在后验概率映射上。[RE136]

现有 `tools/mve/a2_run_sensitivity.py` 已具备按掩码把 Depth 局部置零、以 480×640 推理并输出 mIoU 类指标的 pilot 基础，当前配置也明确为 `DFormerv2_S` 骨干和 `ham` 解码器；该项目事实只说明可复用局部链路，不等于已经具备正式校准工具、完整 logits 缓存或退化结论。[RE752]

## 1. 路径 A：问题—假设验证

### 1.1 核心假设识别

**核心假设 A：** 对同一 `evaluation-pilot` 样本主动增大单一根因变量——Depth 局部置零比例 `q`——会造成可检测的置信度—正确率失配，尤其是更多高置信错误或更大的置信度—正确率缺口；这将直接支持“当前 RGB-D 模型在可控 Depth 信息缺失下存在值得研究的校准问题”。[RE068]

`q` 定义为被掩码并置零的**原本有效 Depth 像素占全部有效 Depth 像素的比例**；最短 pilot 建议在运行前将唯一非零工作点预注册为 `q*=0.30`，因为现有 A2 掩码工具已能表达该工作点，但 `0.30` 只是本项目的工程筛查值，不是文献参数，也不代表真实传感器故障率、粉尘强度或物理风险概率。[RE752, RE666]

### 1.2 最小可行实验设计

#### 实验目标

用一次成对前向比较判断：在保持 RGB、标签、checkpoint、推理配置和样本集合不变时，单个非零 `q` 是否比 `q=0` 制造出更多高置信错误或更明显的置信度—正确率缺口，并同时记录分割性能是否按预期退化。[RE752]

#### 实验步骤

1. 在门禁放行后冻结一个验收合格的 checkpoint，并固定 `evaluation-pilot`、480×640 推理配置、有效像素规则和 float32 logits 导出格式；当前尚未完成正式长程三种子 baseline，因此不得用未验收 checkpoint 把 pilot 写成正式结论。[RE130]
2. 为 `evaluation-pilot` 的每张图冻结一份可审计的局部掩码，只比较 `q=0` 与预注册工程工作点 `q*=0.30`；该值沿用现有 A2 工具可表达的 pilot 档位以减少新增实现，但不得冒充文献参数，且现有 A2 读取官方 test 的样本选择逻辑不能复用于本实验，只复用掩码生成与推理机制。[RE752]
3. 对每张图在 `q=0` 和 `q=q*` 下分别执行同一冻结模型推理，保存 15 类逐像素 float32 logits、标签、有效像素掩码、退化掩码和样本标识；除 Depth 掩码区域置零外，不改变任何输入或推理条件。[RE136]
4. 从未校准 Softmax 计算像素置信度、正确性、NLL、15 个等宽分箱的 ECE、Brier Score、最高置信分箱 `[0.90,1.00]` 的“平均置信度减实际正确率”缺口，以及高置信阈值 `t_H=0.90` 下的高置信错误率；这些数值口径是待预注册的工程定义，概率可靠性与高置信失败应作为准确率之外的独立评价维度。[RE068]
5. 同时计算 mIoU 及每图正确率或像素准确率变化，但路径 A 的主判断只使用高置信错误和置信度—正确率缺口，分割退化仅作为“退化确实生效”的伴随证据。[RE165]
6. 对 `q=q*` 减 `q=0` 的每图配对差值给出图像级 bootstrap 置信区间；像素不作为彼此独立的重采样单位，因为图像级重采样更符合场景相关性并可避免虚假的超大样本量。[RE447]

#### 所需数据／材料

所需材料仅为一个合格冻结 checkpoint、冻结的 `evaluation-pilot`、每图成对的 `q=0/q=q*` 掩码条件、RGB/Depth/标签、float32 logits 缓存及最小离线指标脚本；现有 A2 局部置零链路可作为输入退化与推理部分的基础。[RE752]

### 1.3 关键成功／失败指标（G 与 N-G）

以下阈值均是**预注册的工程判断阈值**，只用于早期方向筛选，不是任何文献的原始阈值；在导出 `evaluation-pilot` 结果前必须把 `q*`、`t_H`、ECE 分箱规则和 bootstrap 规则写入运行记录。[RE447]

**A-G（成功）**要求同时满足以下三项：[RE068]

- 退化操纵检查通过：`q=q*` 相对 `q=0` 的 mIoU 绝对下降至少 1.0 个百分点，证明所选工作点对分割产生了可测影响。[RE165]
- 两个主问题指标中至少一个达到方向门槛：高置信错误占全部有效像素的比例绝对增加至少 0.5 个百分点，或最高置信分箱的“平均置信度减正确率”缺口绝对扩大至少 2.0 个百分点。[RE068]
- 达到门槛的主问题指标，其图像级配对 bootstrap 95% 置信区间下界大于 0；若 pilot 图像过少导致区间极宽，则只能标记为“方向性 G、待正式 seed 复核”，不能升级为正式结论。[RE447]

**A-N-G（失败）**为以下任一情况：mIoU 未达到 1.0 个百分点的操纵下降；两个主问题指标均未达到上述工程门槛；或主问题指标方向不稳定且 95% 置信区间跨越 0。[RE447]

若分割明显下降而高置信错误与正缺口不增加，应解释为“该置零工作点制造了准确率问题，但未制造出本研究所需的过度自信问题”，因此仍判 A-N-G，而不是放宽阈值追求成功。[RE068]

### 1.4 所需最简资源

路径 A 只需一个冻结 checkpoint 的两次成对推理，可在一张可运行该模型的 GPU 上完成；指标、Softmax、配对统计与图形均可在 CPU 上离线计算，无需重新训练模型、训练严格单模态模型、运行全退化套件或开展跨矿实验。[RE666]

优先缓存 `q=0` 与 `q=q*` 的 float32 logits，后续计算不得为不同指标重复推理，从而减少资源消耗并避免输入与数值路径不一致。[RE136]

### 1.5 备选及简化方案

若现有掩码无法精确达到 `q*`，可在预注册时固定“实际置零像素比例最接近 `q*` 的可用掩码”规则，并报告每图实际比例；不得在看到校准指标后更换掩码。[RE752]

若 `q*=0.30` 未通过操纵检查，可只增加现有工具可表达的 `q=0.50` 作为一次性更强边界诊断，并把它标记为路径 A 的边界补充而非原计划成功；最短路径不扩展到更多强度、RGB 退化、错位或复合退化。[RE666, RE752]

若暂时无法实现完整 NLL/ECE/Brier 工具，路径 A 可先保留主判断所需的高置信错误率与最高置信分箱缺口，再补充 mIoU 操纵检查；该简化只回答“问题是否存在”，不回答“哪种校准方法有效”。[RE068]

### 1.6 路径原理解释

路径 A 采用“只改变一个可定量原因，其余条件全部锁定”的反事实式对照，使观察到的置信度失配更容易归因于 Depth 局部信息丢失，而不是 checkpoint、样本或推理过程变化。[RE752]

把高置信错误与置信度—正确率缺口设为主判断，是因为研究动机是检验概率是否过度自信，而不是再次证明退化会降低普通分割精度。[RE068]

## 2. 路径 B：方案—假设验证

### 2.1 核心假设识别

**核心假设 B：** 在冻结同一 checkpoint 和同一批正常条件（`q=0`）float32 logits 的条件下，仅用独立 `calibration-pilot` 拟合一个正的全局温度 `T`，可以在互斥的正常条件 `evaluation-pilot` 上同时改善 NLL、ECE 与 Brier Score，而不改变逐像素 argmax 和 mIoU，从而证明最简单后验校准具有初步价值。[RE136]

全局正温度只统一缩放每个像素的类别 logits，因此保持类别排序；AURC 依赖风险排序，故本路径不把 AURC 改善设为全局温度缩放的成功条件。[RE226]

### 2.2 最小可行实验设计

#### 实验目标

用同一份 `evaluation-pilot` 原始 logits 做最小 A/B：A 分支为未校准 Softmax，B 分支为在独立 `calibration-pilot` 上拟合并冻结的单一全局温度缩放，以判断概率数值质量能否在独立数据上稳定改善。[RE136]

#### 实验步骤

1. 对同一个合格 checkpoint 分别导出 `calibration-pilot` 与 `evaluation-pilot` 在正常条件 `q=0` 下的 15 类逐像素 float32 logits，并记录 checkpoint、配置、清单及有效像素掩码；两份 pilot 按 location group 互斥，且还必须与该 checkpoint 使用的 `model-selection` groups 隔离，均不使用官方 test。[RE136]
2. 只在 `calibration-pilot` 上以多分类 NLL 拟合一个正的全局温度 `T`，拟合完成后立即冻结；不针对 `evaluation-pilot` 的类别、图像、退化条件或指标重新选择温度。[RE136]
3. 在 `evaluation-pilot` 的同一份缓存 logits 上计算分支 A：`Softmax(z)`，以及分支 B：`Softmax(z/T)`；两分支共享完全相同的标签、有效像素和聚合规则。[RE136]
4. 在独立 `evaluation-pilot` 上配对比较 NLL、ECE、Brier Score，并逐元素核验 argmax 一致率以及 mIoU 是否相同；可靠性指标用于衡量概率值，mIoU 核验用于确认最小后验操作未改分割决策。[RE165]
5. 对每张图的 NLL 与 Brier 差值做图像级配对 bootstrap；ECE 同时报告全局值和按图重采样区间，以减少单次分箱估计对方向判断的影响。[RE447]
6. AURC 可以作为解释性核验，预期在排序完全不变时不改善；若实现报告了明显 AURC 变化，应先检查风险定义、并列处理或样本过滤是否不一致，而不是将其直接算作温度缩放收益。[RE226]

#### 所需数据／材料

所需材料仅为同一冻结 checkpoint 对两个互斥 pilot 清单导出的 float32 logits、标签与有效像素掩码，一个全局温度拟合函数，以及 NLL/ECE/Brier/mIoU 一致性检查；无需修改或反向微调 `DFormerv2-S + ham`。[RE136]

### 2.3 关键成功／失败指标（G 与 N-G）

以下数值同样是**预注册的工程判断阈值**而非文献原始阈值，其作用是让早期 pilot 能作出停止或继续决定，不得在查看 `evaluation-pilot` 后修改。[RE447]

**B-G（成功）**要求在独立 `evaluation-pilot` 上同时满足以下条件：[RE136]

- NLL 相对未校准分支降低至少 1.0%。[RE136]
- ECE 绝对降低至少 1.0 个百分点。[RE226]
- 多分类 Brier Score 相对降低至少 0.5%。[RE226]
- 逐像素 argmax 一致率为 100%，mIoU 绝对差不超过浮点汇总容差 `1e-6`；若不满足，应优先判定实现或数据路径不一致。[RE136]
- NLL 与 Brier 的每图配对改善均有 bootstrap 95% 置信区间上界小于 0，且 ECE 的重采样结果大多数为改善方向；若区间因 pilot 过小而不稳定，只能记录为“数值改善但证据不足”，判 B-N-G 并决定是否扩大 pilot。[RE447]

**B-N-G（失败）**为以下任一情况：NLL、ECE、Brier 中任一指标未达到预注册改善门槛；关键配对区间不支持稳定改善；argmax 或 mIoU 发生超过容差的变化；或温度拟合、清单互斥与 logits 一致性无法审计。[RE136]

AURC 不改善不构成 B-N-G，因为正全局温度保持排序；AURC 若意外明显变化反而触发实现审计。[RE226]

### 2.4 所需最简资源

路径 B 优先复用已经缓存的 float32 logits，温度拟合与全部评价可在 CPU 上离线完成；若尚无 logits 缓存，只需用单个冻结 checkpoint 各导出两个 pilot 一次，无需重新训练或占用多卡资源。[RE136]

pilot 阶段只使用一个合格 checkpoint；B-G 后再对三个正式 seed 各自独立拟合温度并检查“多数 seed 同向”，以区分方法价值与单次训练偶然性。[RE130]

### 2.5 备选及简化方案

若 `calibration-pilot` 类别覆盖不足，仍只拟合单一全局温度，不升级到类别条件温度、向量缩放或其他高自由度方法；更复杂方法需要更多独立数据并会削弱最短验证的可归因性。[RE136]

若 ECE 对预注册分箱较敏感，可额外报告可靠性图或一个预先固定的自适应分箱 ECE作为诊断，但不得用事后挑选的 ECE 版本替换主指标以改变 G/N-G。[RE226]

若 B-N-G 仅由置信区间过宽造成，可在不改变 checkpoint、温度规则和阈值的前提下，按预注册的 group-aware 规则一次性扩大两个 pilot 后重跑；若三项点估计本身均无改善，则停止扩样并保留 N-G 结论。[RE447]

### 2.6 路径原理解释

路径 B 把模型、样本和 logits 全部冻结，只让“是否除以一个全局温度”发生变化，因此是成本最低、因果边界最清楚的后验方案验证。[RE136]

把独立 `calibration-pilot` 与 `evaluation-pilot` 分开，可防止在拟合数据上观察到的改善被误当成泛化价值，并与项目官方 test 封存及阶段二开发职责隔离保持一致。[RE136]

把 NLL、ECE 和 Brier 共同设为成功重点，可以同时检查对数评分、分箱可靠性和概率平方误差；把 argmax/mIoU 不变设为硬核验，则保证收益来自概率值修正而非偷偷改变分割类别。[RE226]

## 3. 两条路径的互补关系

路径 A 回答“校准研究的问题是否真实”：它主动控制 Depth 局部置零比例，寻找退化引发的过度自信或置信度—正确率失配；路径 B 回答“最低复杂度方案是否有价值”：它在不改变排序和分割结果的前提下检验概率数值能否被全局温度修正。[RE068]

A-G 并不自动推出 B-G，因为被制造出的失配可能不是单一全局温度可以修正；B-G 也不自动推出 A-G，因为正常评价数据上的总体概率改善不证明 Depth 局部缺失会制造项目关注的高置信错误。[RE226]

两条路径共同采用同一 checkpoint、隔离数据职责、缓存 float32 logits 和事前阈值，使“问题存在”与“方案有效”成为两个可分别证伪、又能组合决策的最短证据单元。[RE136]

## 4. 四种结果后的行动组合

### 4.1 A G / B G

结论是“受控 Depth 缺失确实制造了校准问题，且最简单全局温度在独立数据上已有初步价值”；下一步仅复核三个正式 seed 的方向一致性，并在复核通过后再把同一冻结温度应用到预注册的正常与 Depth 置零条件，明确区分概率改善与排序不变。[RE130]

在三 seed 复核前不扩展复杂校准器、全退化套件或跨矿实验，以保持精益路线并先确认基础发现不是单 checkpoint 偶然结果。[RE130]

### 4.2 A G / B N-G

结论是“问题真实，但单一全局温度不足或 pilot 证据不足”；先检查数据互斥、logits 一致性、ECE 分箱和温度实现，审计通过后仅根据失败形态决定是否扩大 pilot 或预注册一个更有表达力但仍离线的校准器。[RE136]

若 NLL/ECE/Brier 均无方向性改善，则停止温度缩放主线，把后续问题限定为退化条件化或排序风险研究，而不是通过反复调温度、阈值或数据划分挽救结果。[RE226]

### 4.3 A N-G / B G

结论是“全局温度对当前独立数据的总体概率值有初步价值，但所选 Depth 局部置零工作点没有验证出预期问题”；保留 B 的校准价值，并只允许路径 A 增加一个预注册的更强边界 `q` 进行操纵诊断。[RE666]

若边界 `q` 仍不能制造高置信错误或正缺口，则停止把 Depth 局部置零作为核心问题证据，后续不得用分割下降替代校准问题成立。[RE068]

### 4.4 A N-G / B N-G

结论是“当前最短证据既未确认目标问题，也未确认最简单方案”；停止扩展复杂校准器、区域风险、全退化套件和跨矿研究，优先完成阶段二正式长程三种子 baseline 与数据门禁，再重新评估研究问题是否值得继续。[RE130]

只有在审计发现明确的数据、实现或操纵失败时才修复后按原预注册规则重跑；若实验本身有效但结果为 N-G，应保留可证伪结论而不是修改阈值或评价集。[RE447]

## 5. 执行前后检查清单

- 启动前确认阶段二开发划分门禁已通过、官方 test 仍封存、正式长程三种子 baseline 的实际完成状态被如实记录，且 pilot 使用的是至少一个验收合格的冻结 checkpoint。[RE130]
- 确认 `model-selection`、`calibration-pilot` 与 `evaluation-pilot` 在正式长程训练及 checkpoint 选择前已按 location group 冻结为互斥职责，不改变 01 协议的 train-dev/val-dev 成员归属，且均未使用官方 test；如既有 `val-dev` 已整体用于模型选择，则停止并另立无泄漏协议。[RE136]
- 确认路径 A 只有 `q=0` 和一个待预注册非零 `q*`，路径 B 两分支读取同一份 evaluation logits，所有 logits 为 float32 且样本与有效像素完全一致。[RE136]
- 确认所有 G/N-G 数值已标为预注册工程判断阈值，结果文件中不填入任何未运行的数值，也不把 pilot 写成三 seed 正式结论。[RE447]
- 确认路径 B 不以 AURC 改善为温度缩放成功条件，并逐元素核验 argmax 与 mIoU 不变。[RE226]
- 确认本方案不要求重训模型、严格单模态模型、全退化套件、跨矿实验或未必要的硬件与优化器细节。[RE666]

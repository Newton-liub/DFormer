# 给下级模型的完整执行指令

## 任务名称

`MMFR-A2-v3 corruption pipeline performance optimization`

目标：

**在 MMFR-A2 v3 科学协议完全不变的前提下，提高** `depth-corruption-v3` **的训练吞吐。**

当前正式 500 epoch 训练继续暂停。

不得把本任务理解为：

- 改模型；
- 改 reliability head；
- 改 loss；
- 改 corruption 类型；
- 改 corruption 强度；
- 改 target；
- 改 batch size；
- 改训练超参数。

本任务只允许优化**实现效率**。

# 4. 特别确认是不是 CPU 把 GPU 饿住了

当前假说是：

```text

    ↓
GPU 等数据
    ↓
forward/backward
```

必须验证，而不是直接接受。

记录 GPU 每一步开始前的 idle gap。

如果发现类似：

```text

```

```text

```

当前云端资料只支持“原因方向”指向 GPU 前 CPU corruption，并没有做完整分项 profiler，所以本步骤是必须的。

# 6. 优化优先级：先做低风险优化

## Opt-A：消除无意义复制和 dtype 往返

先检查是否存在：

```text
tensor
→ numpy
→ copy
→ uint8
→ copy
→ float
→ tensor
→ normalize
```

等重复操作。

允许：

- 减少 `clone()`；
- 减少 `astype()`；
- 减少临时 ndarray；
- 使用预分配 buffer；
- 使用 contiguous buffer；
- 对同一个值不重复计算；
- 一个 batch 最后只做一次必要的 normalize；
- 重用 mask / validity buffer。

禁止改变：

```text
rounding
clipping
uint8 conversion rules
zero sentinel
1..255 valid encoding
```

优化后立即跑 golden parity。

要求：

```text
0 mismatches
```

否则撤回。

---

# 7. Opt-B：优先尝试 batch 内样本并行

这是我认为最值得优先尝试的优化。

当前 batch size 是 10，而且每个 sample 都使用独立确定性 RNG，因此可以尝试：

```text
batch 内多个 sample corruption 并行执行
```

而不是：

```text
sample0
→ sample1
→ sample2
→ ...
→ sample9
```

依次串行。

先尝试 CPU worker 数：

```text
1
2
4
6
8
10
```

不要默认越多越快。

推荐优先尝试：

```text
ThreadPoolExecutor
```

原因：

NumPy/OpenCV 很多底层运算会释放 GIL，线程方案比多进程更容易避免大 tensor IPC。

但必须同时防止 OpenCV 自己再开大量线程造成 oversubscription。

测试：

```text
cv2.setNumThreads(1)
```

和当前默认行为的区别。

记录每种：

```text
worker count
step time
img/s
CPU utilization
GPU utilization
output parity
```

关键规则：

每个 sample 仍使用原来的：

```text
train_seed
epoch
iteration
global_rank
sample_slot
sample-id SHA256
```

生成自己的 PCG64。

**绝对不能因为线程调度改变 RNG draw order。**

结果收集时必须按：

```text
sample_slot
```

恢复原 batch 顺序。

---

# 8. Opt-C：批量向量化简单 corruption

如果 profiler 显示明显耗时，可以优先针对：

```text
gaussian_noise
quantization
spatial_dropout
```

减少 Python 循环。

但是要求：

> 与旧实现逐位一致。

特别是 RNG。

不要把：

```text
10 次独立 PCG64
```

直接改成：

```text
一个 batch RNG 一次生成 B×H×W
```

因为这样虽然数学分布相同，却改变了确定性身份。

必须保持每 sample 原 RNG stream。

允许：

```text
各 sample 独立生成参数/随机数
↓
后续非随机算子批量处理
```

---

# 9. Opt-D：blur 只做工程优化，不改数学定义

当前仍必须使用：

```text
mask-normalized blur
```

即现有 A+MID-A 语义。

不得为了快改回普通 Gaussian blur。

允许：

- 重用 kernel；
- 缓存相同 sigma 的 kernel；
- 减少 numerator / denominator 的临时 buffer；
- 预分配输出；
- 同尺寸情况下复用 workspace。

所有结果必须和原 v3 parity。

如果无法逐位一致，则本轮先不优化 blur 算法。

---

# 10. Opt-E：misalignment 只能优化数据搬运

必须继续保证：

```text
Depth 与 validity 使用同一个 (dy, dx)
```

允许优化：

- slice assignment；
- 预分配 destination；
- 减少 zero-initialize；
- 批量处理 metadata。

不得改成新的插值算法。

不得由 integer shift 改 affine/grid_sample。

不得改变边界行为。

---

# 11. 第一轮禁止 GPU 重写 corruption

暂时**不要**把：

```text
OpenCV / numpy corruption
```

直接重写成：

```text
torch CUDA corruption
```

原因不是做不到，而是：

- Gaussian blur 数值实现可能不同；
- interpolation / rounding 可能不同；
- uint8 ↔ float 规则可能不同；
- RNG 会变化；
- misalignment 边界规则可能漂移。

第一轮优化目标是：

> **same algorithm, faster execution**

而不是：

> approximate equivalent algorithm。

只有低风险 CPU 优化仍无法解决问题，才允许提交：

```text
Opt2 GPU-corruption proposal
```

供高级模型另外审核。

下级模型不得自行执行 GPU 算法替换。

---

# 12. 第二个重点：实现 CPU corruption 与 GPU compute 重叠

如果 profiler 证明确实 CPU-bound，尝试增加**异步预取**。

目标从：

```text
prepare batch N
→ corrupt N
→ GPU train N
→ prepare N+1
```

改成：

```text
GPU train N
          ╲
           CPU simultaneously corrupt N+1
```

优先采用：

```text
single-batch lookahead
queue depth = 1
```

先不要搞复杂的 4～8 batch 队列。

要求：

- sample 顺序完全不变；
- epoch/iteration 定义不变；
- seed 不变；
- selector 不变；
- corruption 的 iteration 必须仍对应训练实际消费的 iteration；
- 发生 exception 时 fail closed；
- 不能跳 batch；
- 不能偷偷预生成下一 epoch 后改变 epoch-based curriculum；
- resume 后必须能恢复正确 batch/iteration 语义。

如果实现需要改变 sampler 或 RNG 身份：

**立即停止，不进入当前 opt1。**

## 我特别建议下级模型先尝试的三个动作

不要让它一上来重构整个数据系统。按收益/风险排序：

**① 先 profile。**

**② 在保持每个 sample 独立 RNG 的情况下，把 batch 内 10 个 corruption 从串行改成 4/6/8 CPU workers 并行。**

**③ 如果 CPU corruption 仍明显长于 GPU compute，再实现 queue-depth=1 的“CPU 准备下一 batch / GPU 训练当前 batch”异步重叠。**

这三步如果做对，最有可能解决你现在的问题，而且**基本不需要碰 MMFR 的科学设计**。

> **高级审计结论：** `A + MID-A`。A 表示 intensity corruption 只能在当前有效 Depth 状态内作用，不能复活 invalid Depth；MID-A 表示 misalignment 同时搬运 Depth 和 validity。

## 0. 一句话摘要

v2 在正式 500 epoch 训练前完成了实现和本地资格，但 validity transport 审计发现普通噪声、模糊和错位可能把原生无效 Depth 变成非零值，且 misalignment 的有效性坐标语义尚未冻结。高级审计因此选择 A + MID-A，要求建立新 v3，而不是原地修改 v2。v3 只改变 validity state 与 corruption interaction，保留主实验条件、超参数、selector、evaluator、成功门槛、natural-invalid 监督、8 个全无有效 Depth crop 和 43 个 optimizer-missing 参数。v3 的五项本地资格全部 `PASS`，当前只具备申请云端短 probe 授权的资格，没有正式训练或效果结论。

## 1. 审计者应先确认的五件事

1. **v2 没有被覆盖。** v2 代码、config、protocol、报告、commit 和 tag 继续作为历史身份；v3 使用新文件和新 protocol。
2. **唯一科学变化是 validity semantics。** v3 没有借机改变 failure condition、severity、curriculum、`p_clean`、`lambda_rel`、500 epoch、selector、主 evaluator 或主成功门槛。
3. **A + MID-A 已实际落地。** 不能只看高级审计文字，还要核对 v3 helper、config 守卫、训练入口和 validity transport 报告。
4. **五项资格不是效果评价。** severity/burden、CPU、transport、初始状态和 AMP 更新轨迹都只证明有限范围内的实现或公平性，不提供 mIoU 或可靠性收益。
5. **当前没有训练授权。** `eligible-for-cloud-capacity-probe-authorization` 只表示可以向用户申请云端单 GPU、batch size `10` 短 probe；它不授权创建实例、运行 probe 或启动 500 epoch 训练。

## 2. 变更原因和决策链

### 2.1 v2 暴露的问题

v2 将 Depth reliability target 写成 `V_D^pre * R_D^syn`，但 validity transport 审计进一步显示：

- `gaussian_noise`、`blur`、`misalignment` 可能在 raw Depth 为 0 的原生无效像素上产生非零值；
- 在最稀疏样本上，`gaussian_noise@0.25` 单个 crop 曾产生 `129,563` 个此类 `newly_valid` 像素；
- `R_D^sup` 和旧记账等式可以闭合，但这并不能证明生成的非零值具有测量语义；
- misalignment 存在“按原坐标取 validity”还是“随 Depth 内容一起搬运 validity”的选择。

这些问题发生在正式训练前，因此 v2 没有产生需要追溯解释的模型结果。v2 被标记为 `superseded-before-formal-training-after-validity-semantic-review`。

### 2.2 高级审计的 v3 处置

- natural-invalid 继续监督，不重加权、不 masking；不删除 `train-dev` 中 8 个训练几何下全无有效 Depth 的 crop。
- A：`V_state=0` 是吸收状态；noise、blur、quantization 只能作用于 `V_state=1`，不得生成新的有效测量。
- blur 使用 mask-normalized blur，invalid zero 不参与普通卷积。
- MID-A：misalignment 对 Depth 值和 validity state 使用相同整数平移，再应用几何 `valid_mask`。
- 最终监督 target 改为 `V_state_final * R_syn`，并硬断言最终状态、`depth_valid_post` 和实际非零 Depth 输入逐位一致。
- 43 个不在 optimizer param group 的参数保持上游语义；本次不修，避免混入新的训练变量。

## 4. 逐文件改动细节

### 4.1 `utils/dataloader/multimodal_failure_v3.py`

- 新建 A1 identity：`MMFR-A1-corruption-basis-v3`，supersedes v2。
- 保留六类 failure、severity 单次编码、`MISSING_BURDEN=1e4`、`DAMAGE_REFERENCE=0.25`、相对 blur/misalignment 尺度、三阶段 curriculum 和组合顺序。
- 新增显式 validity state 参数和结果字段。初始状态是 `depth_valid_pre`；所有后续 failure 按 spec 顺序更新 state。
- noise、blur、quantization 只在 state 有效处修改 Depth，不改变 state；spatial dropout 与 entire missing 分别收缩或清零 state；misalignment 对 Depth 与 state 使用同一整数位移。
- 新增 `_depth_finalize`、`_masked_assign` 等保护，确保 state=1 时输出 uint8 不为 0，state=0 时输出精确 0。
- blur 使用 mask-normalized Gaussian 公式，不让 invalid zero 参与有效测量的卷积归一化。
- 输出 reliability 仍是 synthetic burden 推导的 `[0,1]` 目标；它不是自然传感器真值。

### 4.2 `utils/dataloader/mmfr_training_v3.py`

- 新建 A2 helper identity：`MMFR-A2-train-integration-v3`，不调用 v2 helper 处理 v3 corruption。
- corruption 仍固定在最终 mirror/scale/crop/pad 后、GPU 前，由主进程逐样本执行；clean 样本复用 normalized tensor，保持 exact no-op。
- 输出 `depth_valid_pre`、`depth_valid_post`、`telemetry_masks` 和显式 metadata；不再导出含义不明确的 v1 单一 `depth_valid`。
- 初始状态使用 `depth_valid_pre = (raw_depth_pre_uint8 > 0) & valid_mask`；最终强制验证 `depth_valid_post == V_state_final == (raw_depth_post_uint8 > 0) & valid_mask`。
- target 使用：

$$
R_{D}^{sup,v3}(p)=V_{D}^{state,K}(p)R_{D}^{synthetic}(p).
$$

- 四类 telemetry mask 精确划分几何有效区：`natural-invalid`、`synthetic-invalid`、`implicit-quality`、`valid-clean`。它们互斥并完整覆盖 `valid_mask`，不进入 loss weighting。
- `newly_valid_pixels` 在 v3 的 intensity corruption 中必须为 0；misalignment 以 transported state 定义最终有效性。
- 保留独立 PCG64 `SeedSequence`：seed words 包含训练 seed、epoch、iteration、global rank、sample slot 和 sample-id SHA-256 前四个大端 uint32。

### 4.3 三个 v3 config

- `DFormerv2_S_MMFR_A2_Common_v3.py`：建立 v3 protocol、schedule、两个分析身份、A + MID-A corruption、target、telemetry、归一化、loss 和云端执行 profile；`configure_mmfr_identity_v3()` 拒绝错误 basis、target、severity encoding、MID-A 或监督通道。
- `DFormerv2_S_MMFR_A2_Clean_v3.py`：run identity `museg-dformerv2-s-mmfr-a2-clean-control-v3`；不执行 corruption、不实例化 reliability head。
- `DFormerv2_S_MMFR_A2_DepthCorrupt_v3.py`：run identity `museg-dformerv2-s-mmfr-a2-depth-corruption-train-v3`；启用 Depth-only corruption、16 hidden channels、`lambda_rel=0.1` 和四类 telemetry。
- 三个配置都保持 v2 的科学超参数：seed `772961337`、AdamW、learning rate `6e-5`、500 epoch、warmup 10、batch size `10`、workers `8` 和相同 train scales。

### 4.4 `models/builder.py`

- 在 `EncoderDecoder.forward()` 与 `reliability_auxiliary_loss()` 中增加 `reliability_telemetry_masks` 接口。
- reliability loss 仍只对 Depth channel 计算，RGB 为 all-ones unscored scaffold。
- 对四类 telemetry 逐类计算 detached Depth BCE、像素数和类别顺序，空类使用 detached NaN 占位并以零像素排除聚合。
- telemetry 只记录类别 loss 和像素统计，不改变 aggregate reliability loss、分割 loss 或 optimizer 权重。
- 缺失 supervision 字段、未知 protocol 语义或无有效监督像素继续 fail-closed。

### 4.5 `utils/train.py`

- 新增 v3 helper import 和 protocol dispatch；只允许 v1、v2、v3 三个明确身份，v3 不会误走 v2 helper。
- 新增 v3 守卫：basis 必须为 v3、severity 必须单次编码、target 必须为 `V_state_final * R_depth_synthetic`、监督必须 Depth-only、spatial corruption 必须相对尺度、misalignment 必须 MID-A、final validity contract 必须存在。
- v3 将 `depth_valid_post` 提供给 reliability feature extractor，将 `telemetry_masks` 提供给模型做类别 telemetry。
- 每个 epoch 记录四类像素数/比例与四类 reliability-loss 均值；category telemetry 不参与优化权重。
- 保持旧配置关闭 A2 时的惰性旧路径；v1/v2 路径不被 v3 telemetry 静默改变。

### 4.6 `protocols/mmfr-a2-train-integration-v3.template.json`

- 新建 v3 protocol，明确 `supersedes=v2`、`status=eligible-for-cloud-capacity-probe-authorization`、`official_test_included=false`。

- `cloud_capacity_probe_authorized=false`、`formal_training_authorized=false`、`full_evaluation_authorized=false`、`cloud_resource_creation_authorized=false`、`official_test_authorized=false`。

### 4.7 五个 v3 qualification 工具
